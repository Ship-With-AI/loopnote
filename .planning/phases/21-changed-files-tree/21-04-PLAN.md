<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `document`-level `pointerdown` listener (ViewOptionsMenu's outside-click dismiss) → menu open/close state | The listener only ever reads `event.target` to decide whether to close the menu; it never reads or trusts any payload from the event beyond DOM containment |
| `panelState.treeLineCounts`/`treeCommentBadges` write path (the new menu's selections) → localStorage | This plan WRITES these fields for the first time (21-01 only read/defaulted them) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-08 | Tampering | `panelState.treeLineCounts`/`treeCommentBadges` write path (ViewOptionsMenu → App.vue handlers) | mitigate | Both handlers only ever write one of a closed, hardcoded set of values (`'always'`/`'hover'`/`'never'` for line counts, a `boolean` for badges) originating from the menu's own fixed `menuitemradio`/`menuitemcheckbox` click/keydown handlers — no free-form user input reaches `persist()` here; the read-back path's per-field validation is already covered by 21-01's `parsePanelState` |
| T-21-09 | Spoofing / Elevation of Privilege (clickjacking via the new popover) | `ViewOptionsMenu.vue`'s hand-rolled outside-click dismiss | accept | ASVS L1 out of scope for this same-origin, no-auth, localhost-only desktop review tool (`.claude/CLAUDE.md`'s Fastify-bound-to-127.0.0.1 constraint, unchanged); the menu is a small anchored popover (not a full-viewport overlay) with standard focus-trap-free Esc/outside-click dismissal, matching the risk profile of every other small overlay already shipped in this codebase |
</threat_model>
