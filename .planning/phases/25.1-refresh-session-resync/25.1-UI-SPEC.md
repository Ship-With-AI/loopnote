# Phase 25.1 — UI Design Contract: Refresh Session Resync

> Visual interaction contract for Phase 25.1 (IDENT-04, SHELL-05 gap closure). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Source truth: `25.1-CONTEXT.md`'s `<decisions>` block (locked — selection-change announcement wording, path-not-fileId selection matching, "Removed" label for paths absent from the re-fetched session). Cross-cutting token/component precedent carried forward unchanged from `20-UI-SPEC.md` (type scale, `.ui-button`), `22-UI-SPEC.md` (single live-region `announce()`/`liveMessage` discipline), `23-UI-SPEC.md`/`24-UI-SPEC.md` (`ReviewStateBadge` `size="compact"` muted-row convention for non-interactive state chips — "Anchor missing"/resolved-row precedent this phase's "Removed" row follows).

## Component Usage / Markup

### 1. Session resync (no new visual surface)

Re-fetching and reassigning `session.value` inside `performRefresh()` is a data-layer fix — the tree, status bar, identity pill/popover, and file list already render from `session.value` today, so correcting what feeds them produces **no new DOM, no new class, no new copy** beyond the two items below. Nothing to contract visually here beyond "every surface that already reads `session.value` now reads current data."

### 2. Selection-change announcement (locked verbatim, CONTEXT)

When Refresh selects a different file because the previously-selected path no longer exists in the re-fetched session, fire the existing single live-region exactly once:

```ts
announce(`${previousPath} is no longer in the review; showing ${nextPath}`);
```

- Mechanism: `App.vue`'s existing `announce()` / `liveMessage` / `liveMessageVersion` — the one `<p class="visually-hidden" aria-live="polite">` region already in the template (`App.vue:1809-1811`). **No second live region, no toast, no visible banner.**
- Fires only when the selection actually changes as a result of this resync (path still present → no announcement, matching the existing "only announce on actual change" discipline used by every other `announce()` call site in `App.vue`).
- Wording is locked by CONTEXT and MUST NOT be altered — not even punctuation.

### 3. `RefreshSummaryPanel.vue` row states (the one new copy/visual element)

Today every row in the Added / Removed / Modified lists is unconditionally a clickable `<button class="ui-button">{{ path }}</button>` emitting the raw path. Per CONTEXT, each row's target must resolve against the re-fetched session before rendering:

| Row state | Condition | Visual treatment | Interactive? |
|---|---|---|---|
| Resolved | Path resolves to a `fileId` in the re-fetched session (includes a path still listed with a deletion-kind status — "removed but still shown as a deletion diff") | Unchanged: `<button type="button" class="ui-button">{{ path }}</button>` | Yes — click opens that file (deleted paths open their deleted-diff state, same as any other file) |
| Absent | Path does not resolve to any `fileId` in the re-fetched session at all | Muted label, **not a button** — plain text at `--text-muted` + a `ReviewStateBadge` chip | No — no click handler, not focusable, not a `<button>` element |

Markup for the "Absent" row (new — minimal CSS addition, one line, reusing `--text-muted` exactly like the existing `.name-tone--muted` one-liner at `styles.css:1146-1148`):

```html
<li v-for="path in removed" :key="path">
  <button v-if="resolvePath(path) !== undefined" type="button" class="ui-button" @click="emit('select-file', resolvePath(path))">
    {{ path }}
  </button>
  <span v-else class="refresh-summary-row--removed">
    {{ path }}
    <ReviewStateBadge kind="disabled" size="compact" label="Removed" />
  </span>
</li>
```

```css
.refresh-summary-row--removed {
  display: flex;
  align-items: center;
  gap: var(--space-2);
  color: var(--text-muted);
}
```

Same branch applies identically inside the Added and Modified `<li>` loops (resolution is applied uniformly across all three lists per CONTEXT's "resolve each path to a fileId in the re-fetched session" — in practice only the Removed list is expected to ever hit the "Absent" branch, since Added/Modified paths are derived from the session that was just fetched, but the markup/condition is not list-specific).

**Why `ReviewStateBadge kind="disabled"` (default — derived from existing component, not a new one):** this exact kind/chip is already shipped and already means "present but non-actionable" — `DraftRecovery.vue`'s `ReviewStateBadge kind="disabled" label="Read only"` row is the direct precedent. It is deliberately **not** `kind="unavailable"` (the warning-toned chip `23-UI-SPEC.md` reserves for "Anchor missing") — "Removed" is a neutral/inert state (the file simply isn't part of the review anymore), not a warning, so it must not borrow the warning color (`--status-warning-foreground`). `kind="disabled"` is the only existing kind whose semantics and color (`--status-disabled-foreground`/`--status-disabled-background`, both muted, non-alarming) match.

**Emit contract change:** `RefreshSummaryPanel.vue`'s `select-file` emit now carries a resolved `fileId` (string), not the raw path — matching `App.vue`'s `selectFile(fileId: string)` signature, which today no-ops on a path. Exactly where the path→fileId resolution helper lives and how the resolved targets reach the component (props vs. internal computed) is Claude's Discretion per CONTEXT and is a wiring/architecture decision for the planner, not a visual one — this contract only fixes what must render and what must be clickable.

### 4. No other RefreshSummaryPanel changes

The existing heading (`"Since previous snapshot: …"`), the Added/Removed/Modified `<h3>` section headings, the stale/orphaned comment-count sentence, and the `InlineNotice tone="neutral" role="status"` wrapper are all unchanged verbatim.
