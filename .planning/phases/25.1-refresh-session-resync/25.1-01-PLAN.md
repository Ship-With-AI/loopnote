<objective>
Build and unit-test the pure path→fileId resolution helper that Phase 25.1's two production fixes (App.vue's selection-preservation re-derivation and RefreshSummaryPanel.vue's row-click target) both depend on. Per 25.1-CONTEXT.md's Claude's Discretion note, this is a new pure function in `src/web/model/`, matching `src/web/model/draft-reconciliation.ts`'s existing path-indexing shape rather than inventing a new pattern.

Purpose: SHELL-05 requires the post-Refresh summary's file links to open their files instead of no-opping on a raw path passed into the fileId-typed `selectFile(fileId)`. D-03 (25.1-CONTEXT.md) locks the resolution contract: resolve each path to a fileId in the re-fetched session; a removed path still listed (as a deletion) opens its deleted state; a path absent from the new session is unresolvable. Matching by fileId across a re-fetch is explicitly wrong (25.1-RESEARCH.md's Anti-Patterns: fileIds may change across snapshots) — the helper must match by effective path string, exactly like `src/domain/file-tree.ts:49-73`'s `effectivePath()` and `draft-reconciliation.ts`'s path-keyed index already do.
Output: `src/web/model/refresh-resolution.ts` (new, pure, tested in isolation before any component wiring touches it) and its dedicated unit test file.
</objective>
