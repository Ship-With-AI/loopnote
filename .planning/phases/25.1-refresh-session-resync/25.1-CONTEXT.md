# Phase 25.1: Refresh Session Resync - Context

**Gathered:** 2026-11-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Gap closure for the v2.1 milestone audit blocker (`.planning/v2.1-MILESTONE-AUDIT.md`): after Refresh in an uncommitted (Staged / Unstaged / Working tree) or standalone session, the visible session must reflect the recaptured snapshot everywhere, and the post-Refresh summary's file links must open their files. Requirements: IDENT-04, SHELL-05.

Root causes (audit, verified): `src/web/App.vue` `performRefresh()` calls `refreshWorktreeSnapshot()` + `getDraft()` and reconciles comments, but never reloads the session, so `session.value.files` stays frozen at mount; `RefreshSummaryPanel.vue` emits `select-file` with a path string into `selectFile(fileId)`, which no-ops. Not in scope: server snapshot semantics, export bytes, draft schema.

</domain>

<decisions>
## Implementation Decisions

### Refresh resync behaviour
- After every successful `refreshWorktreeSnapshot()`, re-fetch the session via `sessionClient.getSession()` and replace `session.value` (the single source for tree, list, footer, ⌥↑/⌥↓ order, status bar, identity pill/popover), then reconcile comments as today. The v2.0 pre-Phase-14-edit code re-fetched the session in this path; restore that behaviour on the current workbench.
- Selection: keep the selected file if its **path** still exists in the new session (fileIds may change across snapshots — match by path); otherwise select the next file in tree order (previous if it was last), announcing once "{path} is no longer in the review; showing {next}".
- Summary links: resolve each path to a fileId in the re-fetched session; a removed path still listed (as deleted) opens its deleted state; a path absent from the new session renders as a muted "Removed" label, not a button.
- Preserve across Refresh: comments/threads and in-progress edit text (THREAD-08), panel open/tab, side-bar width/visibility, filter text, tree expansion where paths still exist.
- Coverage: one packaged-binary e2e per session kind (Staged, Unstaged, Working tree, standalone) that adds, modifies, and deletes files mid-session, triggers Refresh via the title bar, the popover, and ⌥⇧R, and asserts tree, navigation, status bar, pill, summary links, and comment survival; plus a unit test for path→fileId resolution.

### Claude's Discretion
- Where path→fileId resolution lives (a pure helper in `src/web/model/`), how the RefreshSummaryPanel receives resolved targets, and how re-fetch is sequenced with the existing busy/announce flow.

</decisions>
