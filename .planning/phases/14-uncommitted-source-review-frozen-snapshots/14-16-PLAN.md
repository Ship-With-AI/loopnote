<objective>
Wire 14-15's server-side D-19 mechanics (the `recoveryAvailable` session flag and `POST /api/uncommitted/recover-draft`) into the running browser shell: a session-client method, and a dismissible "Resume previous uncommitted review?" offer in `App.vue`'s `.shell-warning-stack` whose acceptance copies the prior draft's comments into the active workspace. This is the client half of D-19's relaunch-recovery offer; 14-15 built the server half this plan depends on.

Purpose: make the offer D-19 requires ("offers recovery through the existing draft-recovery flow... Accepting creates a new draft... comments copied and reclassified") actually visible and actionable in the browser, closing the gap where `findUncommittedDraftCandidate`'s result previously reached nobody but a CLI console line.

Output: `client.ts`'s `recoverUncommittedDraft()` method; `App.vue`'s `recoveryAvailable` computed, the "Resume previous uncommitted review?" `InlineNotice` banner, and `acceptUncommittedRecovery()`.
</objective>
