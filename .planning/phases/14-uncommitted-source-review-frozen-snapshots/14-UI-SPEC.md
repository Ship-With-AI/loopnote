## Component Contracts

### `src/cli/picker.ts` (D-01, D-02, D-03)

- Add a top `{ kind: 'separator', label: 'Uncommitted' }` group to the **Base**-role prompt's item list (`buildSourceSearchItems`, `picker.ts:191-226`), before the existing `Local branches` separator, containing three candidate-style rows: `Staged`, `Unstaged`, `Working tree`. These are a new `SourceSearchItem` variant (not a `BranchCandidate`/`WorktreeCandidate`); they must render with the same single-line bracket-free format as the group rows (no `[Branch]`/`[Worktree]` prefix, since they are a third candidate kind, not a selector type) and no "Suggested" suffix.
- Selecting one of these three rows switches the flow per D-01: Unstaged (D-05) skips the second prompt entirely and launches immediately; Staged/Working tree advance to the existing Base-selection prompt (today's second step) with `HEAD`/the current branch preselected as the default so **Enter accepts** without typing.
- The existing committed Base→Head two-step flow is visually and textually unchanged for every row that is not one of the three new Uncommitted rows.
- Picker rows are never disabled for "no changes" (D-03) — emptiness is discovered only after launch, inside the workspace's "No changes" empty-session state (see `App.vue` below), not at the picker.
- `--base` combined with `--unstaged` is rejected with the exact Copywriting Contract error string above (D-05).

### `IdentityHeader.vue` (D-01 source label, D-13 Refresh control, D-14 change indicator, D-12/D-15 banner hosting)

This component gains a third session shape alongside today's `isExactPatch`/pinned-committed branches: an **uncommitted session** (`'sourceKind' in props.session`, naming left to the planner's wire contract — see canonical_refs `src/contracts/request.ts`/`src/contracts/comparison.ts`).

- **Comparison strip** (`.session-header__comparison`): add a third `<template>` branch, visually identical in structure to the existing two (`BASE`/`HEAD` endpoint spans, decorative `→`, same `.session-header__endpoint`/`.session-header__endpoint-label`/`.session-header__selector` classes — no new CSS rule needed beyond reusing these exactly):
  - **Staged / Working tree:** `BASE` endpoint shows the resolved Base candidate label + short OID exactly as today's pinned `baseLabel`/`baseOid` computed properties already render (D-06: merge-base(Base, HEAD), same value the committed flow already computes). `HEAD` endpoint shows the Copywriting Contract source label (`Staged` / `Working tree`) followed by `· snapshot {first 7 hex chars of the current snapshot's content digest}`, mirroring the existing `· {short oid}` suffix format but naming "snapshot" instead of a commit, since no single commit OID identifies uncommitted content.
  - **Unstaged:** `BASE` endpoint shows the fixed label `Index` with no OID/title suffix (D-05: Unstaged has no Base choice, so this is never a clickable/selectable value, just descriptive text — same non-interactive `<span>` the other endpoints already use). `HEAD` endpoint shows `Unstaged · snapshot {short digest}`.
- **Cue text** (`.pin-cue`, `IdentityHeader.vue:99`): extend the existing ternary to a three-way match — `Pinned comparison` (committed) / `Frozen patch` (exact-patch) / `Frozen snapshot` (uncommitted, resolved above).
- **Dirty badge** (`dirtyEndpoints`/`.dirty-badge`, `IdentityHeader.vue:37-47,100-109`): must **not** render for uncommitted sessions — the existing "Dirty bytes ignored" badge communicates that staged/unstaged/untracked bytes are being *ignored*, which is false for an uncommitted session (that is exactly the content being reviewed). Gate `dirtyEndpoints` to return `[]` whenever the session is uncommitted, the same way it already returns `[]` for exact-patch (`IdentityHeader.vue:38-39`).
- **Refresh control** (new, D-13): a new button in `.header-facts`, positioned immediately before the existing `Review notes` button (after any `attached-fact`), using the identical `identity-disclosure` class as `Support Cumpa`/`Review notes` (`IdentityHeader.vue:111-129`) — **not** `identity-disclosure--accent` (Refresh is a routine action, not the phase's primary CTA; accent stays reserved for `Review notes` per the existing reserved-for list). Rendered **only** when the session is snapshot-backed (uncommitted now; standalone-file sessions reuse this same control in Phase 15 per D-13's "shown only for snapshot-backed sessions"). Label `Refresh`, accessible name `Refresh snapshot`, wrapped in the existing `UiTooltip` primitive (`ui/UiPrimitives.vue`) showing `Refresh snapshot · Alt+Shift+R`. While in flight: `disabled`, `aria-busy="true"`, visible text `Refreshing…`, reusing the existing `ui-spinner`/`ui-button--busy` pattern (`DraftRecovery.vue:194-202`) — note `IdentityHeader.vue` does not yet import that pattern, so this is this phase's first consumer inside the identity header, not a new visual pattern.
- **Passive change indicator** (new, D-14): a non-interactive `<span class="change-indicator">` placed immediately before the Refresh button (same `.header-facts` flex row, `--space-2` gap), visible text `Working tree changed since snapshot`, shown only when the polling check (modeled on `SelectorDriftObserver`, `src/git/selector-drift.ts`) reports a difference. **Never triggers a refresh itself** — it is inert text, not a button, matching D-14's "Never auto-refresh" and avoiding a second affordance that could be mistaken for a live toggle.
- **Refresh icon**: add one new `refresh` glyph to `UiIcon.vue`'s `UiIconName` union and `<template>` switch, drawn in the same stroke-based `viewBox="0 0 16 16"` style as the existing 12 glyphs (a simple circular-arrow path, consistent stroke-width `1.5`) — the only new icon this phase introduces, and it is additive to the existing local component, not a new dependency.
- This component also becomes the mount point for the session banner (D-12) and the Refresh summary panel (D-15) via the existing `shell-warning-stack` section in `App.vue` (unchanged location/ordering — see `App.vue` below), not inside `IdentityHeader.vue` itself; `IdentityHeader.vue` owns only the strip/cue/badge/Refresh/indicator described above.

### Session banner — "Changed during capture" (new, D-09/D-12)

- Reuses `InlineNotice.vue` with `tone="warning"` `role="note"` (not `alert` — it is informational, the session still opened normally per D-09's "the rest of the session opens normally"), placed in `App.vue`'s existing `.shell-warning-stack` section (`App.vue:1110-1119`) alongside `SelectorDriftNotice`/`StaleAnchorNotice`, after those if both are present (most-actionable-first ordering is unchanged; this is an additive sibling, not a reordering).
- **New capability `InlineNotice` does not yet have: dismissibility.** Add an optional `dismissible`/`dismissLabel` prop pair to `InlineNotice.vue` that renders a trailing `Dismiss` text button (same `ui-button` class every other inline action button uses) emitting a `dismiss` event, following the existing `SupportDialog.vue:52` "Not now" precedent for the interaction (a plain dismiss button, not a close-icon). This is the one new piece of shared-component surface this phase adds to `InlineNotice.vue`; every other consumer (`SelectorDriftNotice`, `StaleAnchorNotice`, existing `patchDrifted`/`actionMessage` call sites) is unaffected because the prop defaults to `false`/non-dismissible.
- Heading text uses the exact D-12 template (`{N} files changed during capture — Refresh to recapture`); dismissing hides the banner for the remainder of the session (parent-owned `ref`, same `dismissedForSession` pattern already used for the support dialog, `App.vue:113,970-973`) — dismissing never clears the underlying per-file "Changed during capture" marker/reason (those remain until the next successful Refresh recaptures the file).

### `FileRow.vue` (D-09/D-12 availability marker, D-15 post-Refresh marker)

- **"Changed during capture" availability**: extend the existing `availabilityLabel` computed (`FileRow.vue:28-37`) with a fourth case returning `Changed during capture`, following the exact same `.availability-marker`/`.availability-marker--{kind}` rendering the component already uses for `unsupported`/`unavailable` (`FileRow.vue:65-73`) — no new CSS class pattern, just a new availability kind value consumed identically. Status column (`StatusBadge`) is unaffected; this is purely the trailing marker column.
- **Post-Refresh "Changed" marker (D-15)**: a new, separate inline `<span class="tree-row__refresh-marker">Changed</span>` (accessible name `Changed since last snapshot`) positioned between `PathDisplay` and the line-counts column, visible only for files present in the most recent Refresh's added/removed/modified sets **and not yet opened this session** (cleared the moment that file becomes the selected/active file, matching D-15's "until each file is opened"). This marker coexists with normal reviewable rows — unlike the availability-column marker, it does not replace or gate reviewability. Use `--text-secondary` (existing muted metadata token), `12px`/`600` mono, matching the Typography contract above; never color-only because the word "Changed" is always rendered as text, never an icon/dot alone.
- Both markers may appear on the same row only in the impossible case of a file simultaneously torn-during-capture and present in a Refresh delta; in practice "Changed during capture" is cleared by the very Refresh that would populate the Refresh-delta sets, so this is not a real joint state — no extra visual rule is needed.

### `ActiveFileToolbar.vue` (D-09/D-12 header reason)

- When the selected file's non-reviewable reason is "Changed during capture", render the exact file-header copy from the Copywriting Contract (`This file changed while Cumpa was capturing the snapshot and could not be read consistently. Refresh to recapture it.`) in the same place/style the component already reserves for non-reviewable explanations — this phase does not change `ActiveFileToolbar.vue`'s existing `layoutLabel`/`status.kind` branching (`ActiveFileToolbar.vue:36-50,79-85`) for reviewable files; it only adds this one new non-reviewable-reason string alongside whatever existing non-reviewable messaging path the tree/empty-pane already uses for `unsupported`/`unavailable` files (see `09-UI-SPEC.md:259` precedent — the planner wires this into the same mechanism, not a new one).

### Refresh summary panel (new, D-15)

- A new dismissible panel, structurally modeled on `SelectorDriftNotice.vue` (sections-per-category, clickable action buttons) rather than plain `InlineNotice` text, because it must show grouped, clickable file lists:
  - Root: `<InlineNotice tone="neutral" role="status" dismissible dismiss-label="Dismiss Refresh summary">` — `tone="neutral"` because this is a routine confirmation, not a warning (parallel reasoning to the post-Refresh tree marker using a neutral/muted tone rather than warning).
  - Heading: the exact D-15 template string from the Copywriting Contract.
  - One `<section>` per nonzero category (`Added`, `Removed`, `Modified`), each a `<h3>{category}</h3>` followed by a `<ul>` of `<button type="button" class="ui-button">{path}</button>` rows — activating a row selects and opens that file (same `activate`/`select` event contract `FileTree.vue`/`FileRow.vue` already expose), closing the panel's file-focus loop without requiring the user to hunt for the file in the tree.
  - Comment-reclassification counts (D-16) render as a trailing `<p>` using the exact count-copy template from the Copywriting Contract, only when nonzero.
  - Placed in the same `.shell-warning-stack` section as the session banner, after it when both are visible (a Refresh that recaptures torn files clears the session banner's underlying count — see dismiss-independence note above — so both can legitimately coexist only in the rare case new tearing occurred again post-Refresh).
- Opens automatically after a successful Refresh that has at least one nonzero category (immediate, not requiring a user action to reveal it — "After Refresh, user sees a summary", SNAP-04); dismissing it does not undo or hide the underlying tree-row "Changed" markers (D-15: markers persist "until each file is opened" independent of panel dismissal).

### `App.vue` (D-03 empty-session state)

- Reuses the exact existing `emptyFilesCopy` pattern (`App.vue:169-188`) and its exact existing render site (`<section v-if="session.files.length === 0" class="empty-state"><h2>{{ emptyFilesCopy.heading }}</h2><p>{{ emptyFilesCopy.message }}</p></section>`, `App.vue:1160-1163`), extended with a fourth branch for uncommitted sessions returning the heading/body pairs from the Copywriting Contract above (one body variant per source kind, naming the resolved Base label for Working tree). No new markup, no new CSS class — this is purely a new branch in the existing computed and the existing `ChangedFilesDialog`'s `empty-heading`/`empty-message` props (`App.vue:1217-1219`) continue to receive the same values unchanged.
- No "disabled row" treatment exists anywhere in this flow (D-03 confirms picker rows are never disabled for emptiness) — this empty state is the only visual surface for "no changes."

### Single-pane rendering reuse (D-07, confirms composition only — no new contract)

- Untracked files in Working-tree sessions render as `added`-status files through Phase 13's existing single-pane adapter (`13-UI-SPEC.md` component contracts for `StatusBadge.vue`/`ActiveFileToolbar.vue`/`DiffWorkspace.vue`/`ReviewToolbar.vue`), entirely unchanged. The `, single pane` visually-hidden suffix (D-09 of Phase 13), `Added · Head only` header label, and hidden "Change navigation" toolbar group all apply identically to an untracked file in an uncommitted session as they do to a committed added file — Phase 14 adds zero new logic here, only confirms (for the planner/executor) that `singlePaneSideFor`/`StatusBadge`/`ActiveFileToolbar` already key off `status.kind === 'added'`, not off any committed-vs-uncommitted distinction, so no new routing is required.

## Accessibility Contract

- The session banner and Refresh summary panel use `role="note"`/`role="status"` respectively (never `alert` — neither is an error; both describe informational, already-resolved state), matching `InlineNotice`'s existing role vocabulary (`InlineNotice.vue:9`).
- The new `dismissible` prop on `InlineNotice.vue` must not remove the notice from the accessibility tree while open — it is a normal focusable button inside the existing `aside`; dismissing unmounts the `aside` entirely (not `visibility:hidden`), consistent with the existing "hidden regions leave the accessibility tree" invariant (`08-UI-SPEC.md:264`, `11-UI-SPEC.md:177`).
- The passive change indicator (`Working tree changed since snapshot`) is plain text content, not a live region — it does not interrupt focus or trigger an announcement on appearance/disappearance, since D-14 explicitly treats it as a cheap, non-urgent nudge, not an alert. (Contrast with the session banner, which does enter the existing `shell-warning-stack`'s visual flow but likewise uses no `aria-live` beyond what `InlineNotice` already provides via its own content being part of normal document flow — no new live-region owner is introduced; the existing single global live-region owner in `App.vue`, per `11-UI-SPEC.md:300`, remains sole announcer for comment-lifecycle events, and Refresh is not one of those events.)
- Refresh button exposes `aria-busy="true"` while in flight (existing pattern) so assistive tech announces the state change without a redundant `alert`.
- Post-Refresh tree-row "Changed" markers are always-visible text (not `aria-hidden`), so the accessible name of the row includes "Changed since last snapshot" in document order alongside the existing status/path/counts/availability name parts (`09-UI-SPEC.md:197`'s row accessible-name ordering), appended last — this phase extends that name-construction order with one new optional segment, never removing or reordering the existing ones.
- "Changed during capture" is spoken via the existing `.availability-marker` text (already always in the accessible name per `09-UI-SPEC.md:197`); no `aria-hidden` is added to it, matching every other availability value.
- Focus order is unaffected: Refresh and the change indicator sit after the existing `attached-fact` and before `Review notes` in `.header-facts`' existing DOM order — this is a pure insertion, not a reorder, so the file → Base → Head reading-order invariant (`08-UI-SPEC.md:265`, `11-UI-SPEC.md:148`) is untouched.
- The terminal picker's new `Uncommitted` group and its three rows follow `@inquirer/search`'s existing accessible-TTY rendering (the library's own list-navigation semantics); no new accessibility contract beyond exact row text is introduced because this is a terminal, not a browser, surface.
