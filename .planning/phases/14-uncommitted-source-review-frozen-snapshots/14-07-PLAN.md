<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worktree/index bytes at an arbitrary point in time → persisted `.cumpa/` snapshot content | This module freezes live, externally-mutable filesystem state into immutable on-disk snapshot files; the central risk is persisting an inconsistent read as if it were consistent. |
| Snapshot store writes → filesystem | All writes stay under the session's own snapshot root inside `.cumpa/`, never under `.git/`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-07-01 | Tampering | Torn-read bytes silently persisted as consistent | mitigate | `captureFileWithRetry`'s stat-before/read/stat-after bracket plus explicit `'changed-during-capture'` classification (Task 1); a torn file's bytes are never written to the content store at all — this is the phase's central data-integrity guarantee (SNAP-02), directly verified by Task 1's no-partial-bytes-on-disk assertion. |
| T-14-07-02 | Tampering | Concurrent index mutation producing a manifest inconsistent with either index state | mitigate | `captureWithIndexRaceGuard`'s before/after `indexIdentity` bracket with one whole-capture retry, surfaced as a distinct `indexRaceNotice` signal rather than silently accepted (D-11, Task 2). |
| T-14-07-03 | Denial of service | Unbounded snapshot size/file count | mitigate | `MAX_SNAPSHOT_FILES`/`MAX_SNAPSHOT_BYTES` ceilings mirrored from `patch-snapshot.ts`, and `boundedFileBytes` (reused from `snapshot-fs.ts`) caps every individual read at `MAX_SIDE_BYTES`. |
| T-14-07-04 | Information disclosure | Snapshot content written outside `.cumpa/` or into `.git/objects` | mitigate | All writes go through `writeOwned`/`syncDirectory` (reused from `snapshot-fs.ts`) against the caller-supplied snapshot root, which 14-08's session wiring constructs under `.cumpa/`; this module never invokes any `git hash-object -w`/`git update-index` write path (D-21). |
| T-14-07-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install in this plan — native `git` CLI, `node:crypto`/`node:fs/promises` built-ins, all already in the dependency tree. |
</threat_model>
