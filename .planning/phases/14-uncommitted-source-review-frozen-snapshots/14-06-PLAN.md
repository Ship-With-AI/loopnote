<objective>
Add an `Uncommitted` group (`Staged`/`Unstaged`/`Working tree` rows) to the interactive Base prompt in `src/cli/picker.ts`, per D-01: selecting one of these three rows switches the flow — Unstaged skips the Base prompt entirely (D-05), Staged/Working tree advance to the existing Base-selection prompt with `HEAD` preselected. Introduce a new return type `PickedSource` (a discriminated union of today's committed `OrderedSources` result and a new `UncommittedSourceSelection`) so the one caller (`runCli` in `src/cli/run.ts`, wired in 14-09) can branch cleanly.

Purpose: WTREE-01 requires the launch picker to offer Staged/Unstaged/Working tree as the Head source; D-01 specifies exactly where in the prompt flow these rows live and how the flow branches afterward.

Output: `buildSourceSearchItems` prepends the `Uncommitted` group ahead of `Local branches`; a new `pickSource(options, dependencies)` function (the picker's new top-level entry point, superseding direct `pickOrderedSources` calls from `run.ts`) returns `Promise<PickedSource>`.
</objective>

    In `src/cli/picker.ts`, add a new exported type `export type UncommittedRowKind = 'staged' | 'unstaged' | 'worktree';` and `export type UncommittedSourceSelection = Readonly<{ readonly kind: 'uncommitted'; readonly sourceKind: UncommittedRowKind; readonly base?: SourceCandidate; }>;` (`base` is present only when `sourceKind !== 'unstaged'`, per D-05).     Extend `buildSourceSearchItems` so that when `options.role === 'base'`, it prepends three candidate-shaped rows ahead of today's `{ kind: 'separator', label: 'Local branches' }` entry: `{ kind: 'separator', label: 'Uncommitted' }` followed by three `SourceCandidateSearchItem`-shaped rows with `value` set to new stable sentinel ids (`'cumpa:uncommitted:staged'`, `'cumpa:uncommitted:unstaged'`, `'cumpa:uncommitted:worktree'`) and `name` set to the exact Copywriting Contract strings `Staged`, `Unstaged`, `Working tree` (no `[Branch]`/`[Worktree]` prefix, no "Suggested" suffix, never `disabled` — D-03's "picker rows are not disabled for emptiness"). These rows must only be prepended when `options.role === 'base'`; the Head-prompt call (`options.role === 'head'`) is unaffected and keeps its current output unchanged.

    Add a new exported `export async function pickSource(options: PickOrderedSourcesOptions, dependencies: PickOrderedSourcesDependencies = {}): Promise<PickedSource>`. Implement it by running the Base-prompt selection loop itself (reusing the existing `prompt`/`sourceForPrompt` plumbing `pickOrderedSources` already builds), but after the Base prompt resolves, check whether the selected id is one of the three `cumpa:uncommitted:*` sentinels: if so, branch per D-01 — for `'cumpa:uncommitted:unstaged'`, return `{ kind: 'uncommitted', sourceKind: 'unstaged' }` immediately (D-05's "Base prompt is skipped"); for the other two, run **one more** prompt call using the existing committed Base-selection `sourceForPrompt`/`promptItems` machinery (so the second prompt shows the normal branch/worktree candidate list, not the Uncommitted group again) with its `message` set to the UI-SPEC's exact post-selection copy (`Choose base — changes will be compared from its merge base with HEAD`) and its `default` pre-filled to the current `HEAD`/current-checkout candidate's id (reuse the same `suggestedHeadId`-style lookup `pickOrderedSources`'s `runCli` caller already computes for `HEAD`, threaded in via a new `preselectedBaseId` option on `PickOrderedSourcesOptions`), then return `{ kind: 'uncommitted', sourceKind: <row>, base: <resolved candidate> }`. If the Base-prompt selection is a normal branch/worktree id (not one of the three sentinels), fall through into the existing committed Base→Head two-step loop unchanged and return `{ kind: 'committed', ...result }`. Keep the existing `pickOrderedSources` export and its `OrderedSources` return shape completely unchanged (it stays the committed-only building block `pickSource` now wraps and calls internally for the committed path) — do not delete or rename it, since changing its signature would be a breaking change to a function this plan does not need to touch.
