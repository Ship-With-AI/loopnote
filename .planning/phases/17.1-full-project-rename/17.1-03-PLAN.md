<objective>
Rename the npm package identity (`package.json` name/bin, `package-lock.json`'s regenerated name), the CLI command and its picker-mode identifiers (`src/cli/run.ts`, `src/cli/picker.ts`), and the Monaco editor theme/CSS-token-virtual-module identifiers (`src/web/monaco/theme.ts`, `diff-adapter.ts`, `scripts/token-root-plugin.mjs`) to `RENAME_MAP`-derived forms, using an AST-aware TypeScript rename (`ts-morph`) for the cross-file theme identifiers so every import/call site stays consistent.

Purpose: REN-01 requires the product renamed everywhere, with `--help` showing only the new name. This plan owns the "identity surface" a user sees first (package name, CLI command, picker prompts) plus the one place in the codebase where a cross-file TypeScript identifier rename (`CUMPA_THEME_ID`/`applyCumpaTheme`) genuinely benefits from `ts-morph`'s import-aware rename over a manual find/replace, per RESEARCH.md's tooling recommendation. This is a scope-sanity split of the original, oversized 17.1-03 (23 files) per the checker's warning; the web display-copy and release-script halves of that plan now live in 17.1-06 and 17.1-05 respectively.
Output: `package.json`/`package-lock.json` carry the new npm identity; `src/cli/run.ts`/`picker.ts` use only `RENAME_MAP`-derived CLI strings and env var names; the Monaco theme id, `applyCumpaTheme`-equivalent function, and the `virtual:${RENAME_MAP.slug}-tokens` module id are renamed consistently across `theme.ts`, `diff-adapter.ts`, and `token-root-plugin.mjs`.
</objective>
