# Phase 17.1 Plan 14: Support-store state-path rename and D-06 one-time copy Summary

**`resolveSupportStatePath` now resolves RENAME_MAP's Title-Case/lowercase Loopnote state-directory segments; a new `resolveLegacySupportStatePath` keeps the old Cumpa/cumpa path as the sole documented migration-source exception; `createSupportStore()` performs a guarded, atomic, mode-preserving one-time copy of a supporter's `support.json` from the old path to the new one on first run, proven by 4 dedicated real-filesystem tests.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 2 (RED, GREEN)
- **Files modified:** 6

## Accomplishments
- `src/server/support-store.ts`: `resolveSupportStatePath`'s macOS/Windows segment now uses `RENAME_MAP.xdgStateDirTitleCase` ('Loopnote') and its Linux/XDG segment uses `RENAME_MAP.xdgStateDirLower` ('loopnote'); the new `resolveLegacySupportStatePath` resolves the identical shape with the old literal `'Cumpa'`/`'cumpa'` segments, documented as the one intentional D-06 grep-audit exception.
- `createSupportStore()` gained a `legacyPath` option (defaulting to `resolveLegacySupportStatePath()`) and a `copyLegacyIfNeeded()` step run once per store instance before the first `state()`/`markVerified()` load: if the new path is missing and the legacy file exists, is not a symlink, and parses as a valid `SupportStateV1`, its exact original bytes (never re-serialized) are copied atomically via the shared `writeAtomic` primitive, opened with the legacy file's actual mode (read via `fileSystem.stat`) rather than a hardcoded default. A malformed/missing/symlinked legacy file is silently left alone and falls through to ordinary initialization — never partially trusted, never a move.
- `tests/api/support-store.test.ts`: extended the path-resolution table with 5 new-form assertions and added a 5-case `resolveLegacySupportStatePath` table (still asserting the old literal paths), plus 4 real-temp-directory D-06 tests: copy-when-missing (byte-exact), no-copy-when-present (existing new-path content untouched), old-file-untouched (legacy bytes/mtime unchanged after copy), mode-preserved (`0o640` legacy mode reproduced exactly on the copied file).
- `tests/api/support.test.ts` / `tests/unit/shared-support-home.test.ts`: renamed `cumpa-support-`/`cumpa-support-override-` tmpdir prefixes to `${RENAME_MAP.slug}-...` forms.
- `tests/e2e/public-support-states.spec.ts`: renamed `kind: 'cumpa.review-request'` to `${RENAME_MAP.kindPrefix}.review-request`; renamed the dialog heading/body/button display-copy assertions ("Support Cumpa" → "Support Loopnote", "Cumpa stays fully usable..." → "Loopnote stays fully usable...") and the hosted-completion text ("...return to Cumpa." → "...return to Loopnote.") to match 17.1-06's `SupportDialog.vue` and 17.1-09's `support-flow/index.ts` renames; renamed `CUMPA_SUPPORT_STATE_WINDOW` to `${RENAME_MAP.envPrefix}SUPPORT_STATE_WINDOW` (both the read site and the thrown-error message).
- `tests/package/marketplace-profile-acceptance.test.ts`: renamed its `CUMPA_SUPPORT_STATE_WINDOW` read, thrown-error message, and forwarded-environment key to the same `${RENAME_MAP.envPrefix}SUPPORT_STATE_WINDOW` form, per the orchestrator's explicit instruction to keep 17.1-08's deferred cross-file contract consistent.
