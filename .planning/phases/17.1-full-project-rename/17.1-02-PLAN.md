<objective>
Rename the agent protocol's `kind` literals from `cumpa.review-request` / `cumpa/export` to `RENAME_MAP.kindPrefix`-derived values, add a specific, tested rejection path for requests still carrying the old literal kind, and update every consumer of these literals repo-wide — including the CLI-layer request test, the e2e export-safety spec, the committed export snapshot, and the markdown/uncommitted-contract fixture tests that assert on the export `kind` field directly. Today old-kind requests fall through to a generic `'unknown-mode'`/`'invalid-request'` error; after this plan they get a dedicated `'legacy-kind'` error naming the new kind.

Purpose: REN-02 requires the protocol to use new kinds only, with old-kind requests rejected before launch with a specific error. The checker's review confirmed the core schema/guard work was correctly scoped in the original plan, but found the plan's own `files_modified` omitted several real consumers of the `kind` literal discovered by this revision's full-tree reconciliation — `tests/cli/request.test.ts` (asserts the exact old-kind rejection body), `tests/e2e/agent-ready-export-safety.spec.ts` and `tests/unit/review-markdown.test.ts`/`tests/unit/uncommitted-contracts.test.ts` (fixture objects using `kind: 'cumpa/export'` or `kind: 'cumpa.review-request'` literally), and the committed snapshot file `tests/unit/__snapshots__/review-export.test.ts.snap` (a stale snapshot would fail Vitest's snapshot-diff check the moment the builder's output changes). Without these, `npm test` fails after this plan executes even though `tsc --noEmit` might still pass.
Output: `AgentReviewRequestSchema` and all six `ReviewExportVN` schemas accept only the new kind literal; `AgentRequestErrorKind` gains `'legacy-kind'`; `readAgentReviewRequest` rejects old-kind bodies with that specific error before any Git/browser work; every fixture, spec, and the committed snapshot that references either kind literal is updated to match.
</objective>
