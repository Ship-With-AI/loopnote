Add three new props: `hasThreadsAnywhere: boolean` (disables previous/next-thread when false — per UI-SPEC's keyboard table, "no threads exist anywhere in session", NOT scoped to the current file, since ⌥F9/⇧⌥F9 jump across files), `anyThreadExpanded: boolean` (drives the collapse/expand icon+label swap for the CURRENT file only, per UI-SPEC's Collapse Behavior section), and `hasCommentsInCurrentFile: boolean` (hides the collapse/expand button entirely when the current file has zero comments, per UI-SPEC's "If file has zero comments, button not rendered" rule — this is a `v-if`, not `:disabled`, unlike the other two buttons).

Add three new emits: `previousThread: []`, `nextThread: []`, `toggleThreadsCollapsed: []`.

Append a new `<span class="editor-title__separator" aria-hidden="true" />` followed by `<div class="editor-title__group" role="group" aria-label="Comment threads">` after the existing Markdown-mode group (after line 214's closing `</template>`, before the `filesDrawer` button at line 215) containing:
- A `previous-thread` icon button, `aria-label="Previous thread"`, tooltip text `"Previous thread · Option+F9"` (Windows/Linux: `"Previous thread · Alt+F9"` — reuse the existing platform-detection convention already driving other tooltip text in this file's sibling components, or hardcode the Mac glyph form if no existing helper is in scope — check `UiTooltip`'s callers elsewhere in `src/web/components/workbench/` for the established Windows/Linux fallback pattern before inventing a new one), `:disabled="!hasThreadsAnywhere"`, `@click="emit('previousThread')"`.
- A `next-thread` icon button, same shape, `aria-label="Next thread"`, tooltip `"Next thread · Shift+Option+F9"`, `@click="emit('nextThread')"`.
- A single collapse/expand button, `v-if="hasCommentsInCurrentFile"`, whose icon is `collapse-threads` when `anyThreadExpanded` else `expand-threads`, whose `aria-label`/tooltip text is `"Collapse all threads"` when `anyThreadExpanded` else `"Expand all threads"` (label always names the action the click performs, never the current state — same discipline the existing `renderSideBySide` toggle group already follows and the one this file's own 20-UI-REVIEW.md lesson locks in), with no `aria-pressed` (unlike the diff-layout toggle, this is an action button with a swapping label, not a two-state pressed toggle), `@click="emit('toggleThreadsCollapsed')"`.

Both previous-thread/next-thread icons stay visible (not hover-opacity-gated) in every mode including when `singlePane` is true — unlike the existing previous-change/next-change group (`v-if="!singlePane"`, lines 114-138), do not wrap the new group in that same `v-if`.
