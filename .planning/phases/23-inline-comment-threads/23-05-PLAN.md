Add three new private methods, generalizing `createSpacerZone`/`addZone`/`positionZones`/`growPairedZones` (lines 667-700) from operating on the two private fields to operating on one `threadZones` entry looked up by key:
- `createThreadZone(commentId: string, anchor: Anchor): HTMLElement` — creates a plain spacer `IViewZone` on BOTH sides (both `suppressMouseDown: true`, `aria-hidden`, per Pattern 2's "the zone's domNode becomes a plain, non-interactive spacer again — on both sides, including the anchored side"), positions them at `anchor.line`/the counterpart line (reuse `counterpartBoundary`, same as `rebuildAnchoredLayout` does today), and creates exactly one widget (content or overlay, per the spike's decision) attached to the anchored side's editor only, whose DOM node is returned to the caller for Vue mounting. For the overlay-widget variant, wire the anchored zone's `onDomNodeTop` to update `widgetTop` and call `editor.layoutOverlayWidget(widget)`, per RESEARCH.md's Pattern 2 code example.
- `growThreadZone(commentId: string, heightInPx: number): void` — looks up the one `threadZones` entry, sets both sides' `zone.heightInPx`, and issues both `layoutZone()` calls back-to-back inside one `changeViewZones` pass per side, synchronously (RESEARCH.md Pitfall 1 — never let a `nextTick()` separate the two calls for the same thread), then re-layouts the widget.
- `removeThreadZone(commentId: string): void` — removes both zones and the one widget, deletes the map entry.

Apply the identical generalization to `PublicMonacoSinglePaneAdapter`'s single `zone` field (lines 721, 1077-1090): a `threadZones = new Map<string, { zoneId: string; zone: monaco.editor.IViewZone; widget: ...; widgetTop: number }>()` with the same three methods, simplified (one editor, no counterpart/pairing — no `growPairedZones`-style two-sided call, just one `layoutZone()`/one widget relayout per operation). Keep this class's existing `this.zone`/`createComposerZone`/`rebuildAnchoredLayout` single-field composer path unchanged, same reasoning as the two-pane class.

Add the gutter `+` composition hover affordance (THREAD-06): add a new decorations collection (alongside the existing `originalDiffDecorations`/`modifiedDiffDecorations`, created in the constructor) covering every valid line (1 to the model's line count) with `glyphMarginClassName: 'diff-gutter-line'` — a decoration class distinct from and additive to `buildDiffDecorations`'s existing `monaco-diff-change-sign--*` classes (Monaco applies classNames from multiple decoration collections touching the same line to the same glyph-margin DOM node). Clicking inside this affordance uses the existing `activateFocusedAnchor`/`captureAffordance`/`onMouseDown` wiring already present (lines 181-184) — do not add a new click handler, only the hover-visible `::before` chip. Add `.diff-gutter-line:hover::before` to `styles.css` exactly per UI-SPEC's CSS block (content `'+'`, `background: var(--interactive-accent-emphasis)`, `color: var(--text-on-emphasis)`).
