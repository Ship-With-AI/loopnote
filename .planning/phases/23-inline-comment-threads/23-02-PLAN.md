<feature>
  <name>Cross-file thread order with wraparound</name>
  <files>src/web/model/thread-order.ts, tests/unit/thread-order.test.ts</files>
  <behavior>
Export a pure module with no Monaco/Vue imports:

- `flattenThreadOrder(comments: readonly WorkspaceComment[], flatFileRows: readonly VisibleFileTreeLeaf[]): readonly ThreadOrderEntry[]` where `ThreadOrderEntry = Readonly<{ commentId: string; fileId: string; side: DiffSide; line: number }>`. Build a `Map<fileId, number>` from `flatFileRows`'s index (the already-produced tree-path order, per `file-tree.ts:37,186-194,298` — never re-derive tree order independently), filter out comments whose `fileId === null` (orphaned — no file to jump to), then sort by `(treeIndex, side === 'base' ? 0 : 1, line)` ascending. Comments whose `fileId` is not present in `flatFileRows` (file not currently visible/filtered out of the tree) are also excluded, same reasoning as orphaned.
- `nextThread(order: readonly ThreadOrderEntry[], currentCommentId: string | undefined): Readonly<{ entry: ThreadOrderEntry; wrapped: boolean }> | undefined` — returns the entry immediately after `currentCommentId`'s position in `order` (or the first entry if `currentCommentId` is undefined or not found), `wrapped: true` only when stepping past the last entry back to the first. Returns `undefined` when `order` is empty.
- `previousThread(order, currentCommentId)` — mirror of `nextThread`, `wrapped: true` only when stepping before the first entry to the last.

Cases (write as `expect(...).toEqual(...)`/`toBe(...)` before implementing):
- Empty `comments` → `flattenThreadOrder` returns `[]`; `nextThread([], undefined)` → `undefined`.
- Two comments in the same file, same side, different lines → ordered by line ascending.
- Two comments in the same file, one `side: 'base'` one `side: 'head'`, same line → base before head.
- Two comments in different files → ordered by each file's position in `flatFileRows`, regardless of line number (a line-9999 comment in the first tree file still precedes a line-1 comment in the second tree file).
- A comment with `fileId: null` (orphaned) is excluded from the returned order entirely.
- A comment whose `fileId` has no matching entry in `flatFileRows` is excluded.
- `nextThread(order, lastEntry.commentId)` on a 3-entry order → returns entry 0 with `wrapped: true`.
- `previousThread(order, firstEntry.commentId)` on a 3-entry order → returns the last entry with `wrapped: true`.
- `nextThread(order, undefined)` → returns the first entry, `wrapped: false`.
- `nextThread(order, 'id-not-in-order')` → returns the first entry, `wrapped: false` (graceful fallback, e.g. the current thread was just deleted).
  </behavior>
  <implementation>
Implement after the RED tests above are written and failing. Follow `comment-groups.ts`'s existing comparator-composition style (`orderComments`, lines 52-58: compose tiebreakers left-to-right, each returning negative/zero/positive) for the sort, and `file-tree.ts`'s `flatFileRows` indexing idiom (build a `Map` once, O(1) lookups) rather than `indexOf` scans. No Monaco or Vue import in this file — it is consumed by Plan 23-08 (App.vue) and, for the Monaco-side `addAction` registration, indirectly informs Plan 23-05's `AdapterNavigation` callback shape, but this module itself stays presentation-free.
