# Phase 23 — UI Design Contract: Inline Comment Threads

> Visual and interaction contract for Phase 23 (THREAD-01..09). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Design source of truth: `.kimi-code/skills/sketch-findings-loopnote/references/comments-and-export.md` § Inline thread widget (sketch `004-comment-threads`, winning variant **A**). `23-CONTEXT.md`'s `<decisions>` block is locked and takes priority over the sketch wherever the two disagree (delete-Undo timing, reply textarea scope, collapse-default). Cross-cutting geometry/token precedent: `20-UI-SPEC.md` (shell tokens, icon-button conventions), `21-UI-SPEC.md` (declared type scale, accent-reservation discipline). This phase extends `EditorTitle.vue`, `diff-adapter.ts`'s paired-zone helpers, and the existing `CommentComposer.vue`/`ReviewStateBadge.vue`/`InlineNotice.vue` components; it does not touch `TitleBar.vue`, `StatusBar.vue`, `WorkbenchShell.vue`, or `FileTree.vue`.

Lesson carried from `20-UI-REVIEW.md`: never ship two differently-labelled controls for one piece of state (duplicate sidebar toggle was Top-3-Fix #2). This phase's single "Collapse all threads ⇄ Expand all threads" editor-title action is the **only** bulk collapse control — no second affordance is introduced elsewhere for the same state. Icon-only buttons always carry a paired `aria-label` + `title` tooltip (Top-3-Fix #3 lesson), and the pluralization idiom is always `{n} comment{{n === 1 ? '' : 's'}}` (exact convention already shipped at `App.vue:1375`, `RefreshSummaryPanel.vue:67,70`) — never a bare `{n} comments`.

## Monaco Integration & Thread Frame (THREAD-01, THREAD-06, THREAD-08)

Each thread renders as a Monaco view zone (`changeViewZones`) on its anchored side's editor, directly under the anchored line — the same mechanism `diff-adapter.ts` already uses for the composer zone (`createComposerZone`/`createSpacerZone`/`growPairedZones`). The opposite editor gets a paired empty spacer zone of equal height so Base and Head stay line-aligned (`setAnchorZoneHeight`/`growPairedZones`, reused unchanged). Interactive DOM inside a zone needs a content/overlay widget layered over the zone's `domNode` — raw view-zone DOM does not receive pointer events reliably (per `23-CONTEXT.md` Pitfalls, confirmed by the design source).

**Adapter architecture (Claude's Discretion per CONTEXT):** extend the paired-zone helpers into a keyed multi-zone map (`Map<CommentId, {anchorZoneId, spacerZoneId}>`), diffed by comment id on every draft/reconciliation update — never torn down and rebuilt wholesale (CONTEXT: "zones/widgets are diffed by comment id … never rebuilt wholesale").

**Frame (reuses `.conversation-card` base, `styles.css:225-234`, with a new state-coloured top rule):**

| Property | Value | Source |
|---|---|---|
| Border | `1px solid var(--border-default)` | existing `.conversation-card`/`.inline-comment-composer` rule |
| Top rule | `2px solid` in state colour (see State Chips) | new — `border-top` override per state, not a new token |
| Corners | bottom corners only: `border-radius: 0 0 var(--radius-overlay) var(--radius-overlay)` | `--radius-overlay` existing (6px) |
| Background | `var(--surface-panel)` | existing |
| Max width | `720px` | literal, matches design source |
| Code-column indent | `56px` from the gutter in side-by-side mode, `96px` in inline mode | literal from design source — **values to be confirmed empirically by the Plan 01 go/no-go spike** against this app's actual rendered `glyphMargin` + line-number column widths (`CODE_FONT_SIZE`/`lineNumbersMinChars` in `diff-adapter.ts`), not re-derived here |

```css
.comment-thread {
  border: 1px solid var(--border-default);
  border-top: 2px solid var(--interactive-accent); /* open */
  border-radius: 0 0 var(--radius-overlay) var(--radius-overlay);
  background: var(--surface-panel);
  max-width: 720px;
}
.comment-thread--resolved { border-top-color: var(--status-resolved-foreground); }
.comment-thread--stale { border-top-color: var(--status-warning-foreground); }
```

**Component split (Claude's Discretion per CONTEXT):** `CommentThread.vue`, mounted via Vue `render()` into the zone's widget DOM, matching how `CommentComposer.vue` is already mounted into composer zones today.

## State Chips (THREAD-02)

Three states, each with a non-colour-only text label (never colour-only, per THREAD-02): **Open**, **Resolved**, **Anchor moved**.

Reuse `ReviewStateBadge.vue` unchanged (icon + text, already the project's non-colour-only state-badge pattern) with its existing `kind` → colour mapping — no new colour tokens:

| Chip | `kind` prop | Icon | Colour token | Label |
|---|---|---|---|---|
| Open | `open` | `open` | `--interactive-accent` | `"Open"` |
| Resolved | `resolved` | `check` | `--status-resolved-foreground` | `"Resolved"` |
| Anchor moved | `stale` (existing kind — already means anchor-mismatch per `DurableAnchorV1Schema.verification.reason: 'anchor-mismatch'`) | `warning` | `--status-warning-foreground` | `"Anchor moved"` |

**Chip priority when a thread's verification state conflicts with its open/resolved state (default, undecided by CONTEXT — pick most consistent with Phase 20/21 conventions):** `resolved` wins over `stale` (a resolved thread shows **Resolved** even if its anchor later drifted — editing/re-anchoring is blocked until reopened, so the anchor-moved warning is secondary); otherwise an open thread with `verification.state === 'stale'` shows **Anchor moved**; otherwise **Open**. Orphaned comments (`verification.state === 'orphaned'`) never render inline (see **Orphaned Comments** below) — they use a fourth, separate chip (`kind="unavailable"`, label `"Anchor missing"`) only inside the file-level orphaned group.

**New size variant — compact/uppercase (default decision, deviates from the sketch's literal "10px uppercase pill"):** the sketch specifies a 10px uppercase pill; this project's governed type scale (`20-UI-SPEC.md`/`21-UI-SPEC.md`) already declares exactly four sizes (`--font-size-label` 11px, `--font-size-metadata` 12px, `--font-size-chrome` 13px, `--font-size-body` 14px) and explicitly avoids a fifth one-off value. Add a `size="compact"` prop to `ReviewStateBadge.vue` that maps to the nearest already-governed "small uppercase label" token instead of introducing 10px:

```css
.review-state-badge--compact {
  padding: 0 var(--space-2);
  border: 1px solid currentColor; /* matches sketch's 1px currentColor border; kind classes still set color */
  border-radius: var(--radius-pill);
  font-size: var(--font-size-label);       /* 11px, reused — not a new 5th size */
  letter-spacing: var(--letter-spacing-label);
  text-transform: uppercase;
  line-height: 15px;
}
```

Used only inside `CommentThread.vue`'s header; the existing default (non-compact) `ReviewStateBadge` usages elsewhere (`BottomPanel.vue`'s `Open N`/`Resolved N` counts, `DiffWorkspace.vue`'s accepted-comment card) are unchanged.

## Collapse Behavior (THREAD-05)

- **Default (locked, CONTEXT):** open threads start **expanded**; resolved threads start **collapsed**.
- **Collapsed row** shows the header line only (twistie, location label, state chip, one-line ellipsized snippet of the comment's first line) — body, meta line, and actions hidden (`display: none`).
- **Collapse state (locked, CONTEXT):** in-memory `Map<CommentId, boolean>`, scoped to the session (not persisted across reloads, not part of the draft).
- **Editor-title bulk toggle:** one icon button, placed after the existing icon groups in `EditorTitle.vue` (see **Editor-Title Navigation Icons**), applies to the **current file only**. Label reflects the action, not the current state (same pattern as Phase 21's list⇄tree toggle — icon/label always describe what clicking does):

| Current aggregate state (any thread in file expanded) | Icon (`UiIconName`) | Accessible name |
|---|---|---|
| ≥1 thread expanded | `collapse-threads` | `"Collapse all threads"` |
| all threads collapsed | `expand-threads` | `"Expand all threads"` |

If the file has zero comments, this button is not rendered (see **Copywriting Contract** — empty state).

Clicking it opens the **existing, unchanged** `CommentComposer.vue` composer zone at that line/side (same component, same copy — "Add comment" primary button, "Discard draft" destructive button, `.inline-comment-composer__support` helper text) — this phase does not introduce a new composer; it only adds the gutter trigger that opens it (today's composer is presumably opened by a different existing affordance that this phase does not change; the `+` chip is the new, additional pointer entry point named by THREAD-06).

## Editor-Title Navigation Icons (THREAD-07, THREAD-09)

New icon group appended after `EditorTitle.vue`'s existing groups (diff-layout, then Markdown source/preview when present), with a leading separator — same `editor-title__group` / `editor-title__separator` pattern already used for every other group in that row:

```
… [diff-split][diff-inline] | [markdown-source][markdown-preview] | [previous-thread][next-thread] | [collapse-threads/expand-threads]
```

Group wrapper: `<div class="editor-title__group" role="group" aria-label="Comment threads">`, matching the existing `aria-label="Diff layout"` / implicit Markdown group convention.

| Icon (`UiIconName`, new) | Accessible name | Shortcut | Disabled when |
|---|---|---|---|
| `previous-thread` | `"Previous thread · Option+F9"` (`"Previous thread · Alt+F9"` on Windows/Linux) | ⌥F9 / Alt+F9 | no threads exist anywhere in the session |
| `next-thread` | `"Next thread · Shift+Option+F9"` (`"Next thread · Shift+Alt+F9"` on Windows/Linux) | ⇧⌥F9 / Shift+Alt+F9 | no threads exist anywhere in the session |
| `collapse-threads` / `expand-threads` (mutually exclusive per current file state) | `"Collapse all threads"` / `"Expand all threads"` | — (no dedicated shortcut; click-only, not named by THREAD-09) | current file has zero comments |

Both icons always visible (not hover-opacity-gated) — same as every other `EditorTitle.vue` action icon today.

**Cross-file order (locked, CONTEXT):** tree path order (Phase 21's order), then Base before Head, then line number. Wraps around. ⌥F9/⇧⌥F9 fire both inside and outside the diff editor (document-level handler + Monaco `addAction`, same dual-registration pattern as F7/⇧F7 and ⌥↑/⌥↓ in `20-UI-SPEC.md`), always `preventDefault()`.

**Wraparound announcement (locked verbatim, CONTEXT):** reuses the app's single existing live-region (`App.vue`'s `announce()`/`liveMessage` — the one already wired for resolve/reopen/delete/export/refresh announcements). No second `aria-live` region is introduced.

- Wrapping forward past the last thread: `"Wrapped to first thread"`
- Wrapping backward past the first thread: `"Wrapped to last thread"`

Jumping to a thread in a different file: opens that file, expands the target thread (temporarily, regardless of its session collapse state, so it's visible), and scrolls it to center — matching the sketch's "opening the file and scrolling the thread to center."

## Edit-in-Place (THREAD-04)

Edit is available on **open threads only** (CONTEXT: resolved threads must be reopened first). Clicking the header's `edit` action replaces the thread body's static comment text with an inline textarea, pre-filled with the current body — reusing the existing `.inline-comment-composer textarea` sizing rule (`min-height: 76px; max-height: 240px`, `styles.css:1733-1739`).

| Interaction | Behaviour |
|---|---|
| ⌘Enter / Ctrl+Enter | Save — dispatches `editComment`, same `mutateReview()` path as resolve/reopen/delete; existing default announce text `"Comment saved locally."` (unchanged, no new copy) |
| Esc | Cancel — discards the in-progress edit text, reverts to the static comment display; no confirm needed (unlike the composer's discard-draft flow, since the original saved text is unaffected) |

**Visible buttons beyond the keyboard shortcut (default, pointer-accessible parity with the keyboard affordance):** two `.icon-btn` icons at the foot of the edit textarea — `check` (`aria-label="Save edit"`) and `close` (existing icon, `aria-label="Cancel edit"`) — plus helper text matching the existing composer's support-line convention: `"⌘Enter to save · Esc to cancel"` (12px, `--text-muted`, same role as `.inline-comment-composer__support`).

**Draft reconciliation / Refresh survival (THREAD-08, locked CONTEXT):** in-progress edit text is kept in memory keyed by comment id through reconciliation and Refresh. If the anchor becomes stale or orphaned mid-edit, the edit stays open with a warning (reuse `InlineNotice` tone `"warning"`, same component/tokens as every other warning notice in the app) rather than being silently discarded or auto-closed.

## Delete-with-Undo (THREAD-01, CONTEXT § Undo & anchor states)

**Timing (locked, CONTEXT — overrides the sketch's "~3s"):** clicking `delete` hides the thread immediately (optimistic, client-only) and shows a toast with an Undo action for **5 seconds**. The real `deleteComment` mutation is sent only when the toast expires or the session is left (flush on `pagehide`/`visibilitychange`). Undo restores the exact same comment id — no schema change, no new draft field.

**New component (no existing toast/snackbar precedent in the codebase — confirmed by `glob` across `src/web/components/`):** `UndoToast.vue`, reusing the app's existing overlay chrome recipe (same recipe `22-UI-SPEC.md` uses for the identity popover, same as `.modal-dialog`, `styles.css:737-741`) — no new hex, no new surface token:

```css
.undo-toast {
  position: fixed;
  bottom: var(--space-6);
  left: 50%;
  transform: translateX(-50%);
  display: flex;
  align-items: center;
  gap: var(--space-3);
  padding: var(--space-2) var(--space-4);
  border: 1px solid var(--border-overlay);
  border-radius: var(--radius-overlay);
  background: var(--surface-raised);
  box-shadow: var(--shadow-overlay);
  color: var(--text-primary);
  font-size: var(--font-size-chrome);
}
```

| Element | Copy |
|---|---|
| Toast body text | `"Comment deleted"` |
| Toast action button | `"Undo"` (`.icon-btn`-sized text button, not icon-only — visible label, no icon needed) |
| Live announcement on toast appearance | none new — the toast is visually self-announcing (`role="status"`); the single live-region (`announce()`) stays silent until the delete actually commits, to avoid a duplicate/competing announcement |
| Live announcement when the delayed delete finally commits (toast expiry or session leave) | reuses the **existing, unchanged** `App.vue` copy: `"Comment deleted. {open} open, {resolved} resolved."` |
| Live announcement on Undo click | `"Comment restored."` (new — minimal, no existing analog; comment never left the draft so no open/resolved recount is needed) |

`role="status"` on `.undo-toast` (not a second `aria-live="polite"` text node — the container itself carries the status role, matching the project's single-live-region-owner discipline by not stacking a nested live region inside it).

## Orphaned Comments & Anchor-Moved Copy (locked verbatim where the design source specifies it)

**Orphaned group (CONTEXT, locked structure):** comments whose anchor is unavailable (`verification.state === 'orphaned'`) are not rendered inline under any line (there is no line to anchor to). They render instead in a file-level group pinned at the top of the diff area:

| Element | Copy / spec |
|---|---|
| Group heading | `"Orphaned comments"` (locked, CONTEXT) |
| State chip (per comment inside the group) | `"Anchor missing"` (locked, CONTEXT) — `ReviewStateBadge` `kind="unavailable"` `size="compact"`, same warning colour token as Anchor moved (`--status-warning-foreground`), distinct text so the two conditions are never confused |
| Group container | reuses `.conversation-card` frame chrome (border/radius/background), no new container styling |

**Anchor-moved (stale) inline body copy — locked verbatim from the design source, carried unmodified into this contract:**

> "Line changed after this comment. Export marks it **stale**; re-anchor or keep as is."

Rendered as a warning row inside the thread body (`InlineNotice` tone `"warning"`, same tokens as every other warning notice), above the comment text, together with the recorded selected text quoted (CONTEXT: "the recorded selected text quoted in the body").
