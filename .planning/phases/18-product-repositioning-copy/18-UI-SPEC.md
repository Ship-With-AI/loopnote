**Voice (D-04, locked):** product-neutral, third person/imperative, factual — no founder first-person, no jokes (D-10). **Umbrella noun (D-07, locked):** every session kind is a "Review"; use "comparison" only where Base/Head literally exist (pinned-ref and exact-patch identity headers).

### Browser tab title (D-09)

| Element | Current | New pattern | Source |
|---------|---------|-------------|--------|
| `<title>` | static `Cumpa` | dynamic, computed per session: **`<Name> · <repo> · <session kind>`** | `index.html:7` (static tag removed in favor of runtime `document.title` assignment) |

Pattern breakdown, each segment grounded in existing computed state:

- **`<Name>`** — resolved from the Phase 17.1 product-identity module's display-name form (see Design System note above). Never hardcoded.
- **`<repo>`** — **gap, not currently wired**: no field carrying a repository/folder name exists on `SessionResponse` (`src/contracts/api.ts`) or anywhere in `src/web`. The server has no `repoName` concept today. Implementing this segment requires either (a) a new, trivial server-side field (e.g. `path.basename()` of the resolved repo root) threaded through the existing session response, or (b) deriving it client-side from an existing field if one is later found to carry a path. This is an implementation gap for the planner to size — it is not a new visual element or token, just a missing data field.
- **`<session kind>`** — reuse the phrases the UI already computes, don't invent new vocabulary:
  - Uncommitted sessions (`isUncommittedSession`): `{sourceLabel} vs HEAD`, e.g. `Working tree vs HEAD`, `Staged vs HEAD`, `Unstaged vs HEAD` — `sourceLabel` already exists at `IdentityHeader.vue:39-46`; this is the literal example given in `18-CONTEXT.md` §Specific Ideas (`<Name> · diff-review · Working tree vs HEAD`).
  - Standalone sessions (`isStandalone`): reuse the existing `standaloneLabel` pattern's file count, e.g. `3 files` — this is `18-CONTEXT.md`'s second literal example (`<Name> · diff-review · 3 files`); source the count from `standaloneSession.value?.changedFileCount` (`IdentityHeader.vue:51`).
  - Pinned range/comparison sessions (not exact-patch, not uncommitted): `{files.length} files`, same `N files` phrasing, sourced from `session.files.length` already available in `App.vue`.
  - Exact-patch sessions (`isExactPatchSession`): `Exact patch` — echoes the existing `'Frozen patch'` pin-cue (`IdentityHeader.vue:152`) and the existing loading-heading wording `'…loading exact patch'` (`App.vue:1208`).

Implementation note: this is new *wiring* (a computed `document.title` assignment, e.g. in a `watchEffect` in `App.vue`), not a new component — no `grep` hit for `document.title` exists anywhere in `src` today, so there is no prior pattern to follow or preserve.

### Empty states (D-10)

Pattern (locked): one short factual sentence stating what's empty, plus one short imperative sentence naming the next action. No jokes, no filler. `18-CONTEXT.md`'s own literal example — `No changes in Working tree. Edit files, then Refresh.` — is the worktree case below and is reused verbatim.

| Session kind | Current heading | Current message | New heading | New message | Source |
|---|---|---|---|---|---|
| Uncommitted, worktree | `No changes` | `The working tree matches {base}. | Uncommitted, staged | `No changes` | `There is nothing staged. Refresh after staging changes, or relaunch with a different source.` | `No changes staged.` | `Stage changes, then Refresh.` | `App.vue:212-213` |

| Exact patch | `No files in this exact patch` | `This accepted patch contains no changed file entries. Relaunch with a non-empty already-applied patch.` | **unchanged — already compliant** (fact + imperative next action) | — | `App.vue:198-201` |
| Pinned range, with scope | `No changes match this review scope` | `The pinned commits contain no changed files selected by this scope.` | `No changes match this review scope.` | `Relaunch with a different scope or range.` | `App.vue:205-208` (adds the missing next action) |
| Pinned range, no scope | `No changes match this review scope` | `The pinned commits contain no changed files.` | `No changes match this review scope.` | `Relaunch with a different range.` | `App.vue:205-208` |
