Close gap 1 from the orchestrator re-baseline (`25-VERIFICATION.md`'s `## Gaps (orchestrator re-baseline)` §1): `npm run typecheck:tests` is 0 errors at v2.0 close commit `0481bcc`; it is 4 errors now because `tests/unit/comment-thread.test.ts`, `tests/unit/identity-pill.test.ts`, and `tests/unit/status-bar.test.ts` import `.vue` components but were left in the plain-`tsc` `tsconfig.test.json` config instead of the vue-tsc `tsconfig.web.test.json` split that every other `.vue`-importing unit test already uses (the Phase 19 pattern).

<root_cause>
`tsconfig.test.json` globs `tests/unit/**/*.ts` and excludes a fixed list of `.vue`-importing files by name so they instead land in `tsconfig.web.test.json`'s `include` list (vue-tsc, which resolves `.vue` module types). The 3 files this plan moves were added by an earlier Phase 25 plan and never added to either list, so plain `tsc` tried to typecheck them and failed with `TS2307` (cannot find module '....vue'). `tests/unit/identity-pill.test.ts` additionally imports `'../../src/contracts/api'` without the explicit `.js` extension ECMAScript module resolution (`moduleResolution: node16`/`nodenext`) requires, producing a second error (`TS2835`) independent of the `.vue` split.

A second, unrelated pre-existing type error was masked by `typecheck:tests`'s `&&` short-circuit: `npm run typecheck:tests:node && npm run typecheck:tests:web` never ran the `:web` (vue-tsc) half while the `:node` half was red, so `tests/unit/monaco-diff-adapter.test.ts`'s `editor.addAction.mock.calls.map((call: [{ id: string; keybindings: number[] }]) => call[0])` — typed against a `vi.fn(() => disposable())` mock whose inferred call signature is zero-argument, not matching the hand-rolled tuple annotation — was never actually typechecked by vue-tsc. Fixing the 3-file split makes the `:node` half pass, which un-masks this and must be fixed in the same plan to keep the combined script green.
</root_cause>
