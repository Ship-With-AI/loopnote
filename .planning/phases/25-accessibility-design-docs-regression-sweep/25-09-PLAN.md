<objective>
Close gap 4 from the orchestrator re-baseline (`25-VERIFICATION.md` §4): list mode renders the dimmed directory segment before the file name; `21-UI-SPEC.md:197` requires the name first, then the dimmed directory. Fix list-mode rendering only — tree mode, and every other full-path ("breadcrumb") use of `PathText`, must stay unchanged.
</objective>

<root_cause>
`PathText.vue` unconditionally rendered `.path-text__directory` before `.path-text__filename` whenever `!basename`. `FileRow.vue` passes `basename="mode !== 'list'"` to `PathDisplay`/`PathText`, so list mode (`mode === 'list'`) is the one caller that sets `basename` to `false` for row-label display — every other `PathText`/`PathDisplay` use (`CommentComposer.vue`'s inline-comment-composer header, `App.vue`'s orphaned-comment heading, `AttachedCompletionWaiting.vue`'s unsaved-draft notices) also renders with `basename` falsy, but as a full continuous path string (e.g. "src/changed.ts") read as a breadcrumb, not as an Explorer-style row label — those must keep directory-then-filename order.

25-04 found this deviation from `21-UI-SPEC.md`'s "filename first… directory segment shown after it" wording but, instead of fixing it, added `file-tree.spec.ts:872`'s `segmentClasses` assertion asserting the wrong (directory-first) order and a comment claiming the shipped markup supersedes the spec, then routed the question to `25-VERIFICATION.md`'s Human Verification §1 as a UX judgment call rather than a defect.
</root_cause>
