  <behavior>
    - `resolveRelativeImagePath(markdownDisplayPath: string, rawSrc: string): string | undefined` — given the Markdown file's own display path (e.g. `docs/readme.md`) and the raw `src` string exactly as written in the Markdown (e.g. `./assets/logo.png`, `../shared/logo.png`, URL-encoded segments), returns the normalized, repository-root-relative POSIX path (e.g. `docs/assets/logo.png`, `shared/logo.png`) with no leading `/` and no `..` segments remaining; returns `undefined` if the normalized result would escape the repository root (starts with `../` after normalization) or is empty.
    - `readWorktreeImageBytes(repositoryRoot: string, relativePath: string): Promise<Buffer | undefined>` — walks `relativePath`'s segments one at a time from `repositoryRoot`, `lstat`-ing each intermediate path; returns `undefined` (not a thrown error) if any intermediate OR the final segment is a symlink, if any segment is missing, if the final segment is not a regular file, or if its size exceeds `MAX_IMAGE_BYTES`; otherwise returns its full bytes. Never calls `fs.realpath`.
    - `readCommittedImageBytes(repositoryRoot: string, commitOid: string, relativePath: string, runner: GitRunner, reader: ObjectReader): Promise<Buffer | undefined>` — runs `git ls-tree <commitOid> -- <relativePath>` scoped to `cwd: repositoryRoot`; returns `undefined` if the output is empty, if the entry's type is not `blob`, or if `reader.read(oid, {maxBytes: MAX_IMAGE_BYTES})` reports `kind: 'missing'` or exceeds the bound; otherwise returns the blob's bytes.
    - `IMAGE_CONTENT_TYPE_BY_EXTENSION` maps lowercased extensions (no leading dot) `png`→`image/png`, `jpg`/`jpeg`→`image/jpeg`, `gif`→`image/gif`, `svg`→`image/svg+xml`, `webp`→`image/webp`; any other extension (or a path with no extension) has no entry.
    - `CapabilityRegistry.readRelativeImage(fileId: string, side: AnchorSide, relativeSrc: string): Promise<Readonly<{ bytes: Buffer; contentType: string }> | undefined>` — `undefined` whenever: `fileId` is unknown; the resolved content-type is not in `IMAGE_CONTENT_TYPE_BY_EXTENSION`; the path-safety resolution fails; or the underlying read returns `undefined`. Each of the four `create*CapabilityRegistry` factories implements this using the Markdown file's own `path`/`repositoryRoot`/commit-OID-for-`side` already available in that factory's closure.
    - `GET /api/files/:fileId/image` — querystring `{ path: string; side: 'base' | 'head' }`, both required, zod-validated (`safeParse` → 400 on failure, matching the `/content` route's zero-extra-param discipline but requiring exactly these two). `fileId` fails `OpaqueFileIdSchema` → 404. `capabilities.lookup(fileId)` returns `undefined` → 404. `capabilities.readRelativeImage(fileId, side, path)` returns `undefined` → 409 (content unavailable, matching the `/content` route's existing 409-for-unavailable convention). Otherwise: `reply.type(contentType).send(bytes)`.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser → `GET /api/files/:fileId/image?path=&side=` | `path` is attacker-influenced if the reviewed repository itself is hostile (a crafted Markdown file can reference any string as an image `src`); `fileId`/`side` are opaque/enum-validated |
| Route → filesystem (worktree sessions) | Must never read outside the repository root, never follow a symlink |
| Route → git object store (committed sessions) | Must only ever resolve blobs that `git ls-tree` on a real pinned commit OID reports; never shells out with unsanitized interpolation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-16-05 | Tampering / Information Disclosure | `readWorktreeImageBytes` path traversal / symlink escape | mitigate | per-segment `lstat` walk from `repositoryRoot`, reject any segment that is a symlink or escapes via `..`, never `fs.realpath`-follow — exact Phase 15 D-04/FILE-04 precedent |
| T-16-06 | Information Disclosure | Arbitrary-file-type disclosure via spoofed extension (e.g. requesting `.env` renamed to `logo.png` in the Markdown source) | mitigate | `IMAGE_CONTENT_TYPE_BY_EXTENSION` allow-list checked server-side before any read is attempted; any other extension is rejected regardless of what the client's renderer requested |
| T-16-07 | Information Disclosure | `git ls-tree` resolving a non-blob tree entry (submodule/gitlink/directory) as if it were image bytes | mitigate | `readCommittedImageBytes` requires the parsed entry's type field to be exactly `blob`; anything else returns `undefined` |
| T-16-08 | Denial of Service | Oversized image exhausting server memory | mitigate | `MAX_IMAGE_BYTES` (10 MiB) bound enforced both in the worktree `lstat`-size check before reading and in the `ObjectReader.read(oid, {maxBytes})` call for committed sessions |
| T-16-09 | Spoofing/Tampering | `path`/`side` query params | mitigate | zod `safeParse` on both (`side` is a closed enum, `path` is a non-empty string); malformed input is a 400, never reaches resolution logic |
| T-16-10 | Elevation of Privilege (SSRF-adjacent) | Route becoming a general-purpose arbitrary-file-read oracle beyond the referencing Markdown file's own repository scope | accept — mitigated by design | the route is fundamentally scoped to the session's own `repositoryRoot`/pinned commit OIDs already established at session-launch time; it adds no new cross-session or cross-repository reachability |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | zero new npm dependency this task |

</threat_model>
