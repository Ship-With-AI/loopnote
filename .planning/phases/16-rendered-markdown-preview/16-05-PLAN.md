<objective>
Implement D-03's block-aligned, best-effort scroll sync between the two `RenderedMarkdownView` instances in side-by-side Rendered mode: scrolling either pane finds its topmost visible `.rendered-block`, finds the nearest-range block in the counterpart pane, and scrolls it into view — guarded against the feedback-loop failure mode RESEARCH.md's Pitfall 4 documents (a programmatic scroll firing the counterpart's own scroll listener, which scrolls back, producing jitter).

Purpose: resolves `16-UI-SPEC.md`'s Open Question #1/D-03 resolution ("block-aligned, best-effort, enabled default... no Monaco primitive exists to delegate to — two plain DOM panes, entirely outside Monaco"). This is deliberately a separate plan from 16-04 because it is a self-contained, independently-verifiable algorithm with its own correctness-critical pitfall, kept out of the larger host-swap task to avoid diluting either task's review focus.

Output: scrolling one Rendered pane visibly moves the other to the matching block, with no jitter.
</objective>

    Add a native `scroll` listener on the component's scrollable root container (the element with `overflow-x: auto` from plan 16-03's CSS; give it `overflow-y: auto` too if not already present, since this is the element that actually scrolls). On scroll, find the topmost `.rendered-block` whose bounding rect's top is `&gt;= container top` (first block not fully scrolled past, via `getBoundingClientRect()` comparison against the container's own rect, iterating the already-materialized block list — no virtualization, per RESEARCH.md's Don't-Hand-Roll guidance), and `emit('scrolledToBlock', { start: block.start, end: block.end })` (add this to `defineEmits`). Skip emitting (return early) when an internal `programmaticScrollInFlight` boolean ref is `true` — this flag is read here but SET by the exposed method below.
    Add `defineExpose({ scrollToRange(startLine: number, endLine: number): void })`: find the block in this instance's own block list whose `[start,end]` is nearest to `[startLine,endLine]` (exact match preferred; otherwise the block with the smallest absolute difference between its `start` and the target `startLine`), set `programmaticScrollInFlight.value = true`, call `block.element.scrollIntoView({ block: 'nearest' })`, then clear the flag on the next animation frame (`requestAnimationFrame(() => { programmaticScrollInFlight.value = false; })`) — never synchronously, so the native scroll event this triggers is still suppressed by the flag.
