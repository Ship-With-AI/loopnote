<objective>
Implement D-03's block-aligned, best-effort scroll sync between the two `RenderedMarkdownView` instances in side-by-side Rendered mode: scrolling either pane finds its topmost visible `.rendered-block`, finds the nearest-range block in the counterpart pane, and scrolls it into view — guarded against the feedback-loop failure mode RESEARCH.md's Pitfall 4 documents (a programmatic scroll firing the counterpart's own scroll listener, which scrolls back, producing jitter).

Purpose: resolves `16-UI-SPEC.md`'s Open Question #1/D-03 resolution ("block-aligned, best-effort, enabled default... no Monaco primitive exists to delegate to — two plain DOM panes, entirely outside Monaco"). This is deliberately a separate plan from 16-04 because it is a self-contained, independently-verifiable algorithm with its own correctness-critical pitfall, kept out of the larger host-swap task to avoid diluting either task's review focus.

Output: scrolling one Rendered pane visibly moves the other to the matching block, with no jitter.
</objective>

    Add three pure, DOM-free functions to the same `src/web/model/rendered-markdown-blocks.ts` module plan 16-03 created (no Vue/DOM import, directly `vitest`-testable against plain data), instead of inlining this logic in the component. `findTopmostVisibleBlock<T extends { start: number; end: number; top: number }>(blocks: readonly T[], containerTop: number): T | undefined` returns the first block in document order whose `top &gt;= containerTop` (first block not fully scrolled past; `undefined` for an empty list) — the component computes each block's live `top` via `getBoundingClientRect()` relative to the container's own rect immediately before calling this function, so the function itself stays pure arithmetic over plain numbers, never touching the DOM. `findNearestBlock<T extends { start: number; end: number }>(blocks: readonly T[], startLine: number, endLine: number): T | undefined` returns the block with an exact `[start,end]` match if one exists, otherwise the block with the smallest absolute difference between its `start` and `startLine` (`undefined` for an empty list) — this is `scrollToRange`'s nearest-match rule, extracted so it is unit-testable directly. `shouldEmitScrollSync(programmaticScrollInFlight: boolean): boolean` returns `!programmaticScrollInFlight` — RESEARCH.md Pitfall 4's feedback-loop guard decision extracted as its own named, directly-testable function instead of an inline `if` in the scroll handler, so the guard's exact polarity (suppress emission while a programmatic scroll is in flight, not the inverse) is pinned by a unit test rather than only by manual/e2e observation.
    Add a native `scroll` listener on the component's scrollable root container (the element with `overflow-x: auto` from plan 16-03's CSS; give it `overflow-y: auto` too if not already present, since this is the element that actually scrolls). On scroll, call `shouldEmitScrollSync(programmaticScrollInFlight.value)`; if it returns `false`, return without emitting. Otherwise compute each `.rendered-block`'s `top` via `getBoundingClientRect()` against the container's own rect (iterating the already-materialized block list — no virtualization, per RESEARCH.md's Don't-Hand-Roll guidance), call `findTopmostVisibleBlock` with that data, and when a block is found `emit('scrolledToBlock', { start: block.start, end: block.end })` (add this to `defineEmits`).
    Add `defineExpose({ scrollToRange(startLine: number, endLine: number): void })`: call `findNearestBlock` against this instance's own block list and the target `[startLine, endLine]`; if a block is found, set `programmaticScrollInFlight.value = true`, call `block.element.scrollIntoView({ block: 'nearest' })`, then clear the flag on the next animation frame (`requestAnimationFrame(() => { programmaticScrollInFlight.value = false; })`) — never synchronously, so the native scroll event this triggers is still suppressed by `shouldEmitScrollSync`.
    Extend `tests/unit/rendered-markdown-blocks.test.ts` (created in plan 16-03's Task 1) with cases for all three new functions: `findTopmostVisibleBlock` returns the first block whose `top &gt;= containerTop` from a sample list, and `undefined` for an empty list; `findNearestBlock` returns the exact `[start,end]` match when present, the closest-by-`start` block when no exact match exists, and `undefined` for an empty list; `shouldEmitScrollSync(true)` is `false` and `shouldEmitScrollSync(false)` is `true`.
