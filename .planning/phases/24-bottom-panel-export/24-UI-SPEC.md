# Phase 24 — UI Design Contract: Bottom Panel & Export

## Tab Bar & Panel Chrome (PANEL-01..05 shell)

**Structure** — `BottomPanel.vue` becomes the tab *shell*; it no longer renders comment counts, `SummarySection`, `ExportSection`, or the attached-completion block directly. It renders exactly one `role="tablist"` and three `role="tabpanel"` hosts, each wrapping one new child component:

```html
<section v-if="open" role="region" aria-label="Review" class="bottom-panel">
  <header class="bottom-panel__header">
    <div role="tablist" aria-label="Review panel" class="bottom-panel__tabs">
      <button
        v-for="tab in TABS" :key="tab.id"
        :id="`panel-tab-${tab.id}`" role="tab" type="button"
        class="bottom-panel__tab" :class="{ 'bottom-panel__tab--selected': activeTab === tab.id }"
        :aria-selected="activeTab === tab.id" :aria-controls="`panel-panel-${tab.id}`"
        :tabindex="activeTab === tab.id ? 0 : -1"
        @click="selectTab(tab.id)"
        @keydown.left="moveTab(-1)" @keydown.right="moveTab(1)"
      >{{ tab.label }}</button>
    </div>
    <button type="button" class="icon-btn" aria-label="Close panel" @click="emit('close')"><UiIcon name="close" /></button>
  </header>

  <div id="panel-panel-comments" role="tabpanel" aria-labelledby="panel-tab-comments" :hidden="activeTab !== 'comments'">
    <CommentsTab v-if="activeTab === 'comments'" ... />
  </div>
  <div id="panel-panel-summary" role="tabpanel" aria-labelledby="panel-tab-summary" :hidden="activeTab !== 'summary'">
    <SummaryTab ... />
  </div>
  <div id="panel-panel-export" role="tabpanel" aria-labelledby="panel-tab-export" :hidden="activeTab !== 'export'">
    <ExportTab ... />
  </div>
</section>
```

`TABS = [{ id: 'comments', label: 'Comments' }, { id: 'summary', label: 'Summary' }, { id: 'export', label: 'Export' }]` — text-only, no icons (see **Icon Inventory**). Tab labels are static; only the primary *action* inside the Export tabpanel relabels to "Finish review" in agent-attached sessions (see **Export tab**) — the tab button itself always reads "Export".

**Mount strategy (Claude's Discretion, default-from-precedent):** each `<XTab>` is `v-if`-gated on `activeTab === id` *inside* an always-present `role="tabpanel"` div that only toggles `hidden` — i.e. the inactive tabpanel's child component unmounts. This matches `SummarySection.vue`'s own inner edit/preview `role="tabpanel"` pair (lines 183–230), which already unmounts the non-active panel's content via `v-if`/`v-else` rather than `v-show`; Phase 24 reuses the identical pattern one level up, so no new mount-persistence convention is invented. Each tab's local presentation state (file-group collapse state in Comments, summary edit/preview mode, Export section's own `open` disclosure) is therefore session-local to that tab's own component lifetime, same as today.

**Keyboard (locked, CONTEXT):** `role="tablist"`/`tab`/`tabpanel`; Left/Right move *and* activate (automatic-activation pattern, same as `SummarySection.vue`'s existing inner Edit/Preview tablist at lines 152–181 — directly reused, not re-derived), wrapping at the ends (Export→Left wraps to Comments; Comments→Right wraps... wait, wraps to Summary going right, to Export going left). `⌘J`/`Ctrl+J` toggles the panel's `open` boolean — unchanged from Phase 20 (SHELL-02/03), not rebound by this phase.

**Last-used tab this session (locked, CONTEXT — in-memory only):** lives in `src/web/model/panel-state.ts`, *not* in `PersistedPanelState`/`loopnote.workbench.v1` (SHELL-04's persisted-fields list is `sidebarWidth`/`sidebarVisible`/`panelHeight` only; Phase 24 adds nothing to it). `panel-state.ts`'s `createPanelState()` gains a new field on its returned `PanelState` object:

```ts
export type PanelTab = 'comments' | 'summary' | 'export';

// inside PanelState interface, alongside existing panelHeight/sidebarWidth refs:
activeTab: ShallowRef<PanelTab>;
setActiveTab(tab: PanelTab): void;
```

Implemented as a plain `shallowRef<PanelTab>('comments')` (default on first load of a session — "Comments" is the natural landing tab for "start reading"), never read from or written to `localStorage`. `setActiveTab` just assigns the ref; it is called by (a) `BottomPanel.vue`'s own tab clicks/arrow-key activation via `update:activeTab` emit, and (b) `App.vue`'s `openPanel(tab)` (see next section) when a status-bar item opens the panel.

**Focus-into-target-tab-panel when opened from a status-bar item (locked, CONTEXT):** `BottomPanel.vue` exposes `focusActiveTab(): void` via `defineExpose` (same pattern as `StatusBar.vue`'s existing `defineExpose({ focusSupport })`), which moves focus to the currently-active tab's `role="tab"` button (not into the tabpanel's content) — this is the standard ARIA tabs pattern (focus the selected tab, then arrow keys/Tab continue naturally into the panel) and requires no new focus-target convention. This method is called **only** when a status-bar item opens the panel (see below); it is **not** called when `⌘J`/the title-bar panel toggle opens the panel (those keep today's behavior — no forced focus move, matching Phase 20 SHELL-02's existing "no keyboard-only forced-focus on toggle" precedent).

## Comments tab (PANEL-01)

**Visual hierarchy / focal point:** on the panel's default-landing tab (Comments), the file-group header row (600-weight name, `FileRow.vue`'s name-tone convention) is the primary focal element — it is the only 600-weight text in the tab and the only row with a disclosure affordance, so the eye lands on file identity first, then scans into the lighter-weight (400) comment rows beneath it. State icons (open/stale/resolved/anchor-missing) are the secondary scan target within each row, ahead of the muted first-line text and right-aligned mono location tag.

**Grouping (locked, CONTEXT):** file-outer, tree order (Phase 21's `flatFileRows` order — same projection `thread-order.ts` already consumes, imported the same way); inside each file: **open** (`state:'open'`, `status:'verified'`) → **stale** (`state:'open'`, `status:'stale'`) → **resolved** (`state:'resolved'`, any status — "resolved wins" matches `23-UI-SPEC.md`'s chip-priority rule verbatim), each bucket ordered by line ascending. **Orphaned comments** (`status:'orphaned'`) can never match a live `fileId` by definition (`23-03-PLAN.md`: "orphaned comments' recorded paths... do not correspond to any currently-resolvable file in the session's inventory") — they render as trailing groups, one per distinct recorded path, using Phase 23's existing `projectOrphanedCommentGroup()` unchanged, positioned **after** every tree-ordered live-file group, each labelled with the recorded path's display name and the `"Anchor missing"` chip (locked, Phase 23 copy) on every row inside it. Orphaned rows are not clickable (no live file/line to reveal — plain `<li>`, no `role="button"`, no `@click`).

**File-group header row:** twistie (▾/▸ text glyph, `aria-hidden`, same convention as `DirectoryRow.vue`'s `.directory-row__disclosure`), file-type mark (`fileTypeMarkFor()`, new shared export above), name + dim directory (`PathText.vue`, unchanged, same component already used inside `BottomPanel.vue`'s inline-composer notice), then the group's total row count (`"{n}"`, `--font-size-metadata`, no pluralized noun — matches sketch's bare count). `role="button"` `aria-expanded`, toggles that file group's row visibility; default **expanded**, collapse state is local `ref<Map<string, boolean>>` inside `CommentsTab.vue` (session-local presentation state, same precedent as `SummarySection.vue`/`ExportSection.vue`'s own local `open` disclosure refs — not lifted to `App.vue`).

**Thread row:** state icon + first-comment-line text (ellipsized, one line) + right-aligned mono side/line (`B4`/`H51` — bare letter+number, no space, no "Head ·" prefix; this is the Comments-tab list's compact format, distinct from the inline thread header's full `"Base · L4"` format in `23-UI-SPEC.md`):

| Bucket | Icon (`UiIconName`) | Text treatment |
|---|---|---|
| open | `comment` | `--text-primary` |
| stale | `warning` | `--text-primary`, plus the mono side/line gets `--status-warning-foreground` |
| resolved | `check` | `--text-muted` (entire row muted, per sketch) |
| orphaned (trailing group only) | `warning` | `--text-muted`; `"Anchor missing"` `ReviewStateBadge` chip (`kind="unavailable"` `size="compact"`, Phase 23's new prop) replaces the mono side/line (no live line to show) |

**Empty state (verbatim, design source):** `"No comments yet. Hover a line number in the diff and click +."` — shown when `comments.length === 0`, replacing the entire grouped list (no tab bar/header change).

**Row click / Enter reveal (locked, CONTEXT):** emits `reveal: [commentId: string, fileId: string, side: DiffSide, line: number]`, bubbled through `BottomPanel.vue` to a new `App.vue` function:

```ts
function revealCommentFromPanel(commentId: string, fileId: string, side: DiffSide, line: number): void {
  if (fileId !== selectedFile.value?.fileId) selectFile(fileId);
  collapsedByCommentId.value = new Map([...collapsedByCommentId.value, [commentId, false]]);
  void nextTick(() => {
    diffWorkspace.value?.revealComment(side, line);
    void nextTick(() => {
      (document.querySelector(`[data-comment-id="${commentId}"] .thread-header`) as HTMLElement | null)?.focus();
    });
  });
}
```

This reuses exactly the three pieces `jumpThread` (`23-08-PLAN.md`) already uses for cross-file thread navigation — `selectFile()`, the `collapsedByCommentId` expand-on-arrival map, and `diffWorkspace.value?.revealComment(side, line)` for the scroll — so "open the file, expand the thread, scroll it into view" is the *same* mechanism, not a parallel one. The one piece `jumpThread` does **not** do is move focus onto the thread's header; Phase 24 adds that as the final step above, targeting `CommentThread.vue`'s root (`[data-comment-id]`, already present — `jumpThread` itself queries it) and its header element (`.thread-header`, Phase 23's clickable collapse-toggle, already focusable by role/semantics per `23-UI-SPEC.md`'s Header Anatomy). No change to `CommentThread.vue`, `DiffWorkspace.vue`, or `thread-order.ts` is required — only this one new `App.vue` function and the `CommentsTab.vue`→`BottomPanel.vue`→`App.vue` emit chain.

## Summary tab (PANEL-02)

`SummaryTab.vue` is a thin wrapper mounting `SummarySection.vue` unchanged (same props/emits it has today). Two small, additive extensions **inside** `SummarySection.vue` itself:

**Autosave (locked, CONTEXT — 800ms, overrides the sketch's 500ms):**

```ts
let autosaveTimer: ReturnType<typeof setTimeout> | undefined;
watch(() => props.modelValue, () => {
  clearTimeout(autosaveTimer);
  if (!unsaved.value || props.pending || props.conflict) return;
  autosaveTimer = setTimeout(() => emit('save'), 800);
});
onBeforeUnmount(() => clearTimeout(autosaveTimer));
```

Guarded by the exact same `unsaved.value && !props.pending && !props.conflict` condition the existing ⌘Enter handler (line 97) already uses, so autosave calls the identical `emit('save')` path — same server-authoritative mutation, same conflict/stale-draft handling, zero new client state (per CONTEXT: "no client-synthesized state").

**Saving… / Saved indicator copy (locked, CONTEXT — matches sketch's "'Saving…' → '✓ Saved'" shape):** the existing `status` computed's `'Saving'` string gains an ellipsis → `'Saving…'`. `'Saved'` is already exact. No other `status` string changes (Conflict/Save failed/Retained strings stay as today — not addressed by CONTEXT, not in the sketch's two-state indicator). The `ReviewStateBadge`'s existing icon-by-`statusBadgeKind` mapping already renders a checkmark for the `'success'` (`Saved`) state and a spinner for `'pending'` (`Saving…`) — satisfies the sketch's "✓ Saved" visually without a copy-level checkmark character.

**⌘S / Ctrl+S immediate save (new, CONTEXT):** document-level handler in `App.vue` (same dual-registration/`preventDefault`-always convention as `⌘B`/`⌘J`):

```ts
} else if ((event.metaKey || event.ctrlKey) && event.key === 's') {
  event.preventDefault();
  if (panelOpen.value && panelState.activeTab.value === 'summary') emit → saveSummary path (same as clicking "Save summary"), clearing any pending autosave timer;
}
```

Active only while the panel is open and the Summary tab is selected (outside that, `⌘S` is `preventDefault()`-ed as a no-op, matching the project's existing "always preventDefault, even when inert" rule for global shortcuts — there is no competing `⌘S` binding anywhere else in the app today).

## Export tab (PANEL-03, PANEL-04, PANEL-05)

**Readiness checklist (locked copy, CONTEXT):** reuses `ExportReadinessSummary.vue`'s existing richer three-way breakdown (`Open actionable` / `Need reviewer attention` / `Resolved`) **unchanged** — this is a finer-grained, real-data breakdown than the sketch's naive two-field `"2 open · 1 resolved comments"` row, and is kept rather than collapsed (same precedent as `22-UI-SPEC.md`'s "keep the real derivable data over the sketch's simplified fiction" rule). The **Summary** row's copy is updated to CONTEXT's exact locked strings, superseding today's wording: `"Summary written"` (was `"Summary included"`) / `"No summary (optional)"` (was `"No summary provided"`). **No viewed row** — `ExportReadinessSummary.vue` already has none; nothing to remove (DEFER-01 confirmed out of scope).

**Stale/orphaned acknowledgement gate — data-grounding note (locked, CONTEXT, but the sketch's literal wording doesn't map to a real field):** the sketch depicts a fictional per-export checkbox keyed to an individual comment's anchor moving ("1 comment's anchor moved. Export it marked **stale**."). No schema field exists for a comment-anchor-specific export acknowledgement (`ExportReviewRequestSchema`'s only acknowledgement field is `driftAcknowledgementToken`, gated by the server's `driftAcknowledgementRequired`/`driftAcknowledgementStale` responses — both about **selector/source drift**, i.e. the pinned Base/Head ref moving, not comment anchors), and `24-CONTEXT.md`'s "Not in this phase" list explicitly excludes any draft-schema change. **Decision:** "the existing stale/orphaned acknowledgement gate that disables the primary action until checked" (CONTEXT's own words) is realized by `DriftExportAcknowledgement.vue`, reused **completely unchanged** — same checkbox copy ("I understand this export remains pinned to the original commits and records the selector drift."), same disabled-until-checked primary button, same `stale` re-acknowledgement path. Individual comment-anchor staleness/orphan status stays informational-only, exactly as today, via `ExportReadinessSummary.vue`'s existing `attentionCount` warning notice (unchanged copy: `"{n} comments need reviewer attention"`) and the unrelated, already-existing `StaleAnchorNotice.vue` in the warning strip (Phase 20, untouched) — neither blocks export.

**Agent-attached "Finish review" replaces "Export review" (locked, CONTEXT — PANEL-05):** `ExportSection.vue` absorbs the attached-completion state machine that today lives as a separate block in `BottomPanel.vue` (lines 187–321), moved verbatim (identical markup/copy for every `finishing`/`completed`/`waitingDisconnected`/`terminalFailure`/`retryableFailure`-with-four-subkinds state, and the unsaved-text/inline-composer/pending/conflict blocking notices) into its own template, gated on new props `attachedLifecycle?`, `attachedReady?`, `attachedFailure?`, `unsavedInlineComposerFile?` (same shapes `BottomPanel.vue` already receives) and new emits `finishReview: []`, `reloadAttached: []`.

Dispatch order inside `ExportSection.vue`, highest priority first:
1. `attached && attachedLifecycle !== undefined && attachedLifecycle !== 'waiting'` → render the moved-verbatim finishing/completed/disconnected/terminal/retryable blocks (unchanged copy, unchanged focus-on-transition `watch`).
2. `exportState.phase === 'conflict'|'failed'|'pending'|'unavailable'` → unchanged today's blocks (apply identically whether attached or not — these are export-mechanism states, not Finish-review states).
3. `exportState.phase === 'drift'` → `DriftExportAcknowledgement.vue`, unchanged, applies whether attached or not (same gate for both actions, per CONTEXT).
4. Otherwise (ready/exported, `attachedLifecycle === 'waiting'` if attached) → readiness checklist, then:
   - **Not attached:** today's unchanged `"Export review"` / `"Export review again"` primary button, `emit('export')`.
   - **Attached:** a single primary button reading **`"Finish review"`**, `:disabled="attachedReady !== true"`, `@click="emit('finishReview')"` — this is the literal replacement CONTEXT locks ("'Finish review' replaces 'Export review' as the Export tab's primary action"). The existing `attachedFinishReady` computed (today independent of export readiness) gains one more AND-condition — `exportState.phase !== 'drift'` — so Finish review additionally stays blocked while an unacknowledged drift observation exists, satisfying "behind the same checklist and drift acknowledgement" without any change to the Finish API payload (`FinishReviewResult`/`finishReview` mutation stay byte-for-byte unchanged — "delivered canonical result unchanged", CONTEXT). The moved-verbatim unsaved-text/inline-composer/pending/conflict notices (point 1's siblings, shown *before* this button when `attachedLifecycle === 'waiting'`) block it exactly as they block today's separate Finish button.

The standalone `attached-completion` section (`BottomPanel.vue:187–321`) is deleted in full; its markup/copy/watchers move into `ExportSection.vue` verbatim as described above. `BottomPanel.vue` no longer receives `attachedLifecycle`/`attachedReady`/`attachedFailure`/`unsavedInlineComposerFile`/`isExactPatch` directly — those become `ExportTab.vue`→`ExportSection.vue` props instead.

**Receipt & "Copy agent prompt" (PANEL-04, locked copy verbatim, CONTEXT):** `ExportReceipt.vue`'s existing `v-if="!previous"` actions row gains one new button, first in the row (before the existing "Copy all receipt details"/"Reveal export directory"):

```ts

  try {
    await navigator.clipboard.writeText(
      `Apply the review in \`${receipt.files[0].path}\` (human-readable: \`review.md\`). ` +
      'Address every open comment; leave resolved ones as context.',
    );
    copyMessage.value = 'Copied agent prompt.';
  } catch {
    copyMessage.value = 'Could not copy. Select the value and copy it manually.';
  }
}
```

`receipt.files[0].path` is the real, already-published review.json path (e.g. `.loopnote/exports/<timestamp>/review.json`), so the `<timestamp>` placeholder in CONTEXT's locked phrasing is satisfied with real data, repo-relative, clipboard-only — nothing sent anywhere, matching CONTEXT verbatim.
