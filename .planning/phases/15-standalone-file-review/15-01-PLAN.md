<objective>
Build the standalone-argument resolver that turns `cumpa <path|glob>...` raw CLI arguments into a validated, deduplicated, repository-relative file list — the sole FILE-01/FILE-02/FILE-04 enforcement point for this phase. Git's own pathspec engine (via `git ls-files`) is the actual traversal/absolute-outside defense; this module orchestrates per-argument calls so each argument's outcome (matched, ignored, not found, outside repository) is individually attributable, and reuses the codebase's existing per-segment `lstat` symlink discipline (via `buildUntrackedChangedFile`/`classifyWorktreeSideAvailability`, already implemented in `src/git/worktree-inventory.ts`) rather than adding a third copy of that logic.

Purpose: every later plan (snapshot capture, CLI launch, e2e tests) calls into this module as the single source of truth for "which files does this argument list mean, and is any of it unsafe or unmatched."
Output: `src/git/standalone-resolution.ts` with `resolveStandaloneArguments`, `classifyStandaloneGitState`, `createStandaloneChangedFileInventory`; one new `export` keyword on `buildUntrackedChangedFile` in `src/git/worktree-inventory.ts`; `tests/git/standalone-resolution.test.ts` exercising all of it against real Git fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| CLI argv → `resolveStandaloneArguments` | User-supplied (or shell-already-expanded) path/glob strings cross into Git pathspec resolution; untrusted relative to the repository boundary |
| Resolved paths → content read (later plans) | A path resolved at one instant may not describe the same filesystem object at read time (TOCTOU) |
| Resolved path count → snapshot/session memory | An unbounded directory/glob argument could expand to an excessive file count |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-15-01 | Information Disclosure / Elevation of Privilege | `resolveOneArgument` (`../`, absolute-outside, embedded `../../` traversal) | mitigate | Never pre-sanitize the argument string in JS; run `git ls-files` with `cwd` pinned to the Git-discovered repository root and catch the fatal exit-128 "outside repository" rejection Git itself performs lexically against the root — empirically verified in RESEARCH.md against real Git 2.54 |
| T-15-02 | Information Disclosure | Symlink escape — an argument names a symlink, or a path segment inside a resolved directory is a symlink | mitigate | Never call `fs.realpath`/follow a symlink; reuse `buildUntrackedChangedFile`'s existing per-segment `lstat` walk (`lstatWorktreeLeaf`, `src/git/worktree-inventory.ts:137-178`) which classifies a symlink leaf as `unsupported`/`symlink` and never traverses a symlinked directory for untracked discovery (confirmed empirically: `git ls-files --others --exclude-standard -- 'escape-link/*'` returns empty) |
| T-15-03 | Denial of Service | Unbounded directory/glob argument resolving to an excessive file count | mitigate | Enforce `MAX_RAW_STANDALONE_ARGUMENTS` (256, mirrors `MAX_PATHSPEC_COUNT`) before any Git call, and `MAX_RESOLVED_STANDALONE_FILES` (10,000, mirrors `MAX_SNAPSHOT_FILES`) after resolution and dedup, both producing a clear pre-launch error |
| T-15-04 | Tampering | TOCTOU between this module's resolution and the later snapshot byte capture | accept (here) / mitigate (downstream) | This module only resolves paths; it never reads file bytes. Byte capture happens in Plan 15-03's `captureWorktreeManifest` integration, which already performs Phase 14's torn-capture retry and re-runs the per-segment `lstat` guard at read time — out of this plan's scope by design, tracked as this plan's boundary, not a gap |
| T-15-05 | Information Disclosure | Defense-in-depth: a resolved path somehow contains a `.git`/`.cumpa` segment despite Git's own checkout already excluding `.git` | mitigate | Explicit segment check on every resolved path, modeled on `exactPath()`'s rejection style (`src/git/exact-patch.ts:122-131`), covered by an injected-runner test since real Git never produces this output |
</threat_model>
