## Component Composition (Claude's Discretion in CONTEXT, recorded here)

New components, both under `src/web/components/workbench/`:

- **`IdentityPill.vue`** — the title-bar trigger button. Props: `session: SessionResponse`, `selectorDriftStatus?: SelectorDriftResponse`, `patchDrifted: boolean`, `worktreeChanged: boolean`, `refreshBusy: boolean`. Emits `toggle-popover` (or owns its own `popoverOpen` ref internally — see below). Computes the identity view-model (next section) via an internal `computed`; does **not** receive a pre-built view-model prop, so `App.vue` stays a thin prop-passer exactly like it already is for `TitleBar.vue`/`StatusBar.vue` (no new `App.vue` computed beyond the two new counts and the normalized `attachedLifecycle` reuse described under Status Bar).
- **`IdentityPopover.vue`** — the disclosure panel. Props: `session: SessionResponse`, `selectorDriftStatus?`, `patchDrifted`, `worktreeChanged`, `refreshBusy`, `canRefresh: boolean`. Emits `close`, `refresh`.
- `IdentityPill.vue` owns the `popoverOpen` ref and mounts `<IdentityPopover v-if="popoverOpen" ...>` as a sibling of its own `<button>` inside a shared positioning host (see Popover Anchoring). This keeps `TitleBar.vue` a pure layout host exactly as Phase 20 left it (brand left, `IdentityPill` center, icon-toggle group right) — `TitleBar.vue` only gains one new child component and loses the `.session-header__comparison`/`.header-facts`/refresh-button markup it previously owned directly. `TitleBar.vue`'s unrelated right-group icon buttons (`sidebar`, `panel`) and its `.attached-fact` agent-status span are **unchanged** — Phase 22 does not touch the agent-lifecycle banner, only the comparison-identity block.
- View-model: a single internal `computed` inside `IdentityPill.vue` (reused by `IdentityPopover.vue` via its own equivalent computed over the same props — no shared composable is required since both components receive the same four props and the logic is short; duplicating ~15 lines of pure derivation across two files is preferable to a new `composables/` file for this phase's scope).

## Identity View-Model (shared derivation, both components)

A discriminated `kind` drives every other field:

```ts
type IdentityKind = 'branch' | 'worktree' | 'range' | 'exact-patch' | 'staged' | 'unstaged' | 'working-tree' | 'standalone';
```

Derivation (reuses existing `App.vue`/`TitleBar.vue` computeds verbatim — no new session-shape branching invented):

| `kind` | Condition |
|---|---|
| `exact-patch` | `'patch' in session` |
| `range` | `'base' in session && session.range?.kind === 'revisions'` |
| `worktree` | `'base' in session && !range && (session.base.worktree !== undefined \|\| session.head.worktree !== undefined)` |
| `branch` | `'base' in session && !range && !worktree` |
| `standalone` | `'uncommitted' in session && session.uncommitted.sourceKind === 'standalone'` |
| `staged` / `unstaged` / `working-tree` | `'uncommitted' in session`, keyed off `session.uncommitted.sourceKind` (`staged`→`staged`, `unstaged`→`unstaged`, `worktree`→`working-tree`) |

`driftKind: 'selector' | 'patch' | 'worktree' | undefined` — mutually exclusive by session kind (server only populates `selectorDriftStatus` for non-exact-patch sessions and only `worktreeChanged` polls for `isUncommittedSession`, so at most one is ever true for a given live session):

```
driftKind = patchDrifted ? 'patch'
  : (selectorDriftStatus?.base.kind !== 'unchanged' || selectorDriftStatus?.head.kind !== 'unchanged') ? 'selector'
  : worktreeChanged ? 'worktree'
  : undefined
```

(Reuses the exact condition `App.vue` already gates its warning-stack `v-if` on today — see `App.vue:1358` — just restructured into one priority-ordered value instead of three independent booleans.)

`canRefresh = isUncommittedSession` (the `App.vue`-level computed, which **includes** standalone — not `TitleBar.vue`'s internal `isUncommitted` local, which excludes standalone for its own template branching). True for staged/unstaged/working-tree/standalone; false for branch/worktree/range/exact-patch.

## Truncation Rule (IDENT overflow-regression guard)

Phase 20's UI-REVIEW blocker: `.attached-fact` had no `overflow:hidden`/`text-overflow:ellipsis` guard and collided with the editor-title row. `styles.css` has since been patched with the canonical guard (`.attached-fact`, `styles.css:1911-1919`: `min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap;`) and `.session-header__selector` already carries the same three properties (`styles.css:310-313`). **Every** text-bearing node inside `IdentityPill.vue` MUST carry this exact four-property block, and every flex ancestor up to `.titlebar__center` (unchanged, already `min-width:0` per Phase 20) MUST also be `min-width:0` so the ellipsis can take effect — this is the specific root cause class of bug being guarded against here, not a restyle.

Defense in depth, two layers:

1. **JS middle-truncation** (primary — this is *why* CONTEXT calls for "middle-truncate", not CSS end-ellipsis: two branches sharing a long common prefix like `feature/` or `claude/` would otherwise render visually identical under end-truncation). A `truncateMiddle(text: string, max = 28): string` helper (new file `src/web/domain/truncate-middle.ts`, or inline in the view-model module — implementer's choice, not a UI contract item): if `text.length <= max`, return unchanged; else `` `${text.slice(0, Math.ceil((max - 1) / 2))}…${text.slice(-Math.floor((max - 1) / 2))}` ``. `max = 28` is chosen against `.titlebar__center{max-width:56%}` (unchanged Phase 20 rule) at the SHELL-06 viewport floor of 1050px (588px available, shared by both endpoint groups, arrow, chevron, lead icon, and inter-element gaps) — 28 mono chars at `--font-size-chrome` (13px) ≈ 210px per ref name, leaving headroom for the rest of the row.
2. **CSS ellipsis backstop** on every `.identity-pill__ref`/`.identity-pill__label`/`.identity-pill__sha`/`.identity-pill__suffix` span (`min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap;`), so a JS truncation edge case still can't blow the 32px row.
3. `.identity-pill { white-space: nowrap; overflow: hidden; }` on the pill button itself — the row never wraps to two lines.

**SHAs are never truncated** — short SHAs are always exactly the existing project-wide 7-char `.slice(0, 7)` form (same as `TitleBar.vue`/`StatusBar.vue` today), never further shortened or middle-truncated; they're fixed-width and already short.

**Accessible name carries the untruncated text.** `IdentityPill.vue`'s `<button>` gets an `aria-label` built from the *full, untruncated* label/oid strings in the view-model (never the JS-truncated display strings), via a `pillAccessibleName` computed. Exact templates per `kind` (↔ matches the Pill Content table below, minus truncation):

| `kind` | `aria-label` template |
|---|---|
| `branch` / `worktree` | `` `Comparison: Base ${baseLabel} at ${baseSha}, Head ${headLabel} at ${headSha}. Opens comparison details.` `` |
| `range` | `` `Comparison: pinned revisions ${baseLabel} to ${headLabel}. Opens comparison details.` `` |
| `exact-patch` | `'Comparison: Repository object to Implemented content, frozen patch. Opens comparison details.'` (literal — exact-patch has no ref/SHA to interpolate, see Data-grounding deviation below) |
| `staged` | `` `Comparison: HEAD at ${baseSha} to Staged changes. Opens comparison details.` `` |
| `unstaged` | `'Comparison: Index to Unstaged changes. Opens comparison details.'` |
| `working-tree` | `` `Comparison: HEAD at ${baseSha} to Working tree. Opens comparison details.` `` |
| `standalone` | `` `Comparison: Standalone review, ${fileCount} files. Opens comparison details.` `` |

When `driftKind !== undefined`, append `' Source changed since this review was pinned.'` to the label. When `refreshBusy`, append `' Capturing current changes.'` instead (mutually exclusive — refresh only runs on sessions that `canRefresh`, which can't simultaneously be mid-selector-drift/patch-drift since those only fire for non-refreshable kinds).

**Data-grounding deviations from the fictional sketch data** (documented per the "exhaust existing sources before inventing" rule):

- **Exact patch has no base ref/SHA in the real schema.** `ExactPatchSessionResponseSchema` is `{ patch: { digest, reviewKey, validationTarget: {kind:'repository'|'worktree'}, changedFileCount }, ... }` — there is no git ref/SHA for the "before" side at all (exact patches aren't resolved against a named commit). - **No snapshot "capture time" field exists anywhere in `api.ts`.** The sketch's `Snapshot (+ capture time)` popover row has no real counterpart (`reviewKey`/`digest` are content-addressed hashes with no associated timestamp). **Decision:** the popover's Snapshot row shows the digest only, no time — see Popover Anatomy below.
- **No "Produced by" / agent-name field exists anywhere in `api.ts`** (`AttachedSessionMarkerSchema` is `{ kind: 'agent-review' }`, no tool identity). The sketch's fictional `patchFrom:'claude-code'` has no real counterpart. **Decision:** the popover substitutes a **"Validated against"** row showing `validationTarget.kind` (`'Repository'` or `'Worktree'`) — real, derivable data serving the same informational purpose (what the patch was checked against), rather than fabricating a producer identity. See Popover Anatomy below.

## IdentityPopover.vue — full anatomy

**Anchoring** (Claude's Discretion — "no new runtime dependency"): pure CSS, no JS measurement. `.identity-pill-host` is `position: relative;` (the wrapping `<div>` from the Pill Content skeleton). `.identity-popover` is `position: absolute; top: 100%; left: 50%; transform: translateX(-50%); margin-top: var(--space-1);` — since `.identity-pill` is itself horizontally centered inside `.titlebar__center` (unchanged Phase 20 `position:absolute;left:50%;transform:translateX(-50%)` rule), anchoring the popover relative to its own host wrapper (not the title bar) is simpler and more robust than the sketch's imperative `getBoundingClientRect()` approach — it degrades correctly if the title bar's center block shifts. Width: `width: min(440px, calc(100vw - var(--space-4)));` (reuses the exact pattern already established by `--dialog-width: min(560px, calc(100% - 24px))` — a literal geometry value, not a new token, same class of exemption as Phase 20's sash). Visual chrome: `background: var(--surface-raised); border: 1px solid var(--border-overlay); border-radius: var(--radius-overlay); box-shadow: var(--shadow-overlay);` — identical to `.modal-dialog`'s own surface treatment (`styles.css:730-741`), reused for visual consistency between the app's two overlay surfaces, no new hex.

**Role & labeling**: `role="dialog"` **without** `aria-modal="true"` (this is a non-modal disclosure popover, not a true modal — CONTEXT: "anchored below the pill" implies content remains visible/interactive behind it, unlike `ModalDialog`'s backdrop-blocking semantics). `:aria-labelledby="headingId"` pointing at the header `<div>`. Trigger button gets `aria-haspopup="dialog"` + `:aria-expanded="popoverOpen"` — reuses the exact existing pattern `StatusBar.vue`'s Support button already uses (`:aria-expanded="supportOpen"`, `StatusBar.vue:60`).
