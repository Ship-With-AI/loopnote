<objective>
Wire the single-pane routing decision (13-02) and the single-pane Monaco adapter (13-01) through the review workspace: `App.vue` computes which files are single-pane and which side anchors their comments, `DiffWorkspace.vue` renders a new single-pane template branch that constructs the right adapter and shows one full-width pane (or an empty-file notice for 0-byte files), and `ReviewToolbar.vue` removes the "Change navigation" group — which has no meaning without hunks — when the active file is single-pane.

Purpose: this is the plan that actually makes PANE-01 and PANE-02 observable to a reviewer. `DiffWorkspace.vue` today has zero `status` awareness and unconditionally renders side-by-side for every reviewable file (confirmed in RESEARCH.md's Pitfall 3 — the layout-routing responsibility described in CONTEXT.md does not exist yet); this plan adds it.

Output: a reviewer opening an added, deleted, or type-changed text file sees one full-width pane with correct side identity, can comment on it, and sees no diff-only controls; modified/renamed/copied files are pixel-for-pixel unchanged.
</objective>
