<objective>
Fix the pre-existing Phase 13 regression recorded in `.planning/phases/17-agent-protocol-extension-marketplace-skill/deferred-items.md`
and `17-VERIFICATION.md`'s Human Verification #1: `tests/helpers/open-runtime-session.ts`'s
`openRuntimeSession` helper asserts `.monaco-diff-editor` immediately after `page.goto`, before
any file is explicitly selected. Since Phase 13, the custody-gated fixtures' default-selected file
(`src/added.ts`, alphabetically first, status `added`) renders as a single-pane Monaco editor, not
a diff editor — so `.monaco-diff-editor` never appears and the assertion times out on every test
that calls `openRuntimeSession`/`openAcceptanceRuntimeSession` (10/16 tests across
`tests/e2e/agent-ready-export.spec.ts` and `tests/e2e/package-assets.spec.ts`).

This is a **stale test**, not a product bug: Phase 13's `13-CONTEXT.md` D-05 deliberately routes
`added`/`deleted`/`type-changed` files to a single-pane layout; `src/added.ts` is working as
designed. Quick task `261031-au0` already carries the identical, established fix for the same
helper pattern in `tests/e2e/complete-review-draft.spec.ts` and `tests/e2e/anchored-review.spec.ts`
(`.diff-workspace__editor` instead of `.monaco-diff-editor`) — this plan applies the same fix to
the shared `openRuntimeSession` helper, plus the one duplicate inline assertion in
`package-assets.spec.ts` that races it.

A repo-wide grep confirms no other `.monaco-diff-editor` locator shares this bug: every other use
runs after a test explicitly selects `src/changed.ts` (status `modified`) or another known
side-by-side file (e.g. a renamed file in `pinned-session.spec.ts`, `alpha.ts` in
`responsive-session.spec.ts`), or deliberately asserts `toHaveCount(0)`/`toHaveCount(1)` to prove
single-pane vs side-by-side layout by design (`anchored-review.spec.ts`,
`rendered-markdown-preview.spec.ts`). None of those change.
</objective>

<action>
In `openRuntimeSession` (`tests/helpers/open-runtime-session.ts:26`), change the post-navigation
assertion from `await expect(page.locator('.monaco-diff-editor')).toBeVisible();` to
`await expect(page.locator('.diff-workspace__editor')).toBeVisible();`.

In `tests/e2e/package-assets.spec.ts:203`, change the identical duplicate assertion (which runs
immediately after `const opening = openRuntimeSession(page, url);`, before `opening` is awaited,
against the same `branch-to-worktree` fixture whose alphabetically-first file is `src/added.ts`)
from `.monaco-diff-editor` to `.diff-workspace__editor` for the same reason.

`.diff-workspace__editor` is the Monaco host `<div>` rendered by **both** branches of
`DiffWorkspace.vue` (single-pane and side-by-side), so the assertion now proves the editor mounted
and the review loaded, regardless of which layout Phase 13 routes the initially-selected file to —
matching each call site's actual intent (confirm the review page finished loading) rather than
hard-coding a diff-specific element that is only present for some file statuses.
</action>
