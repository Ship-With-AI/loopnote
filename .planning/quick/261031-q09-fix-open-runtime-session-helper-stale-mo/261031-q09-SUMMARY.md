# Quick Task 261031-q09: Fix open-runtime-session helper stale .monaco-diff-editor assertion — Summary

**`tests/helpers/open-runtime-session.ts`'s shared `openRuntimeSession` helper asserted `.monaco-diff-editor` immediately after `page.goto`, before any file was explicitly selected — a pre-existing Phase 13 single-pane-rendering regression (recorded in `17-VERIFICATION.md`'s Human Verification #1 and `deferred-items.md`) that broke 10 of 16 tests across `tests/e2e/agent-ready-export.spec.ts` and `tests/e2e/package-assets.spec.ts`, since both specs' custody-gated fixtures auto-select `src/added.ts` (status `added`, correctly single-pane per 13-CONTEXT.md D-05) on load.**

## Root cause (confirmed per failing test)

Before any fix, the baseline run of `npm run test:runtime-artifact` showed exactly **10 failed / 6 passed** (16 total). All 10 failures shared the identical stack trace, terminating at either:

- `tests/helpers/open-runtime-session.ts:26` — `await expect(page.locator('.monaco-diff-editor')).toBeVisible();` inside `openRuntimeSession`, called (directly or via each spec's `openAcceptanceRuntimeSession`/`openRuntimeSession` wrapper) immediately after `page.goto`.
- `tests/e2e/package-assets.spec.ts:203` — an inline duplicate of the same assertion, racing the same unresolved `openRuntimeSession(page, url)` call against the same fixture.

Every fixture that exercises these two specs (`createDirtyGitFixture('branch-to-worktree', N)`) includes `src/added.ts`, `src/changed.ts`, and `src/deleted.ts`; alphabetically, `src/added.ts` sorts first and is auto-selected on load. Per `13-CONTEXT.md` D-05, `added`/`deleted`/`type-changed` files render through `DiffWorkspace.vue`'s single-pane branch (`.diff-workspace__editor` only), never through `.monaco-diff-editor` — so the assertion timed out on **every** test that touched a browser page, regardless of what the test itself was actually trying to prove. This is a **stale test assumption, not a product bug**: the 6 tests that originally passed were exactly the 6 negative-validation scenarios that reject the request before ever launching a browser.

This is the identical bug class already fixed once by quick task `261031-au0` in `tests/e2e/complete-review-draft.spec.ts` and already present correctly in `tests/e2e/anchored-review.spec.ts:154`. Quick task `261031-au0` did not touch `tests/helpers/open-runtime-session.ts` because that helper backs the 4 *custody-gated* specs (`playwright.runtime-artifact.config.ts`), which run on a separate, packed-tarball Playwright config and were out of that task's scope.

## Fix

**1. `tests/helpers/open-runtime-session.ts:26`** (the shared helper, imported by all 4 custody-gated specs: `agent-ready-export.spec.ts`, `package-assets.spec.ts`, `marketplace-review.spec.ts`, `public-support-states.spec.ts`):

```diff
-  await expect(page.locator('.monaco-diff-editor')).toBeVisible();
+  await expect(page.locator('.diff-workspace__editor')).toBeVisible();
```

**2. `tests/e2e/package-assets.spec.ts:203`** (the inline duplicate that races the same page load):

```diff
-    await expect(page.locator('.monaco-diff-editor')).toBeVisible();
+    await expect(page.locator('.diff-workspace__editor')).toBeVisible();
```

`.diff-workspace__editor` is the Monaco host `<div>` rendered by **both** branches of `DiffWorkspace.vue` (single-pane and side-by-side), so each assertion now proves the editor mounted and the review loaded, regardless of which layout Phase 13 routes the initially-selected file to.

**3. `tests/e2e/agent-ready-export.spec.ts:916`** (discovered only once fix #1 let this test run past its first assertion for the first time):

```diff
-    await addSinglePaneComment(page, /staged-20\.txt/, 'head', 'staged 20', 1, 'Uncommitted worktree feedback.');
+    await addSinglePaneComment(page, /\/staged-20\.txt/, 'head', 'staged 20', 1, 'Uncommitted worktree feedback.');
```

The fixture (`createDirtyGitFixture('branch-to-worktree', 20)`) writes both `dirty/staged-20.txt` and `dirty/unstaged-20.txt`. The original unanchored regex matched both tree rows (`unstaged-20.txt` contains `staged-20.txt` as a substring), producing a Playwright strict-mode violation on `getByRole('treeitem', …).click()`. Anchoring on the preceding path separator disambiguates the two. This is a second, independent pre-existing bug written in the same Plan 17-04 that added this test — it was never exercised before because every positive scenario died at the `.monaco-diff-editor` assertion first. Fixed because it lives inside one of this task's two named target spec files and directly blocks the stated 16/16 acceptance criterion.

This is pre-existing harness design, not a regression; it does not block the full-file run (which did register all scenarios except when the 1157 race dropped it).

## How the custody-gated specs are run

`playwright.config.ts` uses `testIgnore: custodyGatedSpecs` (the 4 specs listed in `playwright.runtime-artifact.config.ts`: `package-assets.spec.ts`, `agent-ready-export.spec.ts`, `public-support-states.spec.ts`, `marketplace-review.spec.ts`), so they're excluded from the default `npm run test:package`/`test:browser` runs. They require a locally packed, hash-verified runtime tarball supplied via 4 environment variables (`CUMPA_RUNTIME_CUSTODY_DIR`, `CUMPA_RUNTIME_ARCHIVE_BASENAME`, `CUMPA_RUNTIME_ARCHIVE_SHA256`, `CUMPA_RUNTIME_EVIDENCE`) rather than a fresh dev-server build, per `docs/distribution-operations.md`'s "fair pair" isolation design (`runtime-artifact.ts:149-154`). Recipe used here, matching `17-04-PLAN.md`'s own documented sequence:

```bash
npm run build:web
CUMPA_RELEASE_SUPPORT_SERVICE_URL="https://<20-lowercase-alnum>.supabase.co" \
  npm run pack:runtime-artifact -- --purpose development-check \
  --custody-dir <dir> --evidence <evidence.json>
# then export the 4 CUMPA_RUNTIME_* vars read from evidence.json, and:
npm run test:runtime-artifact   # == playwright test --config playwright.runtime-artifact.config.ts tests/e2e/agent-ready-export.spec.ts tests/e2e/package-assets.spec.ts
```
