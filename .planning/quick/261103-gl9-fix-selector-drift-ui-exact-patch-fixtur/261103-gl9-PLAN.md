<objective>
Fix the two long-standing Playwright failures in
`tests/integration/selector-drift-ui.spec.ts` at `:423` ("exact patch resumed
drafts announce frozen provenance without pinned wording") and `:441` ("exact
patch retry stays snapshot-only and terminal loss focuses one source-correct
heading"). Both throw a ZodError ("expected object, received undefined") from
the spec's own `exactPatchSession()` fixture helper when called with
`withTextFile = true`.

Root cause confirmed by reproduction: `SessionFileSchema`
(`src/contracts/api.ts:320-334`) requires a `oldMode: GitModeSchema` field on
every session file entry. `exactPatchSession(true)`
(`tests/integration/selector-drift-ui.spec.ts:54-74`) builds its single file
object with `fileId`, `status`, `newPath`, `additions`, `deletions`,
`availability` — but omits `oldMode`. `SessionResponseSchema.parse` therefore
fails Zod validation inside the test's own fixture, before the page ever
loads. This is a **stale test fixture**, not a product bug: every real
producer of `SessionFileSchema`-shaped data in `src/` (worktree inventory,
patch snapshot, comparison contracts) always populates `oldMode` from the
actual git diff, and the sibling integration fixture
`tests/integration/anchored-workspace.spec.ts:74-87` already uses the correct
pattern (`oldMode: '100644'` alongside `status: { kind: 'modified' }`,
`newPath`, `additions`, `deletions`). The third exact-patch test in this same
file (`:389`, "exact patch drift is announced while Review notes makes the
shell inert") calls `exactPatchSession()` with no args — `withTextFile`
defaults to `false`, so `files: []` and the missing-`oldMode` branch is never
exercised there, which is why only these two tests fail.

Fix: add `oldMode: '100644'` to the file entry inside `exactPatchSession`'s
`withTextFile` branch, matching the established convention used everywhere
else in the test suite for a plain-text modified file.
</objective>
