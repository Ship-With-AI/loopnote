<objective>
Fix the pre-existing Phase 13 regression recorded in `.planning/STATE.md`'s
Blockers/Concerns: `tests/e2e/complete-review-draft.spec.ts` fails 8/8 against the
packaged build because its `openGeneratedReview` helper asserts
`.monaco-diff-editor` immediately after page load, before any file is explicitly
selected. Since Phase 13, the fixture's default-selected file
(`src/added.ts`, alphabetically first, status `added`) renders as a single-pane
Monaco editor (`.diff-workspace--single-pane`), not a diff editor — so
`.monaco-diff-editor` never appears on initial load and the assertion times out
on every test in the file.

This is a **stale test**, not a product bug: Phase 13's `13-CONTEXT.md` D-05
deliberately routes `added`/`deleted`/`type-changed` files to a single-pane
layout; `src/added.ts` is working as designed. `tests/e2e/anchored-review.spec.ts`
already carries the correct fix for its own copy of this same helper
(`.diff-workspace__editor` instead of `.monaco-diff-editor`, confirmed at
`anchored-review.spec.ts:134`) — this plan applies the identical, already-
established fix to `complete-review-draft.spec.ts`'s copy.

No other `.monaco-diff-editor` locator in the file changes: `activateMonacoLine`,
`activateTopMonacoLine`, and the two direct assertions at lines 830/860 all run
only after the test explicitly clicks the `src/changed.ts` tree row, and
`changed.ts` has status `modified`, which Phase 13 D-05 keeps side-by-side —
`.monaco-diff-editor` is still the correct, present element there.
</objective>
