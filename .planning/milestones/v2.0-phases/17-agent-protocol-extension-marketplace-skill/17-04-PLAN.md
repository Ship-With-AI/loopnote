## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-11 | Tampering | `request.files.paths`/`request.uncommitted.pathspecs` crafted to look like a Git option (e.g. `--upload-pack=...`) | mitigate | Every reused Git invocation (`resolveStandaloneArguments`, `createWorktreeChangedFileInventory`, `createStandaloneChangedFileInventory`) already passes pathspecs after a literal `--` separator and uses `spawn()` with `shell: false` argument arrays (project-wide constraint, unchanged by this plan) — this plan introduces no new Git invocation that omits the separator or interpolates into a shell string. |
| T-17-12 | Information Disclosure | Path-outside-repository / symlink-escape detection in `files` mode | mitigate | Delegated entirely to Git's own exit-128 "outside repository"/"beyond symbolic link" authority via `resolveStandaloneArguments`/`resolveOneArgument`, now surfaced as a typed `StandaloneResolutionError('path-outside-repository', ...)` instead of a second, possibly-divergent path-traversal checker — Git remains the single source of truth for path semantics (ASVS V4 Access Control). |
| T-17-13 | Denial of Service | Oversized agent-triggered uncommitted/files requests, or pathological pathspec counts | mitigate | `MAX_AGENT_REQUEST_BYTES` (1 MiB, enforced before `JSON.parse` in `readAgentReviewRequest`, Plan 17-01, unchanged) and `MAX_PATHSPEC_COUNT`/`.min(1)` (Plan 17-01's Zod layer) both reject oversized input before this plan's dispatch code runs any Git call — negative scenario 7 in Task 1 proves the byte cap still applies to the two new modes. |
| T-17-14 | Spoofing | `AgentRequestError` thrown from `mapStandaloneResolutionError`/`mapGitPathspecError` reaching the existing top-level catch | mitigate | Both adapters only ever throw `AgentRequestError` (never let a bare `Error`/`StandaloneResolutionError`/`GitRunnerError` propagate past this plan's dispatch code) — the pre-existing `catch` block's `error instanceof AgentRequestError` check, unchanged, is the only path that sets exit status 1 with the agent-facing message; any other error type still rethrows to the generic unhandled-error path, unchanged. |
| T-17-15 | Denial of Service | Repeated agent-triggered attached-session launches (`mode:'uncommitted'`/`'files'` invoked many times in a loop) | accept | Out of this phase's scope to newly mitigate — identical resource profile to the already-shipped interactive `--staged`/`--worktree`/standalone CLI launches (one process, one loopback server, exits after Finish or signal); no new amplification surface is introduced. |
</threat_model>
