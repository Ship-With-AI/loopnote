<objective>
Extract the single-pane routing decision (which `ChangedFileStatusKind` values render single-pane, and which `DiffSide` anchors their comments, gated by reviewability) and the type-changed "was `<kind>`" git-mode-to-label derivation into one small, independently testable pure-function module, `src/web/model/single-pane-layout.ts`. Add the missing `oldMode` field to the client-facing `SessionFileSchema` and its two server construction sites, since D-06's derivation needs the file's old git mode and today's `/api/session` response does not carry it (only the separate, differently-shaped `FileMetadataResponseSchema` does).

Purpose: D-05/D-08's routing rule and D-06's label derivation are both small, pure, fully-specified business logic (`expect(fn(input)).toBe(output)` testable) that several Vue components (App.vue, ActiveFileToolbar.vue, StatusBadge.vue via FileRow.vue) all need to apply identically. Centralizing them here means every consumer reads the same decision instead of re-deriving it, and the decision is proven correct once, by unit test, independent of any Vue rendering.

Output: two exported pure functions consumed by 13-03 and 13-04, and a corrected `SessionFile` contract that actually carries the data D-06 depends on.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-02-01 | Tampering | `SessionFileSchema.oldMode` | accept | `oldMode` is produced server-side from git's own mode reporting and validated by `GitModeSchema` (`z.string().regex(/^[0-7]{6}$/)`, `comparison.ts:92`) before it ever reaches this schema. Task 2's acceptance criteria re-confirm the response still excludes `repositoryRoot`, blob OIDs, and the session token. |
