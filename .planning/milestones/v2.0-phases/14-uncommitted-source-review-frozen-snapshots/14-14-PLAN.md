<objective>
Close two verification gaps in Phase 14's already-shipped client shell: (1) `performRefresh()` in `App.vue` never resyncs `workspaceComments` after a successful Refresh, so `StaleAnchorNotice`/per-comment badges stay stale until an unrelated full page reload (SNAP-05's client-side half); (2) `FileRow.vue`'s `recentlyChanged` prop and `tree-row__refresh-marker` span, built in 14-11, are never set from `App.vue`'s most-recent-Refresh file-set, so D-15's tree-row "Changed" marker never appears (SNAP-04's companion behavior).

Purpose: make the server's already-correct reclassification and refresh-delta computation (from 14-08) visible to the user in the two places Phase 14's own spec requires it — the per-comment stale/orphaned badges and the tree-row marker — without touching server code, since both gaps are purely client-side wiring.

Output: `App.vue`'s post-refresh comment resync and `recentlyChangedPaths` state; `recentlyChangedPaths` threaded through `ChangedFilesDialog.vue` → `FileTree.vue` → `DirectoryRow.vue` to every `FileRow`; `tests/e2e/uncommitted-review.spec.ts`'s pinned "broken behavior" assertion updated to assert the now-correct behavior.
</objective>
