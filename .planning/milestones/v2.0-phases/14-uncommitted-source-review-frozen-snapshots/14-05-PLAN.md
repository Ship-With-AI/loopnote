<objective>
Build `src/git/worktree-content.ts`: for any diff side that crosses a worktree boundary (Unstaged's worktree side, Working-tree's worktree side for tracked files), reconstruct the full pre/post text by walking `git diff -U1000000`'s own full-context hunk output — never by independently `fs.readFile`-ing the worktree file and comparing it against an `ObjectReader`-read base/index blob. Also export `blobOid` from `src/git/exact-patch.ts` (currently module-private) so this module computes the synthetic Git-compatible digest for non-object-backed sides using the exact same algorithm exact-patch sessions already use.

Purpose: this resolves RESEARCH.md's Required Focus 2 (the CRLF/clean-filter pitfall). `git diff` already applies the repository's `core.autocrlf`/`.gitattributes` normalization consistently when deciding what changed; reading the worktree file directly and diffing it client-side against a differently-normalized object-backed side would show every line as changed even when git itself reports no real edit.

Output: `resolveWorktreeSideContent(repositoryRoot, path, endpoint, scope, objectFormat, runner?): Promise<{ bytes: Buffer; blobOid: string }>` for tracked files' worktree side, reusing `exact-patch.ts`'s exported `blobOid` for the digest and the file's own hunk-walk technique (modeled on, not copied from, `exact-patch.ts`'s `applyText`) for the bytes. Untracked files (no base side to normalize against) are explicitly out of this module's scope — they are read via a plain bounded `fs.readFile`, already covered by 14-04's Task 2.
</objective>
