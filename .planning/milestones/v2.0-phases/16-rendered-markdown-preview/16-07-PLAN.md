<objective>
Extend the durable anchor domain model and its two call-in schemas with an additive, optional `endLine` field — per CONTEXT.md amendment A-01, which supersedes this phase's original research recommendation ("anchor to the block's first line, compute the visible range client-side with zero schema change"). `endLine` presence/absence is itself the version signal: absent means today's single-line anchor, byte-for-byte unchanged; present means an inclusive `[line, endLine]` range whose `selectedText`/`context`/`contextHash` all cover the whole range, so drift verification classifies the entire stored range rather than just its first line. No `version` literal changes, no export schema (`ReviewExportV1`-`V4`) needs editing — the field reaches every version through the existing `DurableAnchorV1Schema` embed.

Purpose: this is the schema-and-domain foundation plans 16-03/16-04 build the rendered-block comment UI against — it is a self-contained, dependency-free unit of work, independently TDD-shaped (RED tests for both the "unchanged when absent" guarantee and the "whole-range" behavior, then GREEN implementation) and must land before any plan that threads `endLine` through the client.

Output: `buildDurableAnchor`/`verifyDurableAnchor` are range-aware; `DurableAnchorV1Schema`/`AddCommentRequestSchema` accept the optional field; all 5 call sites (`routes.ts`'s `addComment` handler, `capabilities.ts`'s four `verifyAnchor` closures) pass it through; a golden byte-for-byte regression test and a pre-phase-16 fixture back-compat test both pass.
</objective>
