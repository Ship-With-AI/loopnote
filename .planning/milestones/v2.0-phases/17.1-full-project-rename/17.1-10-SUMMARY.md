## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] exact-patch.test.ts's first-draft segment-rejection tests didn't actually exercise the segment check**
- **Found during:** Task 1 (RED) — initial test run showed both new tests passing even against the pre-GREEN implementation (false-positive RED for the new-dir case; accidental-pass for the `.cumpa` case)
- **Issue:** A minimal hand-written single-line `diff --git a/.cumpa/... b/.cumpa/...\n` patch (no `index`/oid line) fails during parsing for an unrelated reason — `parsePatch`'s `finish()` rejects any record missing `oldOid`/`newOid` — before the directory-segment check in `exactPath()` is ever meaningfully distinguishing. Both the `.cumpa` and new-dir variants threw `ExactPatchGroundingError` for the same wrong reason, so the new-dir test gave no RED signal for the feature under test.
- **Fix:** Rewrote both tests to generate a real, fully valid "add file" patch via the file's existing `gitPatch()` helper (two real commits, one adding a file under the reserved directory), so the only path from "valid patch, would otherwise ground successfully" to "rejected" is the segment check itself. Also added a missing base commit (`git commit --allow-empty`) so `captureSourceControlSnapshot`'s `.git/index` read has a file to read.
- **Files modified:** `tests/git/exact-patch.test.ts`
- **Verification:** Re-ran the RED suite — the new-dir test now fails pre-GREEN (as expected) and both tests pass post-GREEN.
- **Committed in:** `9c82871` (Task 1/RED commit — the fix landed before the RED commit, since it surfaced during RED authoring itself)
