# Phase 17.1: Full Project Rename - Patterns

**Mapped:** 2026-10-31

This phase modifies existing files in place (rename, not new architecture), so "patterns" here
are the closest existing code shapes each new piece of logic (old-kind rejection, D-06 one-time
copy, D-05 dual-directory exclusion) should imitate, plus the project's module-shape convention for
the one genuinely new file (the rename-map).

## Pattern 1: Old-kind rejection error (D-04 / REN-03)

**Closest analog:** `src/cli/request.ts` already rejects three other malformed-request shapes with
small boolean type-guard functions checked, in order, before falling back to a generic
`'invalid-request'` error:

```ts
// src/cli/request.ts:48-67 (existing pattern to imitate)
function isUnsupportedVersion(value: unknown): boolean {
  return (
    typeof value === 'object' &&
    value !== null &&
    !Array.isArray(value) &&
    'schemaVersion' in value &&
    value.schemaVersion !== 1
  );
}

function isUnknownMode(value: unknown): boolean {
  return (
    typeof value === 'object' &&
    value !== null &&
    !Array.isArray(value) &&
    'mode' in value &&
    typeof value.mode === 'string' &&
    !['revisions', 'patch', 'uncommitted', 'files'].includes(value.mode)
  );
}
```

Wired in at the parse site, checked in priority order before the generic fallback:

```ts
// src/cli/request.ts:130-141
const parsed = AgentReviewRequestSchema.safeParse(value);
if (!parsed.success) {
  throw new AgentRequestError(
    isUnsupportedVersion(value)
      ? 'unsupported-version'
      : isUnknownMode(value)
        ? 'unknown-mode'
        : isBaseWithUnstaged(value)
          ? 'base-with-unstaged'
          : 'invalid-request',
  );
}
```

Error kinds and messages are a flat `as const satisfies Record<...>` map next to the class:

```ts
// src/cli/request.ts:11-36
export type AgentRequestErrorKind =
  | 'empty-request'
  | 'request-too-large'
  | 'invalid-utf8'
  // ... existing kinds
  | 'pathspec-ignored';

const requestErrorMessages = {
  'empty-request': 'Request input is empty. Pipe one cumpa.review-request JSON document.',
  // ...
} as const satisfies Record<AgentRequestErrorKind, string>;
```

**Apply:** add a new kind (e.g. `'legacy-kind'`) to `AgentRequestErrorKind`, a new guard
`isLegacyKind(value)` matching `kind === '<RENAME_MAP>.oldKindPrefix'` (literal old-kind check, one
of the audit's allowed exceptions — see RESEARCH.md §Allowed Exceptions item 2), check it **first**
in the ternary chain (before the generic `isUnknownMode`, since an old-kind request will otherwise
just look like "unknown mode" and get a less specific error), and give it a message naming the new
kind (per the phase success criteria: "fails before launch with a specific error naming the new
kind"). No change to the `AgentReviewRequestSchema` itself is required for rejection — the Zod
schema just needs its literal `kind` changed to the new value (it already fails old requests via
the generic path; this pattern upgrades that failure to a specific, named error).

## Pattern 2: D-06 one-time supporter-state copy (`support-store.ts`)

**Closest analog:** the module's own existing atomic-write + path-resolution helpers — reuse them
rather than writing a second temp-file/rename/fsync implementation.

```ts
// src/server/support-store.ts:56-63 — path resolution to imitate for BOTH old and new paths
export function resolveSupportStatePath(options: ... = {}): string {
  const platform = options.platform ?? process.platform;
  const home = options.home ?? process.env.HOME ?? '';
  const env = options.env ?? process.env;
  if (platform === 'darwin') return join(home, 'Library', 'Application Support', 'Cumpa', 'support.json');
  if (platform === 'win32') return win32.join(env.LOCALAPPDATA ?? env.APPDATA ?? win32.join(home, 'AppData', 'Local'), 'Cumpa', 'support.json');
  return join(env.XDG_STATE_HOME ?? join(home, '.local', 'state'), 'cumpa', 'support.json');
}

// src/server/support-store.ts:89-106 — atomic write to imitate for the copy
const persist = async (next: SupportStateV1): Promise<void> => {
  const bytes = Buffer.from(`${JSON.stringify(SupportStateV1Schema.parse(next))}\n`);
  const temporaryPath = join(directory, `.support.${randomUUID()}.tmp`);
  let handle: SupportFileHandle | undefined;
  let renamed = false;
  try {
    await fileSystem.mkdir(directory, 0o700);
    handle = await fileSystem.open(temporaryPath, constants.O_WRONLY | constants.O_CREAT | constants.O_EXCL | constants.O_NOFOLLOW, 0o600);
    await handle.writeFile(bytes); await handle.sync(); await handle.close(); handle = undefined;
    await fileSystem.rename(temporaryPath, canonicalPath); renamed = true;
    await fileSystem.syncDirectory(directory).catch(...);
  } finally {
    if (handle !== undefined) await handle.close().catch(() => undefined);
    if (!renamed) await fileSystem.unlink(temporaryPath).catch(() => undefined);
  }
};

// src/server/support-store.ts:73-87 — load()/exists() to imitate for detecting "old path has data, new path doesn't"
const load = async (): Promise<SupportStateV1 | undefined> => {
  try {
    const entry = await fileSystem.lstat(canonicalPath);
    if (entry.isSymbolicLink() || !entry.isFile()) return undefined;
    return SupportStateV1Schema.parse(JSON.parse((await fileSystem.readFile(canonicalPath)).toString('utf8')));
  } catch { return undefined; }
};
```

**Apply:** add a second path resolver `resolveLegacySupportStatePath(...)` (same function body as
`resolveSupportStatePath`, but the hardcoded `Cumpa`/`cumpa` segments — these are the D-06-allowed
exception). In `createSupportStore()`'s initialization (before/inside the first `state()` call,
guarded so it runs at most once), if `load()` on the **new** `canonicalPath` returns `undefined`
*and* an `lstat`+`readFile` on the legacy path succeeds and parses as valid
`SupportStateV1Schema`, copy those exact bytes to `canonicalPath` using the same
temp-file → `fileSystem.open` → `writeFile`/`sync`/`close` → `rename` → `syncDirectory` sequence as
`persist()`, but read the legacy file's mode via `fileSystem.lstat`/`stat` first and `open` the temp
file with that mode (not the hardcoded `0o600`) to satisfy "file mode preserved." **Do not** delete
or modify the legacy file — copy only, per D-06 ("do not move or delete the old one").

## Pattern 3: D-05 exclusion of both old and new directories (`inventory.ts`)

**Closest analog:** the existing single-directory byte-prefix matcher.

```ts
// src/git/inventory.ts:70-85 (existing pattern)
const cumpaPath = Buffer.from('.cumpa', 'ascii');
const cumpaPathPrefix = Buffer.from('.cumpa/', 'ascii');

export function isCumpaInternalPath(path: ExactPath | undefined): boolean {
  if (path === undefined) return false;
  const bytes = decodeBase64url(path.bytesBase64url);
  if (bytes.byteLength === cumpaPath.byteLength) {
    return bytes.every((byte, index) => byte === cumpaPath[index]);
  }
  return (
    bytes.byteLength >= cumpaPathPrefix.byteLength &&
    cumpaPathPrefix.every((byte, index) => byte === bytes[index])
  );
}
```

**Apply:** rename the function to the new identifier (AST rename) and generalize the two
`Buffer.from` constants into two **pairs** (new-dir path/prefix from the rename map, legacy
`.cumpa`/`.cumpa/` literal pair kept as-is — the D-05-allowed exception), matching against either
pair. Reuse the exact same byte-comparison shape (`byteLength === X.byteLength` exact match,
`byteLength >= Y.byteLength` prefix match) for both pairs rather than introducing a different
matching strategy — `worktree-inventory.ts` re-exports and calls this function unchanged (import
rename only, via AST tooling).

## Pattern 4: Rename-map module shape

**No existing shared-constants analog in `src/`** — the codebase has no top-level `constants.ts`;
shared small pure modules live under `src/domain/` (e.g. `src/domain/anchor.ts`,
`src/domain/comparison-key.ts`, `src/domain/errors.ts`: one-purpose exported `const`s and pure
functions, zero I/O, zero framework imports). The rename-map module should follow that same shape
— e.g. `src/domain/product-identity.ts` exporting a single frozen object with the derived forms
(display name, npm package, bin, state dirs, kind prefix, env prefix, CSS/token prefix, TS
identifier prefix) plus any pure derivation helpers, so `src/cli/run.ts`, `src/contracts/*.ts`,
`src/server/support-store.ts`, `src/git/inventory.ts`, and `src/web/monaco/theme.ts` all import
from one place instead of repeating literals. Non-TS consumers (`.github/workflows/*.yml`,
`scripts/*.mjs`, `supabase/config.toml`, `.gitignore`, Markdown docs) cannot `import` it — the
rename/literal-replace script instead reads the same values from a sibling JSON file (or the TS
module re-exported as JSON via a tiny build step) so there is still exactly one source of truth,
per CONTEXT.md D-01 and RESEARCH.md Pattern 1.
