# Phase 17.1 Plan 02: Agent Protocol Kind Literal Rename Summary

**Renamed the agent protocol's `kind` literals from `cumpa.review-request`/`cumpa/export` to `RENAME_MAP.kindPrefix`-derived `loopnote.review-request`/`loopnote/export` across all four request schemas and six export schema versions, and added a dedicated `'legacy-kind'` `AgentRequestError` that rejects old-kind request bodies before any Git/browser work starts, naming the new kind.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2 (RED + GREEN, type: tdd)
- **Files modified:** 11

## Accomplishments
- `AgentReviewRequestSchema`'s four discriminated-union branches (patch/revisions/uncommitted/files) in `src/contracts/request.ts` now use `z.literal(\`${RENAME_MAP.kindPrefix}.review-request\`)` instead of the hardcoded old string.
- All six `ReviewExportVN` schemas in `src/contracts/draft.ts` use `z.literal(\`${RENAME_MAP.kindPrefix}/export\`)`; the single shared `kind` field in `src/export/review-export.ts`'s `buildReviewExportV1` document (reused by V2-V6) was updated once.
- `src/cli/request.ts` gained `AgentRequestErrorKind`'s `'legacy-kind'` member, a `requestErrorMessages['legacy-kind']` entry naming `RENAME_MAP.kindPrefix`, and `isLegacyKind(value)` — a boolean guard matching the exact literal `'cumpa.review-request'` string (the one documented grep-audit exception), checked first in `readAgentReviewRequest`'s rejection ternary, ahead of `isUnsupportedVersion`/`isUnknownMode`/`isBaseWithUnstaged`.
- The pre-existing `'empty-request'` and `'invalid-request'` messages, which previously embedded the literal old-kind string in their text, now reference the new kind via `RENAME_MAP.kindPrefix` template literals — leaving exactly one occurrence of the literal `'cumpa.review-request'` string in `src/cli/request.ts` (inside `isLegacyKind`'s body).
- Updated every fixture consumer of the kind literal: `tests/unit/agent-request.test.ts` (13 sites + 4 new tests), `tests/cli/request.test.ts` (`request()`/`patchRequest()` helpers, 6 message assertions, 2 new tests), `tests/unit/review-export.test.ts` (V1/V5/V6 assertions), `tests/unit/review-markdown.test.ts` (3 sites), `tests/unit/uncommitted-contracts.test.ts` (1 site), `tests/e2e/agent-ready-export-safety.spec.ts` (1 site).
- Regenerated the committed Vitest snapshot `tests/unit/__snapshots__/review-export.test.ts.snap` via `vitest -u`; verified programmatically (field-level JSON diff of all four v1-v4 entries) that only the `kind` field's value changed (`cumpa/export` → `loopnote/export`) — no other field moved.
