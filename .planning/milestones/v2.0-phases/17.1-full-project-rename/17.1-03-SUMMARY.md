# Phase 17.1 Plan 03: npm/CLI/picker/Monaco-theme identity rename Summary

**Renamed the npm package identity, CLI command, picker-mode identifiers, and Monaco theme/CSS-token-virtual-module identifiers from `cumpa`-literal forms to `RENAME_MAP`-derived (`loopnote`) forms, using a temporary ts-morph AST rename for the cross-file Monaco theme identifiers.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 2
- **Files modified:** 14 (8 plan-listed + production-picker.mjs/package-assets.spec.ts's two extra env-var sites required for functional correctness, see Deviations)

## Accomplishments
- `package.json`'s `name`, `bin` key, `repository.url`, `bugs.url` now derive `RENAME_MAP`; `package-lock.json` regenerated by a real `npm install` (not hand-edited), confirmed its top-level `name` matches `RENAME_MAP.npmPackage`.
- `src/cli/run.ts`: `expectedPackageName`, Commander's `.name()`, the launch-options env var, and every `console.error`/`output` display string now read `RENAME_MAP` (11/11 sites).
- `src/cli/picker.ts`: `BACK_TO_BASE`, the three `UNCOMMITTED_ROW_IDS` values derive `RENAME_MAP.slug`; "will be cumpad from" reworded to plain English "will be compared from" (5/5 sites).
- Monaco `CUMPA_THEME_ID`, `CUMPA_THEME`, and `applyCumpaTheme` renamed via a temporary `ts-morph` `Project`/`Identifier.rename()` pass across `theme.ts`, `diff-adapter.ts`, and `tests/unit/monaco-theme.test.ts`; `ts-morph` installed then uninstalled with zero net `package.json`/`package-lock.json` diff.
- Hand-edited the string literals `ts-morph` cannot reach: the theme-id value, the `.add-{side}-comment` editor-action ids, the `inmemory://` URI authority (6 sites across both Monaco adapter classes), and `scripts/token-root-plugin.mjs`'s `VIRTUAL_ID`/plugin `name` (now reading `scripts/rename-map.json` via a Node 24 `with { type: 'json' }` import, matching 17.1-01's established non-TS-consumer convention).
- Updated every matching test fixture (`monaco-theme.test.ts`, `monaco-diff-adapter.test.ts`, `token-contract.test.ts`, `help.test.ts`, `selection.test.ts`, `production-picker.mjs`, `package-assets.spec.ts`) to assert on the new forms.

## Decisions Made
See `key-decisions` in frontmatter. In short: renamed three Monaco identifiers (not just the two the plan's action text gave as examples) and two extra env vars inside `package-assets.spec.ts` (not explicitly named in `<interfaces>`) because both were necessary to fully satisfy this plan's own must_haves truth ("no literal cumpa remains in any file this plan owns") and, for the env vars, to keep that e2e spec functionally correct against the already-renamed `run.ts`. Deferred two other literals in files this plan owns (`CUMPA_SUPPORT_SERVICE_URL` in `selection.test.ts`, `.cumpa` in `package-assets.spec.ts`'s forbidden-path list) because each is a different `RENAME_MAP` field explicitly owned by a different plan, matching the identical precedent 17.1-02 already set for a sibling file.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed `CUMPA_LAUNCH_OPTIONS`/`CUMPA_BROWSER_OPEN_MARKER` in `tests/e2e/package-assets.spec.ts`**
- **Found during:** Task 2 (package-assets.spec.ts fixture update)
- **Issue:** The plan's `<interfaces>` text only called out this file's `bin: {cumpa: ...}` manifest-key assertion. But the same file separately spawns the real packaged CLI and sets `CUMPA_LAUNCH_OPTIONS` to bypass the interactive picker — since Task 2 renamed `src/cli/run.ts` to read `process.env[\`${RENAME_MAP.envPrefix}LAUNCH_OPTIONS\`]`, leaving the test's env var name unchanged would silently break the test's actual control flow (the packaged CLI would fall through to stdin-based `runOrdinaryAction` instead of launching the pinned comparison directly).
- **Fix:** Renamed both env vars to `RENAME_MAP.envPrefix`-derived forms, matching `run.ts` exactly; also fixed the `bin` field's TS type from an invalid computed-property-name-in-type-position (`{ readonly [RENAME_MAP.binCommand]: string }`, which TypeScript rejects since `RENAME_MAP.binCommand`'s static type is `string`, not a literal) to `Readonly<Record<string, string>>`.
- **Files modified:** tests/e2e/package-assets.spec.ts
- **Verification:** Standalone `tsc --noEmit` check against the file (ignoring project config, since `tests/e2e/**` isn't in any tsconfig's `include`) showed zero errors attributable to these edits; the plan's own vitest-based verify command for this file is a no-op (vitest's `include` globs never match `tests/e2e/**`, so the file registers zero tests either way — confirmed by "Test Files 2 passed (2)" instead of 3 when run).
- **Committed in:** 0233701 (Task 2 commit)

**2. [Rule 2 - Missing critical] Also renamed `CUMPA_THEME` (theme object constant)**
- **Found during:** Task 1 (ts-morph rename)
- **Issue:** The plan's action text names `CUMPA_THEME_ID` and `applyCumpaTheme` as the identifiers to rename "(e.g. ...)" but `theme.ts` exports a third identifier, `CUMPA_THEME`, consumed by `diff-adapter.ts`'s theme registration and `monaco-theme.test.ts`'s assertions. Leaving it unrenamed would violate the must_haves truth banning every literal `CUMPA` in files this plan owns.
- **Fix:** Included `CUMPA_THEME` → `Loopnote_THEME` in the same ts-morph rename pass (three identifiers total, same mechanism).
- **Files modified:** src/web/monaco/theme.ts, tests/unit/monaco-theme.test.ts
- **Verification:** `node node_modules/vitest/vitest.mjs run tests/unit/monaco-theme.test.ts` passes.
- **Committed in:** 8a7f886 (Task 1 commit)
