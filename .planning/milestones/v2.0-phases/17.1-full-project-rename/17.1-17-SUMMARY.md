# Phase 17.1 Plan 17: API Test Fixture Rename + Draft/Export Path Schema Fix Summary

**Renamed `cumpa-`-prefixed tmpdir fixtures and `.cumpa`-literal draft/export path assertions across eight API-layer Vitest suites, and fixed four stale `.cumpa`-hardcoded Zod regexes in `src/contracts/api.ts` that were silently turning every successful draft/export response into a generic 500 error.**

## Accomplishments
- All eight API-layer test files (`attached-completion-coordinator`, `attached-completion`, `draft-atomicity`, `draft-conflict`, `draft-lifecycle`, `draft-recovery`, `draft-reveal`, `draft`) now derive their tmpdir fixture prefix from `RENAME_MAP.slug` instead of the literal `'cumpa-'`

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed `.cumpa` repo-local-state-dir path literals in the plan's own eight test files (beyond the plan's stated tmpdir-only scope)**
- **Found during:** Task 1 — re-globbing each file per the task's `<read_first>` instruction surfaced `.cumpa` path-join segments and `.cumpa/drafts/...` string literals in `draft-atomicity.test.ts`, `draft-conflict.test.ts`, `draft-recovery.test.ts`, `draft-reveal.test.ts`, and `draft.test.ts`, in addition to the tmpdir prefixes the plan called out.
- **Issue:** These literals are a residual old-name REN-01 violation inside files this plan already owns; leaving them would mean running the plan's own required `node node_modules/vitest/vitest.mjs run [8 files]` command against assertions still hardcoded to a directory draft-store.ts/draft-loader.ts stopped writing to after 17.1-11.
- **Fix:** Replaced every `'.cumpa'` path-join segment with `RENAME_MAP.repoStateDir.replace(/\/$/, '')` and every `` `.cumpa/drafts/...` `` string-literal prefix with `` `${RENAME_MAP.repoStateDir}drafts/...` ``, following the exact pattern 17.1-11 already established in `tests/unit/draft-load.test.ts`.
- **Files modified:** `tests/api/draft-atomicity.test.ts`, `tests/api/draft-conflict.test.ts`, `tests/api/draft-recovery.test.ts`, `tests/api/draft-reveal.test.ts`, `tests/api/draft.test.ts`
- **Verification:** `grep -rn "cumpa" [all 8 files]` returns no matches; full eight-file vitest run (after deviation 2 below) passes 37/37.
- **Committed in:** `670a283` (Task 1 commit)

**2. [Rule 1 - Bug] Fixed four stale `.cumpa`-hardcoded Zod regex patterns in `src/contracts/api.ts`**
- **Found during:** Task 1's acceptance-criteria verification loop — after deviation 1's path-literal fix, `draft.test.ts` and `draft-recovery.test.ts` still failed: every successful draft load/mutation or export receipt returned `{code: 'request-unavailable', message: '...Relaunch Loopnote from the terminal.'}` with HTTP 500 instead of the expected payload.
- **Root cause (confirmed by a throwaway debug instrumentation of `routes.ts`'s bare `catch`, reverted before committing):** `src/contracts/api.ts`'s `SafeDraftPathSchema` (`/^\.cumpa\/drafts\/[A-Za-z0-9._-]+$/u`) and `ExportReceiptDirectoryPattern`/`ExportReceiptJsonFileSchema.path`/`ExportReceiptMarkdownFileSchema.path` (three `/^\.cumpa\/exports\/.../u` regexes) still only matched the pre-17.1-11 directory name. Since `draft-store.ts`, `draft-loader.ts`, and `export-store.ts` have written `.loopnote/drafts/...`/`.loopnote/exports/...` since 17.1-11 landed, every real draft/export path threw a `ZodError` in `publicLoad`/export-receipt parsing, caught by `routes.ts`'s bare `catch` and reported as a generic 500.
- **Fix:** Rebuilt all four patterns as `new RegExp(\`^\\\\${RENAME_MAP.repoStateDir}...\`, 'u')`, interpolating the live `RENAME_MAP.repoStateDir` value instead of a hardcoded literal.
- **Files modified:** `src/contracts/api.ts`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` and `npm run typecheck:tests:node` both pass with no errors; the plan's full eight-file vitest run passes 37/37 (up from 13/37 passing before any of this plan's edits, 22/37 after deviation 1 alone); a targeted before/after comparison of `tests/api/{exact-patch,export-publication,export,standalone-session,support}.test.ts` (none in this plan's scope) confirmed this fix introduces zero new failures in files already pre-existingly broken for unrelated reasons, except `tests/api/export.test.ts`, which gained 4 additional (expected) failures — see "Deferred to sibling plan" below.
- **Committed in:** `670a283` (Task 1 commit)
