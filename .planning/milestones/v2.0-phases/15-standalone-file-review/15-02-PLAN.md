<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Draft/export JSON on disk → Zod parse | Every persisted or exported document is re-validated on read; a widened schema must not accidentally accept a malformed standalone document as valid |
| Draft identity comparison (`sameComparison`) | Must continue to distinguish a standalone draft from a staged/unstaged/worktree draft with the same `reviewKey` collision space — mitigated structurally since `standaloneReviewKey` uses a distinct domain-separation constant, making cross-kind collision cryptographically implausible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-15-06 | Tampering | `UncommittedScopeSchema`/`WorktreeSnapshotManifestSchema` (later plan) superRefine | mitigate | `standaloneArguments` presence is symmetrically enforced (required iff `sourceKind === 'standalone'`, forbidden otherwise) so a crafted scope cannot smuggle a base commit into a standalone session or omit the argument provenance a standalone session's draft identity depends on |
| T-15-07 | Repudiation | `standaloneReviewKey` domain separation | mitigate | A dedicated `STANDALONE_DOMAIN` constant (distinct from `UNCOMMITTED_DOMAIN`) guarantees a standalone review key can never collide with an uncommitted review key for the same byte inputs, preserving per-session-kind draft isolation (mirrors existing `RANGE_DOMAIN`/`UNCOMMITTED_DOMAIN` separation) |
| T-15-08 | Tampering | `ReviewExportV4Schema` backward-compatibility guard | mitigate | `superRefine` re-derives and `safeParse`s a synthetic V1-shaped sub-document exactly like V1/V2/V3 already do, so a V4 document that would corrupt the common feedback shape is rejected at parse time, not silently accepted |
</threat_model>
