### Rationale for the two "not changed" tokens and the `.tree-row` retuning

- **`--font-size-body` (14px) stays 14px, untouched.** `grep` confirms it drives body copy across every untouched surface this phase re-hosts verbatim: global form controls, `.state-card p`, `.draft-recovery__card p`, `.inline-notice p`, `.export-section` (the interim panel's own `ExportSection.vue` content), `.empty-files-pane p`, `.tree-empty h3`. Repurposing it to 13px would silently restyle all of that, which contradicts "content unchanged" for the interim panel and the untouched empty-file states. `--font-size-chrome` (13px, new) is introduced instead for the *new* shell chrome only.
- **`--control-height-compact` (30px) is renamed/revalued, not left alone.** Its only consumer (`grep`-verified) is `.review-toolbar .ui-button`, and `ReviewToolbar.vue` is deleted this phase. There is no orphaned token and no ripple: `--control-height-icon` (22px) is the direct, clean replacement, consumed exclusively by the new icon-only buttons this phase introduces.
- **`.tree-row` gets a token swap, not a restyle.** TOK-01 requires rows to actually render at 22px. `.tree-row`'s current box (`padding-block:5px` + `line-height-body:21px` = 31px) would still overflow the new `--file-row-min-height:22px` floor if left untouched (CSS `min-height` is a floor, not a ceiling). Phase 20 therefore also changes `.tree-row`'s `font-size`/`line-height` from `--font-size-body`/`--line-height-body` to `--font-size-chrome`/`--line-height-chrome`, and `padding-block` from `5px` to `3px` (3 + 3 + 16 = 22px exactly). This is a pure geometry/token change: no new tree features, no marks/badges/colors/folder-compaction/filter/view-options — those stay exactly as implemented today and are TREE-01..07 (Phase 21). The existing `/* Approved continuity */` comments on `--tree-indent` and `--control-height-compact` in `styles.css` are superseded by this phase's validated sketch source and should be removed when their values change.

## Sash, Panel & Persistence (SHELL-02, SHELL-03, SHELL-04)

### Side-bar sash
- 4px hit area between side bar and editor (`role="separator"`, `aria-orientation="vertical"`, `aria-label="Resize side bar"`, `aria-valuenow`/`aria-valuemin="170"`/`aria-valuemax="520"` reflecting live px width).
- Hover/drag: background → `--interactive-accent-emphasis`. Drag clamps to `[170, 520]` px (`--sidebar-width-min`/`-max`).
- Double-click resets to `--sidebar-width-default` (264px).
- ⌘B / Ctrl+B (title bar icon or document-level shortcut) toggles visibility without changing the stored width; `event.preventDefault()` fires **always**, including with focus inside the Monaco editor (CONTEXT).
- Not a tab stop (pointer/drag + double-click only — matches VS Code's own sash, and SHELL-02's acceptance criteria only require drag + double-click-reset + the ⌘B/title-bar-toggle path, all of which remain fully keyboard-reachable without touching the sash itself). **Known limitation, not a blocker:** there is no keyboard-only way to *resize* (only show/hide); flagged for future consideration, not required by SHELL-02.

### Bottom panel sash
- Same 4px hit-area/hover/drag/reset pattern, horizontal (`aria-orientation="horizontal"`, `aria-label="Resize panel"`), clamps to `[120, 520]` px (`--panel-height-min`/`-max`), double-click resets to `--panel-height-default` (240px).
- ⌘J / Ctrl+J toggles visibility; same always-`preventDefault` rule.
- Panel starts **closed** every session (SHELL-03: "panel is closed when a session starts") — this is never persisted, unlike width/height.
- `✕` (`close` icon, top-right of the panel header) also closes it, returning focus to whatever opened the panel (the title-bar panel toggle, or the status-bar item that opened it).

### Persistence (SHELL-04)
One versioned `localStorage` key: `loopnote.workbench.v1`.

```json
{ "sidebarWidth": 264, "sidebarVisible": true, "panelHeight": 240 }
```

- Persisted: `sidebarWidth` (clamped 170–520), `sidebarVisible` (boolean), `panelHeight` (clamped 120–520).
- **Not** persisted: panel open/closed state (always starts closed per SHELL-03).
- On load: `JSON.parse` failure, wrong shape, non-numeric, or out-of-range values are ignored and replaced with defaults (`264` / `true` / `240`); the key is overwritten with the corrected value on the next persist (debounced on drag-end / toggle), never left corrupt.
- Scoped to "same machine" (SHELL-04) — `localStorage`, not session/server state, matches existing project convention (no prior `localStorage` usage exists in `src/web`; this is the first, and the `.v1` suffix follows the versioned-key pattern CONTEXT specifies for future migrations).
