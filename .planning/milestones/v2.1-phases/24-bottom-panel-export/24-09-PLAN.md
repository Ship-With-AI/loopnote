  <files>src/web/App.vue</files>
  <action>
Add, as a sibling of the existing `selectFile`/`reviewInlineComposer` functions:

```ts
function revealCommentFromPanel(commentId: string, fileId: string, side: WorkspaceComment['side'], line: number): void {
  if (fileId !== selectedFile.value?.fileId) selectFile(fileId);
  collapsedByCommentId.value = new Map([...collapsedByCommentId.value, [commentId, false]]);
  void nextTick(() => {
    diffWorkspace.value?.revealComment(side, line);
    void nextTick(() => {
      (document.querySelector(`[data-comment-id="${commentId}"] .thread-header`) as HTMLElement | null)?.focus();
    });
  });
}
```

This reuses exactly the three pieces `jumpThread` (Phase 23's `23-08-PLAN.md` Task 3) already uses for cross-file thread navigation — `selectFile()` (existing, pre-Phase-23), the `collapsedByCommentId` expand-on-arrival map replacement (Phase 23's Task 1 addition — this plan's cross-phase dependency), and `diffWorkspace.value?.revealComment(side, line)` for the scroll (existing adapter method) — so "open the file, expand the thread, scroll it into view" is the *same* mechanism `jumpThread` uses, not a parallel one. The one piece `jumpThread` does **not** do is move focus onto the thread's header; this function adds that as the final step, targeting `CommentThread.vue`'s root (`[data-comment-id]`) and its `.thread-header` element (Phase 23's clickable collapse-toggle, already focusable by role/semantics per `23-UI-SPEC.md`). Keep **both** `nextTick` layers (never collapse to one) — the outer lets `selectFile`'s file-switch render settle and lets the `collapsedByCommentId` map-replacement re-render the now-expanded thread; only the inner, after `revealComment` has run, queries and focuses `.thread-header` (`24-RESEARCH.md` Pitfall 1 — the riskiest case is when the target file differs from the currently-open one, since `selectFile` tears down and remounts `DiffWorkspace`'s Monaco instance).

No new import is needed if `collapsedByCommentId`/`selectFile`/`diffWorkspace` are already in scope (they are module-level refs/functions in this same `<script setup>` block).
