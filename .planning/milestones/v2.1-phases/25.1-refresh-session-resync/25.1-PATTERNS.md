## Naming note (Claude's Discretion item)

CONTEXT leaves the new helper's path to the planner's discretion. Sibling `src/web/model/*.ts` files are named as domain nouns, not verbs (`file-tree.ts`, `panel-state.ts`, `thread-order.ts`, `comment-groups.ts`, `draft-reconciliation.ts`, `selector-drift-state.ts`). `refresh-resolution.ts` follows that convention and avoids collision with the unrelated `draft-reconciliation.ts` (which resolves *comments* to files via `ExactPath` byte identity at both Base/Head; the new helper resolves *display-path strings from `RefreshResult`* to a single current `fileId`). `path-resolution.ts` is a reasonable alternative if the planner prefers a flatter name — either is a direct structural match to `draft-reconciliation.ts`'s shape.

**Selection-preservation / fallback pattern — closest existing analog is `activeFile` + `selectFile`:**

The new resolution helper (`refresh-resolution.ts`) should build an index keyed by `newPath?.display ?? oldPath?.display` (mirroring this exact precedence) over the **re-fetched** `session.value.files`, used both to re-resolve the currently-selected file's path and to resolve `RefreshSummaryPanel` row targets.

**Conditional single-shot announcement — analog is the guarded `watch` pattern (`App.vue:489-493`):**

Structural precedent for "announce only when the guarded condition transitions / actually changes" — the new selection-change announcement should follow the same if-guard-then-announce shape (`announce()` defined `App.vue:499-502`), called with the exact locked string from the UI-SPEC:
```typescript

```
No new live region: the single `<p class="visually-hidden" aria-live="polite">` region already renders `liveMessage`/`liveMessageVersion` (`App.vue:1809-1811`).

**Analog:** `src/web/model/draft-reconciliation.ts` (full file, 62 lines)

**Core index-building pattern** (`draft-reconciliation.ts:12-35`):
```typescript
function selectedPath(file: SessionFile, side: AnchorSide): ExactPath | undefined {
  return side === 'base' ? file.oldPath : file.newPath;
}

function addFile(index: Map<string, ExactFileCapability>, path: ExactPath | undefined, fileId: string): void {
  if (path === undefined) {
    return;
  }

  const existing = index.get(path.bytesBase64url);
  index.set(path.bytesBase64url, existing === undefined ? { kind: 'available', fileId } : UNAVAILABLE_FILE);
}

function exactFileIndex(files: readonly SessionFile[]): ExactFileIndex {
  const base = new Map<string, ExactFileCapability>();
  const head = new Map<string, ExactFileCapability>();

  for (const file of files) {
    addFile(base, selectedPath(file, 'base'), file.fileId);
    addFile(head, selectedPath(file, 'head'), file.fileId);
  }

  return { base, head };
}
```
**Resolve-by-key pattern + public API shape** (`draft-reconciliation.ts:37-61`):
```typescript
function reconcile(comment: DraftComment, index: ExactFileIndex): WorkspaceComment {
  const exactFile = index[comment.anchor.side].get(comment.anchor.path.bytesBase64url) ?? UNAVAILABLE_FILE;
  const fileId = exactFile.kind === 'available' ? exactFile.fileId : null;
  // ...
}

export function reconcileDraftComment(comment: DraftComment, files: readonly SessionFile[]): WorkspaceComment {
  return reconcile(comment, exactFileIndex(files));
}

export function reconcileDraftComments(comments: readonly DraftComment[], files: readonly SessionFile[]): readonly WorkspaceComment[] {
  const index = exactFileIndex(files);
  return comments.map((comment) => reconcile(comment, index));
}
```
**Delta for the new helper:** build a single `Map<string, string>` keyed by the *display* string — `file.newPath?.display ?? file.oldPath?.display` (matching `App.vue:1071`'s precedence, not `draft-reconciliation.ts`'s split base/head `ExactPath.bytesBase64url` keying, since `RefreshResult.added/removed/modified` are plain `readonly string[]` display paths per `src/web/api/client.ts:75-84` / `src/server/worktree-snapshot.ts:539-543`, not `ExactPath` objects) — then expose a `resolvePathToFileId(path: string, files: readonly SessionFile[]): string | undefined` (or an index-returning builder + lookup pair, mirroring the two-function split above) for both `App.vue`'s selection-preservation and `RefreshSummaryPanel.vue`'s per-row resolution to share.

**No error handling needed** — pure synchronous `Map`/`find` lookups, same as the analog (no try/catch anywhere in `draft-reconciliation.ts`).

## Shared Patterns

### Live-region announcement discipline
**Source:** `App.vue:499-502` (`announce()`), guarded-transition precedent `App.vue:489-493`, template sink `App.vue:1809-1811`
**Apply to:** the new selection-change announcement in `performRefresh()`
```typescript
function announce(message: string): void {
  liveMessage.value = message;
  liveMessageVersion.value += 1;
}
```
Single `<p class="visually-hidden" aria-live="polite">` region; every call site guards on an actual-change condition before calling `announce()` (never unconditionally) — see `App.vue:489-493`, `:477-481` for the two-branch precedent.

### `SessionFile` path precedence (path ↔ fileId)
**Source:** `App.vue:1071` (`file.newPath?.display ?? file.oldPath?.display`), mirrored in `draft-reconciliation.ts:12-14` (`selectedPath`, split by side instead of collapsed)
**Apply to:** `App.vue`'s selection-preservation logic and the new `refresh-resolution.ts` helper — both must use the same `newPath ?? oldPath` precedence so a file that exists in the new snapshot resolves identically everywhere.

### Packaged-binary e2e plumbing
**Source:** `tests/e2e/uncommitted-review.spec.ts:1-27`, `tests/e2e/standalone-review.spec.ts:1-33`, `tests/e2e/workbench-shell-smoke.spec.ts:1-37` (near-duplicate boilerplate across all three)
**Apply to:** any new/extended Refresh e2e assertions — reuse the existing per-file `startGeneratedUncommittedCli`/`waitForLoopbackUrl`/`openGeneratedUncommittedReview` (or standalone/shell-smoke equivalents) helpers already defined in the target file; do not introduce a fourth copy of this plumbing in a new file unless the planner decides a dedicated `refresh-resync.spec.ts` is warranted (CONTEXT does not require a new file — "new/extended e2e specs" permits extending the three existing ones).
