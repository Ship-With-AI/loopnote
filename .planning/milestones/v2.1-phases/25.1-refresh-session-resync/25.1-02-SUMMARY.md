## Accomplishments
- `performRefresh()` closes the IDENT-04 gap: the re-fetched session now replaces `session.value`, so every computed driving the tree, nav order, status bar, and identity pill/popover reflects the recaptured snapshot without a page reload.
- Selection survives Refresh by path, not fileId (fileIds are content-addressed and change when a file's blob changes): the previously-selected file stays open (re-synced via `selectFile()` only when its resolved fileId actually differs), or falls back to the file now occupying its former tree-order position with a single locked-wording announcement.
- `RefreshSummaryPanel.vue` closes the SHELL-05 gap: its `select-file` emit now carries a resolved `fileId` instead of a raw path, so clicking a summary row actually opens the file instead of no-op'ing on `selectFile(fileId)`.
- Unresolved summary paths render a new muted, non-interactive "Removed" row (`ReviewStateBadge kind="disabled"`) instead of a dead button.

## Decisions Made
- `previousPath`/`previousIndex` are captured from the pre-refresh `session.value`/`flatFileRows` *before* reassigning `session.value`, because `flatFileRows` is a `computed` derived from `session.value` and would otherwise report the post-refresh tree order for the "former ordinal position" fallback lookup (25.1-RESEARCH.md Pattern 2 / Anti-Patterns).
- `selectFile(resolvedFileId)` is only invoked on the path-preserved branch when `resolvedFileId !== selectedFile.value.fileId`, matching the plan's explicit guard and avoiding unnecessary content re-fetches/announcements when the fileId is unchanged.
