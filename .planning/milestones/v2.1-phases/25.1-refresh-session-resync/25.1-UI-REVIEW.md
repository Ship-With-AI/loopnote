### Pillar 6: Experience Design (4/4)

**PASS — Origin-owned saves settle before recapture.** Busy lock is acquired before autosaving (`App.vue:1405-1410`). Loop examines old reviewable files, passes each origin `fileId`, awaits `dispatchWorkspace`, and checks that origin's remaining composer (`1411-1418`). Reducer accepts optional `fileId`, defaults ordinary Add comment to active file, and consistently uses chosen file for state and persist command (`src/web/model/workspace-state.ts:66,270-291`). Dispatch awaits `runCommands`, which waits for persistence promises (`App.vue:1050-1068`). This avoids saving off-screen draft as currently selected file.

**PASS — Failed/pending save pauses without recapture or text loss.** Remaining non-empty composer causes paused announcement and early return before `refreshWorktreeSnapshot()` (`App.vue:1414-1419`); `finally` releases busy (`1476-1477`). This branch does not replace session or remove origin row. Failure transition retains text (`workspace-state.ts:309-319`). Retry can save against old snapshot before recapture/reconciliation. Parent's fifth packaged case supplies bounded behavioral proof; this auditor supplies source inspection only.

**PASS — Final repair locks input for the whole Refresh interval.** `dispatchWorkspace` guards composer input, activation, cancellation/discard/move, and ordinary Add comment while `refreshBusy` (`App.vue:1053-1063`). Explicit origin-owned add-comment remains allowed for internal autosave unless attached mutations are locked, avoiding self-blocking the pre-refresh save loop. App passes `attachedMutationLocked || refreshBusy` into existing `DiffWorkspace` lock prop (`1734`). `DiffWorkspace.vue:260-264` forwards it to composer; its existing annotation watcher now includes `props.mutationsLocked` and rerenders annotation (`366-397`), so busy-only changes update the mounted composer rather than waiting for text/comment changes. Parent's sixth case asserts real textarea disabled during delayed recapture. This is not a claim that every thread action or every possible concurrent interaction was personally exercised.

**PASS — Final repair always reopens surviving selection after successful session re-fetch.** Re-fetch replaces `session.value`, with path-based workspace-state mapping (`App.vue:1424-1445`). Surviving selected path unconditionally calls `selectFile(resolvedFileId)` (`1446-1449`): intermediate ID/`delta.modified` guard is gone. Thus a recapture that succeeded before one failed session fetch can be retried with an empty delta without leaving selected bytes stale. Same-active-file `selectFile` takes existing `loadFile` path (`App.vue`, `selectFile` implementation); no metadata-only branch remains in Refresh. Parent's sixth case supplies the failed-fetch/retry interaction evidence, not screenshots.

Fallback retains tree-order ordinal and clears obsolete content for empty inventory (`App.vue:1450-1468`). `FileTree.vue:398-409` respects parent's refreshed selected ID rather than competing fallback. Existing comments reconcile afterward (`App.vue:1470-1474`); pause does not reset existing thread edit buffers. Broader shell/filter/expansion and thread-buffer preservation remain parent runtime gates, not screenshot-proven guarantees. Stable review identity is not regenerated in this path.

**PASS — Fresh-session summary targets; absent rows inert.** `RefreshSummaryPanel.vue:16,19-26` resolves reactive paths against fresh `sessionFiles`; App binds `session?.files` (`App.vue:1673-1677`). Lists branch on resolution, not Added/Removed/Modified category. Deleted-but-still-listed paths remain actionable deleted diffs; absent paths render inert text. Resolver uses effective display paths rather than matching IDs across snapshots (`src/web/model/refresh-resolution.ts:3-50`). S1/S2 agree on counts, selection, and content within captured states.

**PASS — One existing App live owner for Refresh explanations.** Pause (`App.vue:1415`) and selection loss (`1458`) call existing `announce()` (`502-505`), updating message/version refs rendered by one explicit App `<p class="visually-hidden" aria-live="polite">` (`1865-1867`). No second region, toast, panel, CTA, icon, or token. Retained summary `InlineNotice role="status"` (`RefreshSummaryPanel.vue:47-49`) remains separate implicit status surface by existing convention; it does not carry either sentence. Ownership is source evidence, not proof of real assistive-technology scheduling/coalescing or audible count. Existing busy/progress integration remains (`App.vue:1608,1621`). No open interaction defect identified within inspected source and attributed parent evidence.
