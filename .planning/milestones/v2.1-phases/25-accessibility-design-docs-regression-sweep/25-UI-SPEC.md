# Phase 25 — UI Design Contract: Accessibility, Design Docs & Regression Sweep

> Visual and interaction contract for Phase 25 (TOK-02, A11Y-01..03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase ships **no new visual surface**. It closes DEBT-01 (toolbar role/name coverage), adds the live-region announcements the accessibility audit found structurally missing, confirms every popover/menu already meets the keyboard contract, and rewrites `DESIGN.md` to describe the shipped workbench. Every fix below is additive (`role`/`aria-label` attributes, `announce()` calls, prose) — zero new spacing, typography, or colour values. Where prior phases had something new to design, Phase 25 has only existing-surface audit findings to close; this contract is intentionally thin on visuals and dense on exact strings, matching the phase's own boundary (`25-CONTEXT.md` `<domain>`: "Not in this phase: new features, narrow/phone layout, visual redesign beyond defects found by the audits").

Design source of truth for this phase is not a sketch — it is `local://phase-25-accessibility-audit.md` (toolbar/popover/live-region audit) and `local://phase25-research-findings.md` (Phase 24 dependency + DESIGN.md line audit), both already-completed codebase research reused here rather than re-run. Citations below were independently re-verified against the live source files, not taken on trust from the dossiers.

**Critical regression constraint found during this research (not flagged by either dossier):** `TitleBar.vue`'s `<header>` and `StatusBar.vue`'s `<footer>` currently carry their **implicit landmark roles** (`banner` and `contentinfo`). At least 6 existing, currently-passing e2e specs (`anchored-review.spec.ts:136`, `complete-review-draft.spec.ts:153`, `inline-comment-threads.spec.ts:133,141`, `rendered-markdown-preview.spec.ts:118`, `workbench-shell-smoke.spec.ts:217,254`) call `page.getByRole('banner')` to locate the title bar. Overriding `<header class="titlebar">`'s role to `"toolbar"` (the naive DEBT-01 fix) would silently break every one of those locators — a same-phase regression this phase exists to prevent (A11Y-03). The contract below places the new `role`/`aria-label` on the **inner button-cluster `<div>`** in each component instead, leaving the landmark elements' implicit roles untouched. This is also the existing project pattern: `FileTree.vue`'s `role="toolbar"` already sits on a `<div class="file-tree-pane__toolbar">`, not on a landmark ancestor.

## Toolbar Role & ARIA-Label Contract (A11Y-01, closes DEBT-01)

ROADMAP's success criterion #1 names five regions: **title bar, side bar, editor title, panel tabs (bottom panel), status bar.** Current state, re-verified against source:

| # | Region | File | Current state | Verdict |
|---|--------|------|----------------|---------|
| 1 | Title bar | `TitleBar.vue` | `<header class="titlebar">` has no `role`/`aria-label` on any button-cluster wrapper | **Fix below** |
| 2 | Side bar | `FileTree.vue:426` | `<div class="file-tree-pane__toolbar" role="toolbar" aria-label="Changed files actions">` | **PASS, unchanged** |
| 3 | Editor title | `EditorTitle.vue:101` | `<div class="editor-title" role="toolbar" aria-label="Diff navigation">`, with nested `role="group"` sub-clusters (`"Diff layout"`, `"Markdown view"`, `"Comment threads"`) | **PASS, unchanged** |
| 4 | Panel tabs | `BottomPanel.vue` | Phase 24 (concurrent, locked in `24-UI-SPEC.md:86`) ships `<div role="tablist" aria-label="Review panel" class="bottom-panel__tabs">` | **Owned by Phase 24 — do not touch.** Reachable by `getByRole('tablist', { name: 'Review panel' })`, not `'toolbar'`/`'group'` — see note below |
| 5 | Status bar | `StatusBar.vue` | `<footer class="statusbar">` has no `role`/`aria-label` on any button-cluster wrapper | **Fix below** |

**Note on region 4's role:** ROADMAP's literal phrasing is `getByRole('toolbar' | 'group', { name })`, but Phase 24's already-locked, approved contract makes the panel tabs a standard ARIA tabs widget (`role="tablist"` + `role="tab"` children), which is the *correct* semantic — a `tablist` is not a `toolbar`/`group` and should not be forced into either role to satisfy a literal query-string match. The dedicated DEBT-01 e2e spec (below) must query region 4 with `getByRole('tablist', { name: 'Review panel' })`, not `'toolbar'`/`'group'`. This is the intended reading of A11Y-01 ("reachable by role and name"), not a deviation from it.

### Fix 1 — `TitleBar.vue`

Target: `.titlebar__right` (`TitleBar.vue:63`), the `<div>` wrapping the refresh / sidebar-toggle / panel-toggle buttons — **not** the `<header>` itself (preserves `role="banner"` for the locators listed above).

```html
<div class="titlebar__right" role="toolbar" aria-label="Title bar actions">
```

Rationale for `"Title bar actions"`: mirrors `FileTree.vue`'s established `"<region noun> actions"` naming for a button-cluster toolbar (`"Changed files actions"`), rather than `EditorTitle.vue`'s function-named `"Diff navigation"` — the title bar's cluster is a close structural match to the file tree's cluster (icon-only utility buttons, no primary single function to name), not to the editor title's navigation-first cluster.

### Fix 2 — `StatusBar.vue`

Target: `.statusbar__right` (`StatusBar.vue:64`), the `<div>` wrapping the Comments / Export-or-Finish / Support buttons — **not** the `<footer>` itself (preserves `role="contentinfo"`; no test currently depends on it, but overriding a landmark role without need is the same defect this fix is removing from `TitleBar.vue`).

```html
<div class="statusbar__right" role="toolbar" aria-label="Status bar actions">
```

`.statusbar__left` (snapshot identifier only, no interactive controls) gets no role change — it is not a control group.

### Dedicated DEBT-01 proof spec (locked, CONTEXT)

New file, Claude's Discretion on exact name (suggest `tests/e2e/toolbar-roles.spec.ts`, matching the project's `<topic>.spec.ts` naming convention): one packaged-runtime test asserting all five regions resolve via `getByRole`:

```ts
await expect(page.getByRole('toolbar', { name: 'Title bar actions' })).toBeVisible();
await expect(page.getByRole('toolbar', { name: 'Changed files actions' })).toBeVisible();
await expect(page.getByRole('toolbar', { name: 'Diff navigation' })).toBeVisible();
await expect(page.getByRole('tablist', { name: 'Review panel' })).toBeVisible();
await expect(page.getByRole('toolbar', { name: 'Status bar actions' })).toBeVisible();
```

Once this spec passes against the packaged binary, DEBT-01 is removed from `ROADMAP.md` Backlog (`:349`) and `PROJECT.md`'s accepted-debt notes (`:38`, `:331`) — an execution-time edit to those two files, out of this UI-SPEC's write scope.

## Live-Region Announcement Contract (A11Y-02, half 2)

`App.vue`'s `announce(message: string)` (`App.vue:493-496`, sets `liveMessage`/`liveMessageVersion`) is the project's **single live-region owner** — established by Phases 20–24 and unchanged here. Every new announcement in this phase is wired as a child-component emit into an existing `App.vue` handler, never a second live region in a child component.

**House style**, extracted from the 20+ existing call sites (verified at `App.vue:423`, `:773-782`, `:474`, `:485`): short declarative sentence stating the completed outcome, past tense or stated-fact present, period-terminated, no exclamation marks, counts appended as `` `{n} open, {n} resolved.` `` when the action changes thread counts. Examples quoted verbatim as the style reference:

- `'Comment restored.'`
- `'Comment resolved. {open} open, {resolved} resolved.'`
- `'Working tree changed since snapshot.'`
- `'Review export complete. Both files published together.'`

### New announcements this phase must add

Four gaps, each verified as **structurally absent today** by reading the relevant handler (not merely asserted by the audit dossier) — each phrased to match the house style above, each a discrete user action (click or arrow-key activation) that fires exactly once per outcome, so none need the `hadX`-boolean dedup pattern the watcher-based drift announcements use.

**1. Panel tab switch** — wire into whatever `App.vue` handler Phase 24 attaches to `BottomPanel.vue`'s `update:activeTab` emit (`24-UI-SPEC.md:124-128`, `panelState.setActiveTab(tab)`). Reuse Phase 24's own tab-label strings (`'Comments'`, `'Summary'`, `'Export'`) verbatim — do not invent new label text:

```
`${tabLabel} tab selected.`
```
→ `"Comments tab selected."` / `"Summary tab selected."` / `"Export tab selected."`

**2. Thread collapse** — two call sites, two distinct announcements (do not conflate, each is a separate outcome):

- Single thread, `App.vue`'s `toggleCommentCollapse(commentId)` (`:360-366`, handles `CommentThread.vue`'s `toggleCollapse` emit, wired `App.vue:1659`):
  ```
  collapsed ? 'Thread collapsed.' : 'Thread expanded.'
  ```
  (the post-toggle `next.get(commentId)` state — the function already computes `next`/`current` locally, so use `!current`.)

- Collapse-all, `App.vue`'s `toggleThreadsCollapsed()` (`:368-375`, handles `EditorTitle.vue`'s `toggleThreadsCollapsed` emit, wired `App.vue:1558`), which already derives `collapseAll = anyThreadExpanded.value`:
  ```
  collapseAll ? 'All threads collapsed.' : 'All threads expanded.'
  ```

**3. Filter / view-mode change in the file tree** — two sub-cases:

- **View-mode toggle** (tree ↔ list, `TREE-04`): `App.vue`'s `toggleTreeViewMode(mode)` (`:539-542`, handles `FileTree.vue`'s `update:view-mode` emit, `FileTree.vue:415`):
  ```
  mode === 'list' ? 'Viewing as list.' : 'Viewing as tree.'
  ```

- **Filter match count** (`TREE-03`): `FileTree.vue`'s filter is local state (`query = ref('')`, `FileTree.vue:51`) with no existing emit and no existing debounce — the visual "N of M" badge (`FileTree.vue:457`) and `model.flatFileRows.length === 0` empty state (`FileTree.vue:543`, exact text `` `No changed files match "${query}".` ``) recompute instantly on every keystroke. Announcing on every keystroke would violate "exactly one announcement per outcome" (continuous typing is not a discrete outcome). **New, locked implementation detail:** add a single dedicated 400ms debounce timer around a new `FileTree.vue` emit, `filterResult: [matched: number, total: number]`, fired only after the debounce settles (the existing instant visual recompute is untouched — only the announcement is debounced). `App.vue` handles the new emit:
  ```
  matched === 0
    ? `No changed files match "${query}".`   // reuse FileTree.vue:543's exact string, not a new one
    : `${matched} of ${total} files match.`   // reuses FileTree.vue:68's existing "{n} of {m} files" phrasing, completed into a sentence
  ```

**4. Markdown source/rendered toggle** (`EditorTitle.vue`'s `toggle-mode` emit, handled inline in `App.vue:1550` → `setFileMode(fileId, mode)`, `App.vue:554`):
```
mode === 'source' ? 'Showing Markdown source.' : 'Showing rendered Markdown.'
```

### Audit-driven copy fix (not a new announcement — a correctness fix to an existing one)

`25-CONTEXT.md`'s locked decision explicitly scopes "thread resolve / reopen / delete (**+ Undo**)" into the audit, and the audit found the Undo path's announcement is the one outlier that doesn't carry count context its three siblings do. Fix `commitPendingDelete`'s `announce('Comment restored.')` (`App.vue:423`) to match the `resolveComment`/`reopenComment`/`deleteComment` pattern at `App.vue:773-782`, reusing the already-existing `openCommentCount` computed (`App.vue:299`) rather than introducing new state:

```ts
announce(`Comment restored. ${openCommentCount.value} open, ${workspaceComments.value.length - openCommentCount.value} resolved.`);
```

### Out of scope for this contract

The audit additionally flagged that anchor-drift announcement (`App.vue:474`) fires only on the transition *into* the unverified state, never back to verified — and that export-failure announcements share one message across two response kinds by design (not a defect). Whether these (or any other) are genuine duplicate/missing announcements can only be confirmed by the real-Chromium measurement `25-CONTEXT.md` calls for during execution, not by static reading. **Any additional finding surfaced only by that runtime measurement must reuse this contract's house style** (declarative, past-tense/stated-fact, period-terminated, counts appended only where a sibling announcement already carries them) rather than inventing a new tone — this UI-SPEC locks copy only for the five fixes above, which were confirmed structurally absent/incorrect by source inspection alone.
