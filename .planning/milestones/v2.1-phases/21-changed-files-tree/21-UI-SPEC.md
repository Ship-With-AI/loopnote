# Phase 21 — UI Design Contract: Changed-Files Tree

> Visual and interaction contract for Phase 21 (TREE-01..07). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Design source truth: `.kimi-code/skills/sketch-findings-loopnote/references/changed-files-tree.md` (sketch `003-explorer-tree`, winning variant **A**), cross-cutting geometry from `references/tokens-and-density.md` / Phase 20 (`20-UI-SPEC.md`). This contract restyles and extends the side-bar tree Phase 20 re-hosted unchanged; it does not touch `WorkbenchShell.vue`, `TitleBar.vue`, `EditorTitle.vue`, `BottomPanel.vue`, or `StatusBar.vue`. Lessons carried from `20-UI-REVIEW.md`: never ship two differently-labelled controls for one piece of state (the list⇄tree toggle is the **only** control for tree/list mode — no duplicate), and every truncatable text element gets an explicit overflow rule (file names already ellipsis via `.path-text`; nothing new introduced here needs a fresh rule).

## Row Anatomy (TREE-01)

Row height 22px (`--file-row-min-height`, existing token, unchanged), flat (`--radius-file-row: 0`, unchanged), `padding-left` driven by `--tree-indent` (12px) × depth exactly as today.

**DOM / visual order, left to right** (this is also the accessible-name composition order — see `## Focus, Roles & Landmarks`):

```
[file-type mark, aria-hidden] [name] [comment badge]? [markers]* [line counts] [status letter]
```

### 1. File-type mark (new, aria-hidden, decorative)

8-column fixed width, `--font-weight-semibold` (600 — reusing the existing two-weight contract, not introducing a new 700 weight), `--font-size-label` (11px, reused — not the sketch's literal 8.5px; see `## Typography`), `--font-mono`, 20px fixed column width (fixed component dimension, exempt from the `--space-*` grid rule exactly as Phase 20 exempted its own row/title-bar geometry).

| Extension(s) | Mark | Colour token |
|---|---|---|
| `.ts`, `.tsx` | `TS` | `--syntax-type-foreground` |
| `.js`, `.jsx`, `.mjs`, `.cjs` | `JS` | `--syntax-type-foreground` (same family as TS — one new colour for "code", not two) |
| `.vue` | `V` | `--status-added-foreground` |
| `.css`, `.scss`, `.less` | `#` | `--status-resolved-foreground` |
| `.md`, `.markdown` | `M↓` | `--text-muted` |
| `.json`, `.jsonc`, `.json5` | `{}` | `--text-muted` |
| `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`, `.webp`, `.ico`, `.bmp` | `IMG` | `--status-warning-foreground` |
| anything else (incl. no extension) | `·` | `--text-muted` |

### 2. Name (`PathDisplay.vue` / `PathText.vue`, reused unchanged markup)

Colour priority (highest wins — this disambiguates the design source's two different uses of the word "unsupported": the file's **status kind** `unsupported` [rare/unmapped git status code] and its **availability kind** `unsupported`/`unavailable` [binary/non-utf8/oversized/etc., i.e. not reviewable as text] both land in the same muted bucket):

1. `availability.kind !== 'text'` → `--text-muted` (not reviewable as text; de-emphasised regardless of git status)
2. else `status.kind === 'deleted'` → `--status-deleted-foreground` **+ `text-decoration: line-through`**
3. else `status.kind === 'modified'` → `--status-modified-foreground`
4. else `status.kind === 'added'` → `--status-added-foreground`
5. else `status.kind === 'unsupported'` (rare/unmapped git status code or unknown mode) → `--text-muted`
6. else (`renamed`, `copied`, `type-changed`) → `--text-primary` (default; the status letter column alone carries the distinction — the design source colours only M/A/D by name, so R/C/T stay neutral)

Status is **never** colour-only: deleted keeps the strike-through regardless of this priority table; every status additionally shows its letter (below).

Renamed/copied rows keep the existing `PathDisplay.vue` `old → new` markup unchanged (`src/old.ts → new.ts` visual, `aria-label`/`title` = "renamed from {old} to {new}" / "copied from {old} to {new}").

### 3. Comment badge (new, conditional — `v-if count > 0`)

Comment icon (new `comment` glyph, `aria-hidden="true"`) + numeral, `--interactive-accent` (one new, specific, justified accent use this phase — see `## Color`). `aria-label="{N} open comment" + (N === 1 ? '' : 's')` on the badge span (matches the project's existing pluralisation convention, e.g. `App.vue`/`RefreshSummaryPanel.vue`'s `n === 1 ? '' : 's'`, and fixes the exact bug `20-UI-REVIEW.md` flagged in `StatusBar.vue`). Sourced from the new `openCommentCounts` prop (open comments only — resolved threads don't badge).

### 4. Markers (existing components, restyled placement + chrome only — **accessible text unchanged**)

Rendered in this order when present, **before** the line counts:

- **Refresh marker** (`tree-row__refresh-marker`): shown when the file changed since the last snapshot. Accessible label unchanged: `"Changed since last snapshot"`.
- **Standalone git-state marker** (`standalone-state-marker`): shown only for standalone-session files. Unchanged text: `"Standalone · Modified (uncommitted)"`, `"Standalone · Untracked"`, `"Standalone · Unchanged"`.
- **Availability marker** (`availability-marker`): shown (visibly) when `availability.kind !== 'text'`. Unchanged labels: `"Unsupported"` / `"Changed during capture"` (unsupported reason `changed-during-capture`) / `"Unavailable"`. When `availability.kind === 'text'`, the marker stays in the DOM as a visually-hidden `"Text"` label (unchanged) for accessible-name continuity.

**Chrome change (all three):** drop the bordered-pill treatment (`border`, `background`, the `::before` warning-triangle) inside `.tree-row` — render as plain `--text-muted` text at `--font-size-metadata` (12px, existing), matching the reference's "compact muted text badges." Outside the tree (e.g. the editor-title availability display, unaffected by this phase) keeps its existing pill chrome.

### 5. Line counts (existing `.line-counts`, visibility behaviour changes — TREE-02)

Unchanged colours (`--status-added-foreground` / `--status-deleted-foreground`, backgrounds already stripped to `transparent` in tree context) and unchanged `aria-label` (`"{N} addition(s), {N} deletion(s)"` / `"Line counts unavailable"`). **New:** default visibility is hover-or-selected (`opacity: 0` → `1` on `.tree-row:hover`, `.tree-row--selected`, or when the persisted mode is `always`), not always-on. Governed by the persisted `treeLineCounts` mode (`## View Options Menu` below). The `aria-label` is present in the DOM regardless of CSS visibility, so the accessible name is identical across all three modes — only the sighted presentation changes.

### 6. Status letter (restyled `StatusBadge.vue`, rightmost, 12px fixed column)

Flat coloured mono text, no border/background/pill inside `.tree-row` (chrome dropped exactly like the markers above). `font: 600 11px/1 var(--font-mono)`, `width: 12px`, `text-align: center` (fixed component dimension, exempt from the `--space-*` grid rule).

| `status.kind` | Letter | Colour token | Accessible label |
|---|---|---|---|
| `modified` | `M` | `--status-modified-foreground` | `"modified"` |
| `added` | `A` | `--status-added-foreground` | `"added"` |
| `deleted` | `D` | `--status-deleted-foreground` | `"deleted"` |
| `renamed` | `R` | `--status-resolved-foreground` | `"renamed"` |
| `copied` | `C` | `--status-resolved-foreground` | `"copied"` |
| `type-changed` | `T` | `--status-modified-foreground` | `"type changed"` |
| `unsupported` (rare/unmapped git status code) | raw `status.code` (the single uppercase letter git actually reported) | `--status-warning-foreground` | `"unsupported status: {code}"` |

(`unsupported`/`type-changed` previously shared one "Mode"/"Mode changed" presentation in `StatusBadge.vue`; this phase gives `type-changed` its own `T` letter per CONTEXT and gives the genuinely-rare `unsupported` status kind a visible, truthful letter — the actual git code — instead of a misleading "Mode" label, so nothing is silently hidden.)

## Compact Folders & Collapsed Bullet

Folder row: twistie (▾/▸, unchanged glyphs/markup from `DirectoryRow.vue`), compacted path (`directory.segments` joined by `/`, already existing), name in `--text-primary`. **Removed:** the numeric descendant-count badge and its `"{N} changed file(s)"` accessible label (v1.6 behaviour).

**New:** when collapsed, a dimmed `●` bullet (new, `aria-hidden="true"` — decorative; an AT user expands the folder to see real per-file status), opacity `0.7`, coloured by the highest-priority status among the folder's descendant files:

**Priority (highest wins):** `modified` (`--status-modified-foreground`) → `deleted` (`--status-deleted-foreground`) → `added` (`--status-added-foreground`) → `renamed`/`copied` (`--status-resolved-foreground`) → `type-changed` (`--status-modified-foreground`) → `unsupported` (`--status-warning-foreground`).

Hidden entirely when expanded (`v-if="!expanded"`).

## View Options Menu (TREE-05)

⋯ icon button in the view-header, `aria-label="View options"`, `aria-haspopup="menu"`, `aria-expanded`. Opens a `role="menu"` popover (new component) anchored below the button, styled like existing overlays (`--surface-panel` background, `--border-overlay`, `--radius-overlay`, `--shadow-overlay` — reused tokens, no new surface).

```html
<div role="menu" aria-label="View options">
  <div role="group" aria-label="Line counts">
    <div role="menuitemradio" aria-checked="false" tabindex="-1">Always</div>
    <div role="menuitemradio" aria-checked="true"  tabindex="0">On hover or selection</div>
    <div role="menuitemradio" aria-checked="false" tabindex="-1">Never</div>
  </div>
  <div role="menuitemcheckbox" aria-checked="true" tabindex="-1">Open comment badges</div>
</div>
```

- Arrow-key navigation moves focus among the four items (wrapping); Enter/Space activates the focused item (radio selects + closes nothing — menu stays open per native menu-radio convention until Esc/outside-click); checkbox toggles in place.
- Esc closes the menu and returns focus to the ⋯ button. Clicking outside the menu closes it (reuse the existing outside-click-dismiss pattern already used by popovers in the codebase).
- Selections persist immediately (debounced on change, same discipline as `panel-state.ts`'s existing drag-end/toggle persistence).

## Filter (TREE-03)

Opened by: the funnel icon button in the view-header (`aria-label="Filter changed files (⌥⌘F)"`), or ⌥⌘F / Ctrl+Alt+F **while focus is inside the tree** (a tree-scoped keydown handler, not a document-level always-`preventDefault` handler like ⌘B/⌘J — it does nothing when focus is elsewhere). The always-visible search box (v1.6) is removed.

```html
<div class="filter" v-show="filterOpen">
  <input
    type="search"
    aria-label="Filter changed files"
    placeholder="Filter by path"
    v-model="query"
  />
  <span class="n" v-if="query">{{ matchCount }} of {{ totalCount }}</span>
  <button type="button" aria-label="Clear filter" @click="clear">…</button>
</div>
```

- Case-insensitive substring match on the full path (existing `setQuery`/pruning model, unchanged — expansion identity and selection survive clearing per existing v1.6 guarantee).
- Matched substrings highlighted in the visible name with `<mark>` (new — amber 35% fill, `rgb(210 153 34 / 35%)`, matching the design source's literal value; this is a decorative highlight overlay, not a new semantic colour token, so it does not add to the declared colour scale).
- `"N of M"` renders inside the filter row (visible next to the input) while a query is active; empty otherwise.
- **Esc**: clears the query, closes the filter row, returns focus to the tree's current roving-tabindex row (**changed** from v1.6, which refocused the filter input).
- **Enter**: opens (activates) the first visible match.
- **↓**: moves focus from the filter input into the tree (first visible row), without closing the filter.
- Empty state (no matches): replaces the tree body with `No changed files match "{query}".` (curly quotes, literal from the design source) — this is the one change-this-phase makes to the existing "No matching files" empty state; no separate "Clear the filter" button/body copy (the filter row's own Clear-filter button already does this, so the duplicate control from v1.6 is removed, consistent with the "no duplicate controls" lesson from `20-UI-REVIEW.md`).
- Filter text is session-only (component-local `query` ref) — **not** persisted to `loopnote.workbench.v1`.

## List Mode (TREE-04)

List⇄tree toggle button in the view-header (the **only** control for this state — single source of truth, per the Phase 20 duplicate-control lesson). One icon button whose icon + accessible name reflect the mode you'd switch **to**:

| Current mode | Icon shown | Accessible name |
|---|---|---|
| `tree` | `list` | `"View as list"` |
| `list` | `tree` | `"View as tree"` |

- **Tree mode** (default): `role="tree"` container, `role="treeitem"` rows, folders + files, exactly as today restyled per `## Row Anatomy` above.
- **List mode**: `role="listbox"` container, `role="option"` rows (not `treeitem` — no `aria-level`/`aria-expanded`, folders don't exist in this view), flat, one row per file, name first then dimmed directory (`PathText.vue`'s existing `path-text__filename`/`path-text__directory` split, unchanged component, `basename` prop simply turned off) — same right-side content (comment badge, markers, counts, status letter) as tree rows.
- Order: every filter-surviving file in **the same order the tree would show them** (CONTEXT requirement, so ⌥↑/⌥↓ file navigation is identical in both modes) — i.e. depth-first, directory-alphabetical-then-file-alphabetical, **independent of any folder's expanded/collapsed state** (folders don't exist in this view, so a collapsed folder in tree mode must not hide its files here). This requires the model to expose a filter-aware, expansion-independent flat file-row list (see `## Component & Model Changes`).
- Keyboard: ↑/↓/Home/End/Enter/Space work identically to tree mode; ←/→ are no-ops (no folders to fold).
- Persisted as `treeViewMode` (`'tree' | 'list'`, default `'tree'`) in `loopnote.workbench.v1`.

## Footer Totals (TREE-06)

New row beneath the tree/list body, `border-top: 1px solid var(--border-default)`, `--text-muted`, `--font-size-metadata` (12px, existing). **Not** a live region (no `aria-live` — this is a static summary, re-read on its own if an AT user navigates to it).

- Default: `"{N} {file|files} · +{A} −{D}"` (e.g. `"9 files · +64 −17"`; singular `"1 file"` when N=1). Totals sum every changed file's `additions`/`deletions` (null treated as 0 for the sum, matching existing aggregate convention).
- While filtering: `"{N} of {M} files"` (no +/− totals — the match count already lives in the filter row; the footer's job while filtering is just the count, per CONTEXT).

## Focus, Roles & Landmarks

- **View header** (`<nav aria-label="Changed files">`, was `aria-label="Files"`): the `<h2 id="changed-files-heading">` heading is **removed**. The design source's HTML structure renders the header label as a plain, non-interactive, uppercase `<span>Changed files</span>` (VS Code's own Explorer side bar does the same — a section label, not a document heading). The nav landmark alone carries the accessible name; nothing in Phase 20's `## Focus Order & Skip Links` depended on the `h2`'s id (the "Skip files" skip link already focuses the tree's roving-tabindex row, not the heading), so removing it has no other ripple.
- **Tree root**: `role="tree"` (tree mode) / `role="listbox"` (list mode), `aria-label="Changed files"` (was `"Files"`). Rows: `role="treeitem"` (tree mode, unchanged `aria-level`/`aria-expanded`/`aria-selected`/`tabindex` pattern) / `role="option"` (list mode, `aria-selected`/`tabindex` only).
- **Accessible-name composition** for a row follows the DOM order in `## Row Anatomy` exactly (file-type mark is `aria-hidden`, contributes nothing): `{name/path, incl. renamed/copied "from…to…" label}` → `{comment badge label}?` → `{marker labels}*` → `{line-counts label}` → `{status label}`. Example (modified, text-readable, no comment/refresh/standalone): `"tracked.txt, Text, 2 additions, 1 deletion, modified"`.
- **View-options menu**: `role="menu"`, items `role="menuitemradio"` (line-counts group, `role="group"`) / `role="menuitemcheckbox"` (comment badges), per `## View Options Menu`.
- **Filter toolbar**: `role="toolbar" aria-label="Changed files actions"` wraps the four view-header icon buttons (filter / list⇄tree / collapse-all / view-options), matching the design source's HTML structure block. View-header actions are **always visible** (not hover-opacity-gated) per the design source's explicit note ("stay visible in winning sketch").

## Persistence

Same versioned `localStorage` key, `loopnote.workbench.v1` (`src/web/model/panel-state.ts`), extended:

```json
{
  "sidebarWidth": 264,
  "sidebarVisible": true,
  "panelHeight": 240,
  "treeViewMode": "tree",
  "treeLineCounts": "hover",
  "treeCommentBadges": true
}
```

- `treeViewMode`: `'tree' | 'list'`, default `'tree'`. Any other value → default.
- `treeLineCounts`: `'always' | 'hover' | 'never'`, default `'hover'`. Any other value → default.
- `treeCommentBadges`: boolean, default `true`. Non-boolean → default.
- Same discipline as the existing `sidebarWidth`/`sidebarVisible`/`panelHeight` fields: `JSON.parse` failure, wrong shape, or an invalid enum/type value for any one field is replaced with that field's default (the other fields are unaffected), and the key is overwritten with the corrected value on next persist (debounced on change) — never left corrupt.
- Filter query text is **not** persisted (session-only, component-local state).
